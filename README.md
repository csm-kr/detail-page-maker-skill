# Detail Page Maker Skill

공급처 URL 하나에서 제품 SSOT, 시장 조사, 상업 기획, 이미지, GIF, 편집 가능한
Studio v1, `output/detail-page.html`, 쿠팡 Wing CDN 출력을 만드는 단일 Codex
스킬이다. 실행에 필요한 연관 스킬 16개는 이 스킬 폴더 안에 잠금된 상태로
포함된다.

## 한 줄 설치

macOS, Ubuntu, Windows에서 대상 프로젝트 폴더를 연 뒤 같은 명령을 실행한다.
GitHub 저장소에서 `detail-page-maker-skill` 하나만 프로젝트 로컬로 받는다.
현재 비공개 저장소에 처음 연결하는 컴퓨터는 접근 권한이 있는 계정으로 아래
인증을 한 번 마친다.

```sh
gh auth login
gh auth setup-git
```

Windows는 설치 명령 전에 두 가지를 먼저 처리한다. 둘 다 설치가 조용히 깨지는
원인이라 나중에 알아내기 어렵다.

첫째, Git 장경로를 켠다. Windows 레지스트리의 `LongPathsEnabled`가 1이어도 Git은
자체 설정을 따로 보기 때문에 이 명령을 실행하지 않으면 켜지지 않는다. 꺼진
상태에서는 파일 생성이 `Filename too long`으로 실패하는데, 전체가 중단되지 않고
일부 파일만 빠진 채 끝나므로 나중에 실행 단계에서야 문제가 드러난다.

```sh
git config --global core.longpaths true
```

둘째, 프로젝트 폴더 경로를 짧게 둔다. 스킬 파일 경로는 프로젝트 폴더 뒤로 최대
151자가 더 붙는다(`.claude/skills/detail-page-maker-skill/` 또는
`.agents/skills/detail-page-maker-skill/` 38자 + 내부 최장 111자). Windows 기본
경로 한계가 260자라서 프로젝트 폴더 경로가 108자를 넘으면 장경로를 켜도 안전하지
않다. OneDrive 동기화 폴더처럼 경로가 긴 위치는 피한다.

```sh
npx skills add https://github.com/csm-kr/detail-page-maker-skill --skill detail-page-maker-skill --agent codex --yes --copy
```

  **1. 한 화면에는 하나의 핵심 메시지만 전달한다**

  각 섹션은 1초 안에 다음 중 하나를 명확하게 보여줘야 한다.

  - 어떤 불편을 해결하는가
  - 제품의 가장 중요한 장점은 무엇인가
  - 실제로 어떻게 작동하거나 사용하는가
  - 사용하면 어떤 결과를 얻는가

  제목은 짧고 결과 중심으로 작성하고, 보조   . 문구를 읽는 순간 이미지가 그 주장을 직접 증명해야 한다.

  **2. 경쟁 페이지에서는 문구가 아니라 판매 논리를 참고한다**

  경쟁사의 카피와 이미지를 그대로 복제하지 말고 다음을 분석한다.

  - 어떤 고객 문제로 시작하는가
  - 어떤 장점을 가장 먼저 보여주는가
  - 장점을 어떤 순서로 설명하는가
  - 이미지와 영상으로 어떻게 증명하는가
  - 사용법, 옵션, 제품정보를 언제 제시하는가
  - 마지막에 어떤 메시지로 구매를 유도하는가

  동일 상품은 확인된 소구점과 전개 순서를 적 , 이미지·카피·그래픽은 새롭게 제작한다.유사 상품은 경쟁사의 주장을 그대로 사용하지 말고 실제 제품 근거를 별도로 확인한다.

  **3. 한글 문장은 의미 단위로 청킹한다**

  AI가 생성한 문장을 그대로 넣지 말고, 읽는 의미에 맞게 줄바꿈을 다시 설계해야 한다.

  오래 사용해도

  부담은 가볍게

  다음과 같은 줄바꿈은 금지한다.

  간편한 설

  치 방법

  - 조사와 명사를 분리하지 않는다.
  - 숫자와 단위를 분리하지 않는다.
  - 제목은 보통 2~3줄 이내로 제한한다.
  - 핵심 단어를 마지막 줄에 배치한다.
  - 브라우저 자동 줄바꿈에만 의존하지 않는다.

  **4. 중앙 정렬과 시각적 밀도를 실제 화면에서 검수한다**

  제목, 제품, 원형 배지, 아이콘, 단계 안내는 같은 중심축을 사용한다. flex나 grid를 이용해 정렬하고 임의의 margin
  값에 의존하지 않는다.

  CSS상 중앙이어도 글자의 자폭과 line-height 수 있으므로, 최종 렌더링 화면에서 광학중심까지 확인해야 한다.

  빈 공간을 무조건 없애는 것이 아니라 의미 없는 공간을 없앤다. 각 화면은 제품, 사용 장면, 핵심 문구, 기능 확대
  또는 비교 이미지 중 하나가 충분히 크게 보

  **5. 이미지는 결과를, GIF는 변화를 보여준

  정지 이미지는 제품의 형태, 완성된 결과, 소용한다. GIF는 접기, 설치, 세척, 부착, 작동, 변화처럼 움직임이 있어야 이해되는 기능에만 사용한다.

  기능별로 모션 문법을 다르게 설계한다.

  | **기능** | **적합한 모션** |
  | --- | --- |
  | 사용 전후 | 슬라이더, 와이프, 좌우 비교 |
  | 설치·조립 | 단계별 손동작 |
  | 방수 | 물방울 낙하와 흘러내림 |
  | 탄성·복원 | 누르기, 변형, 복귀 |
  | 수납력 | 제품이 채워지거나 정리되는 과정 |
  | 제품 디테일 | 매크로 이동과 원형 콜아웃
  | 규격 | 가로·세로 측정선 순차 표시 |
  | 수량·구성 | 제품 누적과 숫자 카운트 |
  | 사용 장소 | 서로 다른 공간으로 장면 전환 |

  연속된 GIF는 카메라, 핵심 변화, 전환 방식, 강조 그래픽 중 최소 두 가지가 달라야 한다. 모든 GIF에
  확대·흔들기·스캔 효과를 반복하지 않는다.

  **6. GIF는 첫 프레임과 루프까지 검수한다**

  첫 프레임만 표시되더라도 제품, 핵심 메시지 다. 애니메이션은 메시지를 새로 만드는 것이 아니라 첫 프레임의 메시지를 강화해야 한다.

  루프에서는 다음을 확인한다.

  - 첫 장면이 검거나 비어 있지 않은가
  - 마지막에서 처음으로 자연스럽게 연결되는
  - 속도, 방향, 밝기가 루프 경계에서 튀지 않는가
  - 제품 위치와 크기가 갑자기 변하지 않는가
  - 제품 형태, 색상, 부품이 중간에 바뀌지 않는가
  - 숫자와 단계가 정확한 최종 값까지 도달하

  복잡한 다중 장면과 정확한 타이밍이 필요하 저 완성한 뒤 GIF나 WebP 파생본을 제작한다.

  **7. 생성 이미지에서는 제품 정체성을 고정

  이미지 생성 전에 제품의 불변 조건을 정한다

  - 실루엣과 비율
  - 실제 색상과 재질
  - 버튼, 구멍, 손잡이, 로고 위치
  - 구성품과 결합 방식
  - 실제로 존재하지 않는 부품 생성 금지

  모든 장면에서 동일한 기준 제품 이미지를 참 소와 보조 효과는 변경할 수 있지만 제품자체가 다른 상품처럼 변해서는 안 된다.

  AI 생성 이미지에는 가급적 한글을 넣지 않는다. 제품과 배경은 이미지로 만들고, 한글 카피와 숫자·단위는 HTML이나
  검증된 영상 폰트로 처리한다.

  **8. 썸네일은 각각 독립적인 광고로 만든다*

  같은 제품 사진에 문구 색상만 바꾼 썸네일을다 하나의 소구점을 맡긴다.

  - 대표 장점
  - 사용 결과
  - 주요 기능
  - 간편한 사용법
  - 수량·구성 또는 규격

## Studio 실행

Node.js 22.15.0 이상이 필요하다. 설치된 프로젝트의 루트에서 기존 상세페이지
프로젝트를 지정하면 Studio가 기본 브라우저로 열린다.

```sh
node .agents/skills/detail-page-maker-skill/scripts/detail-page.mjs start \
  --project ".workspace/projects/<프로젝트 폴더>"
```

기본 주소는 `http://127.0.0.1:8896/studio.html`이다. 브라우저 자동 실행을
끄려면 `--no-open`, 포트를 바꾸려면 `--port 8897`을 추가한다.

```sh
node .agents/skills/detail-page-maker-skill/scripts/detail-page.mjs start \
  --project ".workspace/projects/<프로젝트 폴더>" \
  --port 8897 \
  --no-open
```

Studio의 `저장`은 선택한 프로젝트의 `output/detail-page.html`을 갱신하고
직전 파일을 `.detail-page/backups/`에 보관한다.

## 실행 검사

Node.js 22.15.0 이상과 GitHub CLI가 필요하다. GIF 제작에는 `ffmpeg`가 필요하고, motion 작업 시
내장 HyperFrames 절차가 `npx hyperframes`로 프로젝트 로컬 런타임을 준비한다.
실제 브라우저 수집·검수에는 `browser-harness` 실행 파일이 필요하다. 이들은
별도 스킬이 아니라 세 운영체제에서 사용하는 실행 프로그램이다.

`doctor`는 진단 전용이라 런타임을 대신 내려받지 않는다. HyperFrames 검사에
`npx --no-install`을 쓰므로 새 컴퓨터에서 처음 실행하면 npx 캐시가 비어 있어
`hyperframes`만 실패로 보고된다. 설치가 잘못된 것이 아니라 런타임이 아직 준비되지
않은 상태다. 아래를 한 번 실행해 캐시를 채운 뒤 다시 검사한다.

```sh
npx --yes hyperframes --version
```

```sh
node .agents/skills/detail-page-maker-skill/scripts/detail-page.mjs doctor
node .agents/skills/detail-page-maker-skill/scripts/e2e.mjs
```

설치된 폴더 하나를 다른 프로젝트에 수동 복사하는 방식은 지원하지 않는다.
프로젝트마다 위 Git 설치 명령을 실행해 출처와 업데이트 경로를 유지한다.

## Windows 수동 검증

GitHub Actions는 사용하지 않는다. Windows 환경 담당자가 필요할 때 저장소
루트에서 아래 검증을 직접 실행한다.

이 검증은 설치본이 아니라 저장소 자체를 받아야 하므로 `git clone`이 필요하다.
장경로가 꺼져 있으면 745개 파일 중 일부만 체크아웃된 채로 clone이 끝나고 테스트가
엉뚱하게 실패하므로, 위 설치 절의 `core.longpaths` 설정을 먼저 확인한다. 저장소는
현재 트리가 40MB인데 히스토리까지 받으면 1.4GB이므로 검증 목적이면 `--depth 1`로
받는다.

```powershell
git config --global core.longpaths true
git clone --depth 1 https://github.com/csm-kr/detail-page-maker-skill
```

```powershell
node tests/run-suite.mjs portable-skill
node tests/run-suite.mjs orchestration

node tests/remote-git-install.mjs
```
