# 살랑 루즈핏 쿨토시 — Commercial Creative Memory

상태: `REV-021 ACTIVE`

이 문서는 이번 상품을 만들며 확인한 제품 고유 규칙과 다른 상세페이지에도 검증해
볼 수 있는 제작 원칙을 한곳에 보존한다. 고객용 HTML에는 노출하지 않는다.

## 1. 고객이 보는 면이 먼저다

- 구매자는 어떤 도구로 이미지를 만들었는지, 누가 검수했는지보다 자신의 불편과
  제품이 주는 변화를 본다.
- `제조사 확인`, `실물 구조 기준`, `상용 촬영 톤으로 재구성`, `God Tibo`,
  `HyperFrames`, `승인본`은 내부 기록에만 둔다.
- 제조사 제공 쿨 소재 사실은 공개 가능하지만 고객 화면에서는
  `뜨거운 하루 위, 한 겹 더 시원한 선택`처럼 고객의 상황과 방향으로 번역한다.
- 수치가 없으면 숫자·°C·퍼센트·시험기관을 만들지 않는다.

## 2. 문제는 정확히 세 갈래로 나눈다

1. 조이는 스포츠 핏의 답답한 인상
2. 손목에서 멈춰 손등이 남는 짧은 덮임
3. 등산 장비처럼 보여 오늘의 옷차림과 겉도는 스타일

세 문장은 같은 문제의 재진술이 아니다. 문자와 말풍선은 고객의 구매 전 망설임을
보여 주는 장치이며 실제 후기·별점·구매 인증처럼 꾸미지 않는다.

## 3. 카피의 기억점

- 현행 핵심 문장: `그늘은 길게, 실루엣은 가볍게.`
- 루즈핏: `바람이 머무는 듯, 주름 사이에 남겨둔 여유.`
- 손등 커버: `손끝의 움직임은 자유롭게, 그늘은 손등까지.`
- 쿨 소재: `뜨거운 하루 위, 한 겹 더 시원한 선택.`
- 스타일: `기능은 가볍게, 오늘의 룩은 그대로.`

직설적인 부품 설명은 보조 문장과 상세 스펙으로 내린다. 비유는 실제 구조와 제조사
주장 범위를 넘지 않는다.

## 4. SSOT와 공개 이미지

- 실제 사용자 원본과 공급처 crop은 제품 동일성의 SSOT다.
- 원본 픽셀을 고객 페이지에 바로 쓰지 않는다.
- 공개 이미지는 SSOT를 참조한 God Tibo 상용 파생 컷이어야 하며 제품 동일성 QA를
  통과해야 한다.
- 화이트 한 쌍, 47×14cm의 긴 비율, 엄지홀, 손등 라벨과 평평한 상단 밴드를
  첫·중간·마지막에서 유지한다.

## 5. 이번 상품의 이미지 하드 실패

- 위쪽 밴드가 두 줄로 교차해 로프·꽈배기처럼 보임
- 한 쌍이 X자로 겹치거나 한쪽이 다른 크기로 보임
- 제품이 짧아져 47cm 길이 인상이 사라짐
- 라벨이 손바닥·팔 안쪽·손목 위로 이동함
- 엄지홀이 과장돼 제품의 주인공처럼 보임
- 원본을 단순 크롭·누끼·배경 교체만 해 공개 자산으로 사용함

## 6. GIF는 장점 바로 다음에 둔다

- 루즈핏: 같은 팔 좌표의 비교 와이프
- 손등 커버: 엄지홀과 손등 길이 방향 전환
- 쿨 소재: 그래프 없이 열감 오버레이가 걷히는 쿨 스윕·공기 흐름
- 스타일: 동일 모델·제품의 3룩 매치컷
- 사용법: 팔 넣기 → 엄지홀 → 손등 정돈
- 구성: 가장 좋은 화이트 한 쌍을 링·빛·짧은 리빌로 공개

페이지 뒤쪽에 `detail proof`를 다시 모으지 않는다. 한 GIF는 한 주장만 증명하고,
첫 프레임부터 제품과 변화가 읽혀야 한다.

## 7. 배경 이미지와 효과

- 주요 장면은 이미지가 배경이 되어 상황을 먼저 전달하게 한다.
- 텍스트는 제품과 얼굴을 피한 여백에 두고 대비가 필요할 때 제한된 스크림만 쓴다.
- 비교선, 막대, 라벨, 글로우는 제품보다 먼저 보이거나 제품을 가리면 안 된다.
- 스타일 전환은 제품 아이덴티티가 아니라 옷과 배경만 바뀌어야 한다.

## 8. 페이지 순서

```text
히어로
→ 서로 다른 불편 3개
→ 제품의 답
→ 장점 1 + 즉시 GIF
→ 장점 2 + 즉시 GIF
→ 장점 3 + 즉시 GIF
→ 장점 4 + 즉시 GIF
→ 사용법
→ 고객 질문/문제 해결 요약
→ 상품 구성
→ 사이즈·상세 스펙
→ 실제 길이가 보이는 마지막 리마인드
```

같은 SKU의 검증된 후기 문장이 없으므로 후기 섹션은 만들지 않는다.

## 9. 출력 위치

작업 파일은 `asset/`, HyperFrames 원본은 `hyperframes/`, 기획은 `planning/`,
검수 기록은 `qa/`에 둔다. 사용자가 실제로 여는 결과는 아래 하나다.

```text
projects/살랑-루즈핏-쿨토시-55873582/
└── deliverables/
    └── rev021-commercial/
        ├── index.html
        ├── media/
        ├── manifest.json
        └── qa/final-report.md
```

완료 안내에는 `deliverables/rev021-commercial/index.html`만 최종 진입점으로
제시한다.

## 10. 현재 GIF 규칙

- 모든 GIF는 해당 소구를 증명하는 주 FX를 최소 1개 가진다.
- 외부 HTML 카피는 고객의 상황·편익, GIF 내부는 상태·단계·수량만 말한다.
- 착용법은 내부 `3 STEP`, 구성은 내부 `1 SET / 2 PCS`만 남겨 외부 문구와
  중복하지 않는다.
- 쿨 소재는 그래프·막대·꺾은선이 아니라 승인 실착 위 열감 오버레이 제거,
  푸른 쿨 스윕, 공기 흐름, 제한된 서리 입자로 보여 준다.
- `약 47cm`는 규격표 바로 위에서 위쪽 밴드부터 손등 커프 끝까지 측정하는
  전용 GIF로 고정한다.

## 11. Studio 편집 계약

텍스트·이미지·GIF·의미 있는 시각 요소를 모두 선택할 수 있게 한다. 선택 요소의
X/Y 위치, 1px·10px 이동, 드래그, 이미지 크기, 텍스트 비우기, 글자색과
`Noto Sans KR`, `Gmarket Sans`, `S-Core Dream`, `Wanted Sans`,
`Black Han Sans`, `Jalnan` 글꼴을 바꿀 수 있어야 한다. 실행 취소 버튼과
`Ctrl/Cmd+Z`를 함께 제공한다.

## 12. 보존과 출력

- 활성 프로젝트 자산 루트는 `asset/` 하나다.
- 이전 `assets/`의 비활성 원본·중복·교체 GIF는 삭제하지 않고
  `archive/legacy-assets/2026-07-28/`에 체크섬과 함께 보존한다.
- HyperFrames 원본과 prototype은 정리 대상으로 보지 않는다.
- 사용자가 여는 최종 진입점은
  `deliverables/rev021-commercial/index.html` 하나다.
