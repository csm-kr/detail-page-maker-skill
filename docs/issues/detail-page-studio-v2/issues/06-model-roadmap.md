## Question

사용자가 원본에서 무엇을 만들고, 어떤 자산이 모델 승인에 의존하며, 그 결과가
상세페이지 14장 어디에 쓰이는지 Studio 한 화면에서 이해하고 통제할 수 있는가?

## Acceptance criteria

- 쿨토시 프로젝트에 최소 24개, 기본 28개 선행 에셋이 용도별로 보인다.
- 제품 원형·모델 후보·배경·착용 예시·구조 증거·GIF 입력 자산이 구분된다.
- 모델 후보는 버전을 비교한 뒤 한 버전만 모델 SSOT로 승인·잠글 수 있다.
- 모델 승인 전에는 모델 의존 에셋 생성이 API와 UI 모두에서 차단된다.
- 각 선행 에셋은 사용될 상세페이지 번호를 표시한다.
- commercial-max 14장과 HyperFrames GIF 2개 로드맵은 목적, 필요한 에셋, 현재 준비 상태를 표시한다.
- 선행 에셋 승인 게이트 전에는 최종 이미지와 GIF 제작이 잠긴다.
- 이미 생성된 역할은 로드맵에서 완료·검수·승인 상태로 반영된다.
- 배치 기본 동시 실행 수는 4개다.

## Answer

Studio 첫 화면에 `원본 → 선행 에셋 28개 → 사용자 승인 게이트 → 최종
상세페이지 14장 + HyperFrames GIF 2개` 지도를 추가했다. 28개는 제품 원형,
모델 후보, 배경, 착용·사용 예시, 구조 증거로 나뉘며 각 카드에 목적, 상세페이지
사용 위치, 모델 의존성, 버전·QA·승인 상태를 표시한다.

모델 후보 A~D는 모두 생성해 비교할 수 있고, 사용자가 고른 QA 통과 버전 하나만
SHA-256과 함께 모델 SSOT로 잠근다. 그전에는 인간 장면 생성 API와 UI가 모두
차단된다. 모델 잠금 뒤에는 이전 모델로 만들어진 인간 에셋을 `승인 모델로
재제작` 상태로 구분한다. 필수 에셋 24개와 선택 모델 1개, 총 25개 승인 게이트를
통과해야 최종 14장과 GIF 2개 제작 단계가 열린다. `god-tibo-imagen` 배치는
기본 4개 병렬 실행이다.
