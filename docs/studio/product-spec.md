## 1. 목적

Detail Page Studio는 공급처 URL, 제품 사실 SSOT, ImageGen 이미지와 HyperFrames 모션을 한 상세페이지로 조립하기 전에 각 완성 에셋의 제품 동일성과 디자인 일관성을 검수하고 사용자 승인을 받는 로컬 제작 도구다.

가장 중요한 목표는 멋진 초안을 빨리 만드는 것이 아니라, 승인되지 않은 제품 이미지나 GIF가 최종 HTML에 섞이지 않게 하는 것이다.

## 2. 디자인 해석

상업 상세페이지 제작자를 위한 전문 크리에이티브 툴로 읽는다. 기본 화면은 차분한 어두운 중립색, 작업 캔버스는 밝은 표면, 강조색은 한 가지로 제한한다.

- Design variance: 5
- Motion intensity: 4
- Visual density: 7

마케팅 랜딩페이지 문법을 편집기 표면에 그대로 사용하지 않는다. 상태, 선택, 비교, 잠금, 오류와 되돌리기가 장식보다 우선한다.

## 3. 사용자와 역할

### Studio

- 파일·해상도·해시·의존성·HTML 경계를 기계적으로 검사한다.
- 승인·조립·개정판 불변식을 강제한다.

### Codex

- ImageGen과 HyperFrames 작업 대기열을 처리한다.
- 제품 SSOT와 후보를 시각적으로 비교한다.
- 이미지, GIF 프레임과 HTML 렌더의 제품 동일성·디자인 일관성 보고서를 기록한다.

### 사용자

- QA 근거를 확인하고 승인·수정·재생성·보류를 결정한다.
- 제품 동일성 하드 실패를 우회할 수 없다.
- 조립과 게시를 최종 승인한다.

ImageGen은 생성만 담당하고 결과를 자가 승인하지 않는다.

## 4. 전체 유저 플로우

```text
프로젝트 생성
  ↓
공급처·제품 SSOT 잠금
  ↓
이미지 등록 또는 ImageGen 생성 요청
  ↓
에셋 자동 검사와 Codex 시각 QA
  ↓
원본·후보 비교
  ↓
사용자 개별 승인
  ↓
GIF·HyperFrames 레이어 편집과 재렌더
  ↓
GIF 프레임 QA와 사용자 승인
  ↓
필수 에셋 승인 완료
  ↓
상세페이지 조립 확정
  ↓
에셋·GIF 읽기 전용 잠금
  ↓
HTML 인터랙티브 편집
  ↓
상용 QA 97점 이상·하드 실패 0건
  ↓
사용자 최종 승인과 내보내기
```

생성과 QA는 백그라운드 작업이다. 사용자는 다른 탭으로 이동할 수 있으며 상단 작업 센터에서 `대기`, `진행`, `완료`, `실패`를 확인한다.

## 5. 작업면

### 5.1 에셋 검수

- 제품 포함 이미지·인포그래픽·GIF는 개별 승인한다.
- 제품이 없는 단순 배경·빛·입자·장식은 묶음 승인할 수 있다.
- 원본과 후보 한 개를 비교한다.
- 만족하지 않으면 후보를 하나씩 추가 생성한다.
- 이전 후보를 지우지 않고 버전 이력으로 보존한다.
- 나란히 비교, 투명도 겹치기, 차이 강조를 제공한다.
- 양쪽 확대·이동·프레임 위치를 동기화한다.

### 5.2 GIF·HyperFrames 편집

완성 GIF 픽셀을 직접 편집하지 않는다. HyperFrames 원본을 다음 레이어로 보존한다.

- 제품
- 배경
- 텍스트
- 말풍선·선·화살표·도형
- 빛·입자·기능 효과
- 키프레임·타이밍·이징

프롬프트 범위는 `레이어`, `그룹`, `장면 전체`를 제공한다. 기본값은 선택한 레이어다. 선택 범위가 커질수록 영향 예상 영역과 추가 확인을 강화한다.

선택 레이어의 텍스트, x/y, 크기, 투명도, 글자 크기와 색을 속성 패널에서 조정할 수 있다. 적용은 완성 GIF를 직접 바꾸지 않고 해당 레이어만 변경한 `hyperframes.edit` 후보 렌더 작업을 만든다.

### 5.3 상세페이지 조립

- 필수 승인 상태와 미처리 작업을 요약한다.
- 조립 직전 실제 사용 버전과 해시를 보여준다.
- 필수 승인이 빠졌거나 하드 실패가 있으면 조립 버튼을 잠근다.
- 사용자가 확인하면 조립 manifest를 생성하고 에셋 단계를 잠근다.

### 5.4 HTML 인터랙티브 편집

허용:

- 카피·줄바꿈·대체 텍스트
- 폰트·크기·굵기·행간·자간·색
- 섹션 순서·간격·높이
- 이미지와 GIF 박스의 위치·크기·크롭·포스터·재생
- 말풍선 본체·꼬리·선·강조 박스
- 정렬·8px 그리드·안전영역
- FAQ·탭·버튼과 스크롤 인터랙션
- 320·390·800px별 명시적 오버라이드
- 자동 저장, undo/redo, 이름 있는 체크포인트

금지:

- 새 제품 이미지 등록
- ImageGen 재생성
- 이미지 파일 교체
- GIF 내부 레이어·타임라인 변경
- 제품 SSOT 변경

에셋 교체 요청은 `새 개정판 만들기`로 연결한다.

### 5.5 최종 QA

- 320·360·390·768·800px
- 제품 동일성
- 깨진 에셋·GIF 재생
- 글자 잘림·경계 밖 요소·안전영역
- 카피·주장 근거
- HTML 인터랙션
- 편집 상태 재현
- 상용 점수

## 6. 프롬프트 수정

모든 생성 가능 요소는 프롬프트 수정 요청을 만들 수 있다.

1. 현재 선택 범위를 고정한다.
2. 수정 이유와 원하는 변화를 입력한다.
3. 변경 금지 대상과 SSOT 참조를 자동으로 붙인다.
4. 사용자가 요청 내용을 확인한다.
5. Codex 작업 대기열에 등록한다.
6. 후보 한 개를 새 버전으로 만든다.
7. 원본과 후보를 비교한다.
8. QA 뒤 사용자가 승인하거나 다시 생성한다.

제품 레이어는 형태·비율·재질·로고·문자·부품 위치를 잠근다. 조명·카메라·크롭·배경·그림자·연출 효과만 수정할 수 있다. 구조 변경은 SSOT 갱신과 새 개정판이 필요하다.

## 7. 승인과 조립 잠금

에셋 상태:

```text
draft
  → qa_pending
  → review_ready
  → approved

review_ready
  → regeneration_requested
  → generating
  → qa_pending
```

제품 동일성 하드 실패:

- 실루엣·비율 불일치
- 로고·인쇄 문자 오류
- 부품 위치·수량·결합 구조 오류
- 치수·재질 사실 오류
- GIF 중간 프레임에서 제품 정체성 붕괴

디자인 경고:

- 조명·배경 분위기 편차
- 타이포·줄바꿈·색감 차이
- 페이지 리듬과 거리감 편차

하드 실패는 승인 차단이다. 디자인 경고는 근거를 보여준 뒤 사용자가 승인할 수 있다.

## 8. 개정판

조립된 현재 버전은 파괴적으로 잠금 해제하지 않는다.

```text
V1 승인·조립·잠금
  ↓ 새 개정판
V2 변경 에셋만 열기
  ↓ 의존성 계산
관련 GIF·HTML 섹션만 재승인
  ↓ 재조립
V2 승인·잠금
```

영향받지 않은 에셋은 이전 승인을 승계한다. 에셋 의존성 그래프가 이미지 → HyperFrames 장면 → GIF → HTML 섹션 연결을 계산하고 사용자는 범위를 확인한다.

## 9. 내보내기

### 검토용 초안

- QA 전에도 생성할 수 있다.
- 검토용 상태를 명확히 표시한다.
- 판매 채널 게시용으로 오해되지 않게 한다.

### 게시용 단일 HTML

- 승인된 이미지·GIF를 내장한다.
- 서버 없이 열린다.
- 상용 QA 97점 이상, 하드 실패 0건, 사용자 최종 승인이 필요하다.

### Studio 프로젝트 묶음

- 제품 사실 SSOT
- 에셋 원본과 모든 후보 버전
- 프롬프트와 참조 이미지
- HyperFrames 원본과 렌더
- 승인·QA·개정판 기록
- HTML 레이어 데이터와 체크포인트

## 10. UI 참고 원칙

### 채택

- [제디터 AI 상품상세](https://manual-geditor.gabia.com/ai/pdp3): 백그라운드 생성 상태와 이력
- [제디터 AI 이미지](https://manual-geditor.gabia.com/ai/image_gen): 참조 이미지, 프롬프트 재삽입, 생성 이력
- [제디터 요소 레이어](https://manual-geditor.gabia.com/element/layer): 그룹·순서·숨김·잠금·이름 변경
- [Framer Agents](https://www.framer.com/help/articles/how-to-use-agents/): 선택 컨텍스트에 한정한 프롬프트 수정
- [Webflow AI Assistant](https://help.webflow.com/hc/en-us/articles/34205154436243-Modify-page-designs-with-the-Webflow-AI-Assistant): 디자인 시스템 재사용, 생성안 검토와 되돌리기
- [Canva Magic Layers](https://www.canva.com/help/editable-magic-layers/): 평면 결과를 선택 가능한 요소로 다루는 직접 조작
- [HyperFrames](https://github.com/heygen-com/hyperframes): seek 가능한 타임라인과 결정적 렌더

### 채택하지 않음

- 제디터의 완성 GIF 파일 교체만으로 끝나는 방식
- 평면 실사 이미지를 AI가 완벽하게 레이어 분해할 것이라는 가정
- 선택 범위 밖 전체 페이지를 프롬프트가 암묵적으로 바꾸는 방식
- 자동 QA 점수만으로 사용자 승인을 생략하는 방식

## 11. 수락 기준

- 필수 에셋이 미승인이면 조립할 수 없다.
- 하드 실패가 있으면 승인할 수 없다.
- 재생성이 기존 버전을 덮어쓰지 않는다.
- 조립 뒤 에셋·GIF가 읽기 전용이다.
- 새 개정판이 영향 항목만 다시 연다.
- 원본·후보와 GIF 동일 시점 비교가 가능하다.
- HTML 변경이 안정된 layer ID와 viewport override로 저장된다.
- 자동 저장·undo/redo·체크포인트가 동작한다.
- 검토용과 게시용 내보내기 권한이 분리된다.
- 게시용은 97점 이상·하드 실패 0건·사용자 최종 승인을 요구한다.
