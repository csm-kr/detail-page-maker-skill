## 1. 목적

Detail Page Studio는 공급처 URL, 제품 사실 SSOT, ImageGen 이미지와 HyperFrames 모션을 한 상세페이지로 조립하기 전에 각 완성 에셋의 제품 동일성과 디자인 일관성을 검수하고 사용자 승인을 받는 로컬 제작 도구다.

가장 중요한 목표는 멋진 초안을 빨리 만드는 것이 아니라, 승인되지 않은 제품 이미지나 GIF가 최종 HTML에 섞이지 않게 하는 것이다.

## 2. 디자인 해석

상업 상세페이지 제작자를 위한 전문 크리에이티브 툴로 읽는다. 기본 화면은 차분한 어두운 중립색, 작업 캔버스는 밝은 표면, 강조색은 한 가지로 제한한다.

- Design variance: 5
- Motion intensity: 4
- Visual density: 7

마케팅 랜딩페이지 문법을 편집기 표면에 그대로 사용하지 않는다. 상태, 선택, 비교, 잠금, 오류와 되돌리기가 장식보다 우선한다.

## 3. 사용자와 역할

### Studio

- 파일·해상도·해시·의존성·HTML 경계를 기계적으로 검사한다.
- 승인·조립·개정판 불변식을 강제한다.

### Codex

- ImageGen과 HyperFrames 작업 대기열을 처리한다.
- 제품 SSOT와 후보를 시각적으로 비교한다.
- 이미지, GIF 프레임과 HTML 렌더의 제품 동일성·디자인 일관성 보고서를 기록한다.

### 사용자

- QA 근거를 확인하고 승인·수정·재생성·보류를 결정한다.
- 제품 동일성 하드 실패를 우회할 수 없다.
- 조립과 게시를 최종 승인한다.

ImageGen은 생성만 담당하고 결과를 자가 승인하지 않는다.

```text

  ↓
용도별 선행 에셋 28개 로드맵 확인
  ↓
모델 후보 4명 생성·비교
  ↓

  ↓
원본·후보 비교
  ↓
사용자 개별 승인
  ↓
선행 에셋 승인 게이트 25/25
  ↓
commercial-max 최종 이미지 14장 제작
  ↓

  ↓

  ↓
```

## 5. 작업면

### 5.1 에셋 검수

- 사용자가 직접 촬영한 동일 SKU 원본은 여러 장을 한 번에 `제품 사실 SSOT`로 등록한다.
- 사용자 촬영 원본은 `product/ssot/`에 보존하며 일반 광고 에셋과 구분한다.
- 등록 사진마다 원본 파일명, SHA-256, 색상 변형, provenance와 동일성 검수 상태를 기록한다.
- 등록 원본의 라벨 문구와 색상을 현재 개정판에 잠그고, 원본 해시와 검수 보고서를 함께 보존한다.
- 잠긴 SSOT 전체를 참조하는 광고 에셋 제작 요청을 Studio에서 작업 센터에 등록할 수 있다.
- 첫 화면에 실제품 원장, 제품 뷰, 모델 후보, 배경, 착용 예시, 구조 증거로 나눈 선행 에셋 28개와 상세페이지 14장·GIF 2개의 연결 지도를 표시한다.
- 각 선행 에셋은 제작 목적, 모델 필요 여부, 사용될 상세페이지 번호와 현재 상태를 표시한다.
- 모델 후보 4명 중 사용자가 선택한 한 버전의 얼굴·체형·헤어·피부톤·의상과 SHA-256을 모델 SSOT로 잠근다.
- 모델 SSOT 승인 전에는 모델이 등장하는 착용·사용 예시와 손·팔 동작 제작을 서버와 UI에서 차단한다.
- 모델 승인 전에도 제품 뷰·배경·비인간 구조 증거를 먼저 제작할 수 있다.
- 권장 제품 에셋 묶음을 한 번에 선택해 등록하고 로컬
  `god-tibo-gpt-image2-skill` 실행기로 기본 8장씩 병렬 생성할 수 있다.
- 병렬 생성 결과는 전체 에셋 보드에 카드로 펼쳐지며 각 카드에서 원본 보기, 수정 요청, 검수·비교를 바로 시작한다.
- 개별 수정은 원본을 보존한 새 버전을 만들며, 버전 칩으로 비교 대상을 바꾸고 승인한 버전을 현재 개정판에 채택한다.
- 실물을 직접 본 사용자가 Codex QA와 다르게 판단하면 `사용자 판단으로 채택`을 선택하고 사유를 남겨 해당 버전을 현재 개정판에 채택할 수 있다.
- 제품 포함 이미지·인포그래픽·GIF는 개별 승인한다.
- 제품이 없는 단순 배경·빛·입자·장식은 묶음 승인할 수 있다.
- 원본과 후보 한 개를 비교한다.
- 만족하지 않으면 후보를 하나씩 추가 생성한다.
- 이전 후보를 지우지 않고 버전 이력으로 보존한다.
- 나란히 비교, 투명도 겹치기, 차이 강조를 제공한다.
- 양쪽 확대·이동·프레임 위치를 동기화한다.

### 5.2 GIF·HyperFrames 편집

선행 에셋 25개 준비·승인과 모델 SSOT 잠금이 완료된 뒤에만 HyperFrames GIF
2개 제작을 시작한다. 선행 에셋 목록에는 GIF 키프레임을 섞지 않는다.

완성 GIF 픽셀을 직접 편집하지 않는다. HyperFrames 원본을 다음 레이어로 보존한다.

- 제품
- 배경
- 텍스트
- 말풍선·선·화살표·도형
- 빛·입자·기능 효과
- 키프레임·타이밍·이징

프롬프트 범위는 `레이어`, `그룹`, `장면 전체`를 제공한다. 기본값은 선택한 레이어다. 선택 범위가 커질수록 영향 예상 영역과 추가 확인을 강화한다.

선택 레이어의 텍스트, x/y, 크기, 투명도, 글자 크기와 색을 속성 패널에서 조정할 수 있다. 적용은 완성 GIF를 직접 바꾸지 않고 해당 레이어만 변경한 `hyperframes.edit` 후보 렌더 작업을 만든다.

### 5.3 상세페이지 조립

- 필수 승인 상태와 미처리 작업을 요약한다.
- 조립 직전 실제 사용 버전과 해시를 보여준다.
- 필수 승인이 빠졌거나 하드 실패가 있으면 조립 버튼을 잠근다.
- 사용자가 확인하면 조립 manifest를 생성하고 에셋 단계를 잠근다.

### 5.4 HTML 인터랙티브 편집

허용:

- 카피·줄바꿈·대체 텍스트
- 폰트·크기·굵기·행간·자간·색
- 섹션 순서·간격·높이
- 이미지와 GIF 박스의 위치·크기·크롭·포스터·재생
- 말풍선 본체·꼬리·선·강조 박스
- 정렬·8px 그리드·안전영역
- FAQ·탭·버튼과 스크롤 인터랙션
- 320·390·800px별 명시적 오버라이드
- 자동 저장, undo/redo, 이름 있는 체크포인트

금지:

- 새 제품 이미지 등록
- ImageGen 재생성
- 이미지 파일 교체
- GIF 내부 레이어·타임라인 변경
- 제품 SSOT 변경

에셋 교체 요청은 `새 개정판 만들기`로 연결한다.

### 5.5 최종 QA

- 카피·주장 근거
- HTML 인터랙션

## 6. 프롬프트 수정

모든 생성 가능 요소는 프롬프트 수정 요청을 만들 수 있다.

1. 현재 선택 범위를 고정한다.
2. 수정 이유와 원하는 변화를 입력한다.
3. 변경 금지 대상과 SSOT 참조를 자동으로 붙인다.
4. 사용자가 요청 내용을 확인한다.
5. Codex 작업 대기열에 등록한다.
6. 후보 한 개를 새 버전으로 만든다.
7. 원본과 후보를 비교한다.
8. QA 뒤 사용자가 승인하거나 다시 생성한다.

제품 레이어는 형태·비율·재질·로고·문자·부품 위치를 잠근다. 조명·카메라·크롭·배경·그림자·연출 효과만 수정할 수 있다. 구조 변경은 SSOT 갱신과 새 개정판이 필요하다.

## 7. 승인과 조립 잠금

에셋 상태:

```text
draft
  → qa_pending
  → review_ready
  → approved

review_ready
  → regeneration_requested
  → generating
  → qa_pending
```

제품 동일성 하드 실패:

- 실루엣·비율 불일치
- 로고·인쇄 문자 오류
- 부품 위치·수량·결합 구조 오류
- 치수·재질 사실 오류
- GIF 중간 프레임에서 제품 정체성 붕괴

디자인 경고:

- 조명·배경 분위기 편차
- 타이포·줄바꿈·색감 차이
- 페이지 리듬과 거리감 편차

하드 실패는 승인 차단이다. 디자인 경고는 근거를 보여준 뒤 사용자가 승인할 수 있다.

## 8. 개정판

조립된 현재 버전은 파괴적으로 잠금 해제하지 않는다.

```text
V1 승인·조립·잠금
  ↓ 새 개정판
V2 변경 에셋만 열기
  ↓ 의존성 계산
관련 GIF·HTML 섹션만 재승인
  ↓ 재조립
V2 승인·잠금
```

영향받지 않은 에셋은 이전 승인을 승계한다. 에셋 의존성 그래프가 이미지 → HyperFrames 장면 → GIF → HTML 섹션 연결을 계산하고 사용자는 범위를 확인한다.

## 9. 내보내기

### 검토용 초안

- QA 전에도 생성할 수 있다.
- 검토용 상태를 명확히 표시한다.
- 판매 채널 게시용으로 오해되지 않게 한다.

### 게시용 단일 HTML

- 승인된 이미지·GIF를 내장한다.
- 서버 없이 열린다.
- 상용 QA 97점 이상, 하드 실패 0건, 사용자 최종 승인이 필요하다.

### Studio 프로젝트 묶음

- 제품 사실 SSOT
- 에셋 원본과 모든 후보 버전
- 프롬프트와 참조 이미지
- HyperFrames 원본과 렌더
- 승인·QA·개정판 기록
- HTML 레이어 데이터와 체크포인트

- 선택 범위 밖 전체 페이지를 프롬프트가 암묵적으로 바꾸는 방식
- 자동 QA 점수만으로 사용자 승인을 생략하는 방식

## 11. 수락 기준

- 사용자 촬영 실제품 사진을 한 번에 여러 장 선택해 각각 독립 SSOT 항목으로 등록할 수 있다.
- 사용자 촬영 원본은 일반 광고 에셋 목록에 섞이지 않고 서버 재시작 뒤에도 유지된다.
- 사용자가 라벨 문구·색상을 확인해 SSOT를 잠그면 모든 원본 해시를 재검증하고 현재 개정판에 고정한다.
- 잠긴 SSOT를 사용한 에셋 제작 요청에는 모든 실제품 원본이 `sourceRefs`로 자동 연결된다.
- 선행 에셋 로드맵은 28개이고 최종 상세페이지 14장·HyperFrames GIF 2개와 별도로 표시된다.
- 승인 모델이 필요한 작업에는 제품 원본과 승인 모델 버전이 모두 `sourceRefs`로 연결된다.
- 제품 단독 에셋은 제품 SSOT를, 배경과 모델 후보는 빈 `sourceRefs`를 사용한다. 따라서 배경에 제품이 섞이거나 모델 후보가 제품 디자인을 학습하는 일을 막는다.
- 승인 모델이 없으면 인간 장면 배치 생성 요청은 `MODEL_SSOT_REQUIRED`로 거부된다.
- 선행 에셋 승인 게이트 전에는 최종 상세페이지 이미지와 GIF 제작이 잠긴다.
- 전체 에셋 배치는 한 요청에서 원자적으로 작업을 만들고 기본 동시성 4로 실행된다.
- 전체 에셋 보드에서 모든 결과를 함께 보고 각 에셋을 독립적으로 수정할 수 있다.
- 이전 버전을 선택해 승인하면 해당 버전이 현재 개정판의 채택 버전이 된다.
- 사용자 직접 채택은 승인자와 사유를 원장에 기록하며 자동 승인으로 대체할 수 없다.
- 필수 에셋이 미승인이면 조립할 수 없다.
- 하드 실패가 있으면 승인할 수 없다.
- 재생성이 기존 버전을 덮어쓰지 않는다.
- 조립 뒤 에셋·GIF가 읽기 전용이다.
- 새 개정판이 영향 항목만 다시 연다.
- 원본·후보와 GIF 동일 시점 비교가 가능하다.
- HTML 변경이 안정된 layer ID와 viewport override로 저장된다.
- 자동 저장·undo/redo·체크포인트가 동작한다.
- 검토용과 게시용 내보내기 권한이 분리된다.
- 게시용은 97점 이상·하드 실패 0건·사용자 최종 승인을 요구한다.
