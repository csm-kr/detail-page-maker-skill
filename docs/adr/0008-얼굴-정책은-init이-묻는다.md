# ADR-0008 — 모델 얼굴 정책에 기본값을 두지 않고 init이 묻는다

**상태** 채택 · 2026-08-05

## 맥락

사용자 의문 — "모델 얼굴이 나오면 안 되나?"

**확인 결과 스킬 규칙이 아니었다.** 스킬 문서에서 "얼굴"이 나오는 곳은 전부
`art-direction.md`의 **폰트 얼굴** 얘기다. 인물 얼굴 정책은 스킬에 **없다.** 그리고
공급처 상세페이지에는 모델 얼굴이 있다.

즉 "인물 얼굴 노출 금지"는 1회차 가이드의 한 문장을 내가 2회차 `SSOT.md`에 **규칙으로
옮겨 굳힌 것**이다. 근거 없는 제약을 사실처럼 적었고, 그 결과 히어로 플레이트에
스크림을 깔아 머리를 가린 것을 "가독성 개선"이라고 보고했다.

이것은 얼굴에 대한 실수가 아니라 **상속 편향**의 사례다 — 앞 회차의 문장을 근거 확인
없이 제약으로 승격시켰다.

## 결정

**선택 사항으로 되돌리고, 기본값을 코드에 두지 않는다.**

- `detail-page-init`의 **필수 인터뷰 질문**이다. 값은 `none` / `crop-below-chin` / `allow`.
- 대화형에서 건너뛰면 다시 묻는다. `--apply`에서 `env.answers.json`에 `model_face` 키가
  없으면 **exit 1**이다.
- `policy.model_face`가 없으면 `start`도 거부한다.
- G4가 프롬프트에 주입하고 G6이 정책 위반 컷을 **선별에서 탈락**시킨다.
- `allow`를 고르면 "동일 인물 유지"를 selection 체크리스트 항목으로 추가한다.
- 프로젝트별로 다르게 하려면 `start --model-face <값>`으로 덮어쓰고,
  그 값이 `flow-plan.output.policy.model_face`에 기록된다.
- 테스트로 고정: **코드·기본값 어디에도 `model_face` 리터럴 기본값이 없다.**

## 결과

**좋아지는 것.** 조용히 `none`으로 떨어지지 않는다. 그것이 중요한 이유는 결과물이
같아 보여도 **그것이 내 판단이었는지 사용자 뜻이었는지 구분할 수 없어지기** 때문이다.
기본값 없음이 그 구분을 강제한다.

**나빠지는 것.** init에 필수 질문이 하나 늘어 무인 실행이 한 번 막힌다. 의도한 마찰이다.

**남는 위험.** 생성 얼굴에는 실제 위험이 있고 그것은 정책과 별개다.

| 위험 | 내용 |
| --- | --- |
| 실인물 유사 | 특정 인물을 닮게 나올 수 있다 |
| 어색함 | 손·팔보다 얼굴이 훨씬 잘 무너진다 |
| 동일성 유지 | 컷마다 다른 사람이 되기 쉽다. 14장 세트에서 특히 |

`allow`를 고르면 위 셋을 selection 체크리스트로 검사한다.

## 기각한 대안

| 대안 | 기각 이유 |
| --- | --- |
| `none`을 기본값으로 | 2회차와 결과가 같아지고, 근거 없는 제약이 다시 규칙처럼 굳는다 |
| `crop-below-chin`을 추천값으로 제시 | 추천도 기본값처럼 작동한다. **내가 정하지 않는다**가 이 결정의 요지다 |
| 컷마다 에이전트가 판단 | 컷 30장에서 판단이 갈리고, 갈린 이유가 기록되지 않는다 |
| SSOT에 계속 규칙으로 둔다 | 사실이 아닌 것을 사실 문서에 두는 것이 문제의 원인이었다 |
