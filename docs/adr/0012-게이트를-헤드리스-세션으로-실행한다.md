# ADR-0012 — 게이트를 헤드리스 세션으로 실행한다

**상태** 검토 · 2026-08-06 · **아직 채택하지 않았다**

사용자 제안: [harness-framework](https://github.com/csm-kr/harness-framework) 의 실행
모델을 가져와 각 게이트를 `exec` 로 헤드리스 실행하고, 컨텍스트는 문서·로그로만 넘긴다.

이 문서는 **검토**다. 구현하지 않았다.

---

## 맥락

### 사용자의 진단

> 지금 스킬들이 너무 하는 일이 많아서 그런지 잘 못하는 것 같다

증거가 있다. 스킬 자체는 작다 — SKILL.md 가 1.3~5KB, 게이트마다 `run.mjs` 와
`check.mjs` 한 벌씩이다. 문제는 스킬의 크기가 아니라 **한 세션이 12개를 다 들고 간다**는
것이다. 실제로 나온 실패들이 전부 그 모양이다.

| 증상 | 무엇이 실제로 일어났나 |
| --- | --- |
| 필드 이름이 갈렸다 | 조립기는 `headline_lines`, 플랜은 `headline`. **같은 세션에서 두 번** — `render.mjs` 에서 고치고 `mockup.mjs` 에서 또 냈다 |
| 목업을 자기 HTML 로 만들었다 | `origin_note` 에 "ChatGPT 대화 산출물이 아니다" 라고 **알면서 적었다.** 세션이 길어 빠른 길을 골랐다 |
| 53분 쓰고 중간에 멈췄다 | 게이트 12개를 한 세션이 이어 달렸다 |
| 픽스처가 손으로 쓴 HTML 이었다 | 조립기가 바뀌어도 테스트가 초록. 판정기와 조립기를 **동시에** 들고 있으면 둘이 갈린 것을 못 본다 |

전부 설계 결함이 아니라 **주의력 결함**이다. 규칙은 문서에 있었고 읽히지 않았다.
`sales-story.md` 가 "공급처와 쿠팡의 판매 표현을 그대로 쓴다" 고 적어 두었는데
flow-map 은 그 표현을 전부 "옮겨 오지 않는 것" 으로 분류했다 — 두 문서를 같은 세션이
썼다.

### harness-framework 가 하는 것

핵심은 `template/scripts/execute.py` 한 파일이다.

```python
result = subprocess.run(
    ["claude", "-p", "--dangerously-skip-permissions", "--output-format", "json", prompt],
    cwd=self._root, capture_output=True, text=True, timeout=1800,
)
```

- **step 마다 새 세션.** 대화 맥락이 넘어가지 않는다
- 컨텍스트는 `_load_guardrails()` 가 만든다 — `CLAUDE.md` + `docs/**/*.md` 전량
- 앞 step 의 결과는 **한 줄 요약만** 넘어간다

```python
lines = [f"- Step {s['step']} ({s['name']}): {s['summary']}"
         for s in index["steps"] if s["status"] == "completed" and s.get("summary")]
```

- 상태는 `phases/{task}/index.json` 으로 주고받는다. 자식이 `completed | error | blocked`
  와 `summary` 를 쓰고 부모가 읽는다
- 실패하면 **이전 에러를 프롬프트에 넣어** 3회까지 재시도
- 출력은 `step{N}-output.json` 에 통째로 남는다
- step 마다 커밋 2단(코드 / 메타)

README 의 한 줄이 설계 의도를 다 말한다.

> 각 step 은 독립된 Claude 세션에서 실행되고, 정본 문서와 가드 훅이 매 step 에 주입되어
> **맥락 유실·규칙 이탈·검증 누락**을 구조적으로 막는다

우리가 겪은 세 가지가 그대로 적혀 있다.

## 우리는 이미 절반 이상 갖고 있다

이게 이 검토의 핵심이다. **새 프레임워크를 얹는 일이 아니라 실행기 하나를 만드는 일이다.**

| harness | 우리 것 | 상태 |
| --- | --- | --- |
| `phases/{task}/step{N}.md` — 작업 지시서 | 게이트별 `SKILL.md` | **있다** |
| step 의 AC — 실행 가능한 검증 명령 | 게이트별 `scripts/check.mjs` | **있다.** 우리 게 더 강하다 |
| `index.json` — step 상태 | `work/gates.json` — 해시 사슬 포함 | **있다.** 우리 게 더 강하다 |
| `_load_guardrails()` — 정본 주입 | `references/` | 있다. 그런데 **주입하는 쪽이 없다** |
| `execute.py` — step 실행기 | **없다** | ← 이것만 없다 |
| 3회 재시도 + 에러 주입 | 없다 (사람이 다시 부른다) | 없다 |
| 가드 훅 (TDD·위험 명령) | 없다 | 없다 |

`gates.mjs` 가 순서를, `check.mjs` 가 판정을, `gates.json` 이 상태를 이미 소유한다.
빠진 것은 **게이트를 새 세션에서 돌리는 실행기**뿐이다.

### 우리 게 더 강한 곳 — 그대로 둔다

harness 는 **자식이 자기 상태를 `index.json` 에 쓴다.** 자식이 "completed" 라고 쓰면
그게 통과다. 우리는 그 패턴을 이미 거부했다.

> `--pass` 는 언제나 `scripts/check.mjs` 를 다시 돌린다. 검사를 건너뛴 통과 기록은 남지 않는다.

**자식의 자기 보고를 믿지 않는다.** 이 규칙을 harness 쪽에 맞춰 낮추면 안 된다.
헤드리스로 가면 오히려 더 중요해진다 — 자식이 무엇을 했는지 사람이 안 보기 때문이다.

## 결정 (제안)

harness-framework 를 **설치하지 않는다.** 실행 모델만 가져온다.

### 1. `orchestrate gate G_n --exec` 을 만든다

```
orchestrate gate G3 --exec
  ├─ 컨텍스트 팩을 조립한다 (아래 2번)
  ├─ claude -p --output-format json  ← 새 세션. 30분 타임아웃
  ├─ work/logs/G3-<시각>.json 에 통째로 남긴다
  ├─ check.mjs 를 **부모가 다시 돌린다**
  └─ 통과 → gates.json 기록 · 실패 → 사유를 넣어 재시도 (최대 2회)
```

`claude -p` 는 확인했다 (v2.1.223). 파이썬으로 다시 쓰지 않는다 — 스택이 Node 한 벌이다.

### 2. 컨텍스트는 **게이트마다 선언한다.** 통째로 붓지 않는다

harness 의 `_load_guardrails()` 는 `docs/**/*.md` 를 전부 넣는다. 우리가 그대로 하면
게이트마다 178KB 를 읽는다 (orchestrator references 112KB + benchmark 66KB).
**그러면 "컨텍스트가 너무 많아서 잘 못한다" 를 12번 반복하는 것이다.**

게이트마다 무엇을 읽는지 선언한다. `run.mjs` 의 `reading:` 이 이미 그 목록이다 —
지금은 사람에게 출력만 하고 있다. 그것을 실제 주입 목록으로 승격한다.

```
G3 컨텍스트 팩
  정본   sales-story.md · benchmark/BENCHMARK.md · art-direction.md
  입력   work/SSOT.md · work/flow-map.md
  요약   G1 · G2 의 한 줄 요약
  지시   detail-page-g3-plan/SKILL.md
  판정   check.mjs 의 거부 사유 목록 (무엇으로 판정되는지 미리 알려준다)
```

전량 주입 대비 얼마나 줄어드는지는 실측해야 한다. 이 값이 이 제안의 손익분기다.

### 3. 스크립트 게이트는 세션을 띄우지 않는다

| 유형 | 게이트 | `--exec` |
| --- | --- | --- |
| 스크립트 | G5 · G9 · G10 · G11 | **안 쓴다.** node 를 직접 부른다 |
| 에이전트 | G1 · G2 · G3 · G7 | **쓴다.** 판단이 필요하고 컨텍스트가 제일 많이 샌 곳 |
| 혼합 | G4 · G6 · G8 | **쓴다.** 단 생성·렌더는 `run.mjs` 가 하고 세션은 판단만 |

12개를 다 세션으로 돌리면 시작 비용만 12번이다. **컨텍스트가 문제였던 게이트에만 쓴다.**

### 4. `blocked` 를 상태로 들인다

harness 에 있고 우리에겐 없다. G6 의 컷 선별, init 의 인증처럼 **사람이 봐야 끝나는**
자리가 실제로 있다. 지금은 그런 게이트가 실패인지 대기인지 구분되지 않는다.

### 5. 가드 훅은 **나중에** 본다

`hooks/tdd-guard.js` 는 매력적이다 — 사용자 CLAUDE.md 가 TDD 를 요구하는데 지키는 것은
성의뿐이다. 다만 이건 이번 제안과 독립이고, PreToolUse 훅은 호스트마다 다르다
(ADR-0005 — 호스트를 고정하지 않는다). 별도로 검토한다.

## 결과

### 좋아지는 것

- **게이트가 자기 것만 본다.** `headline_lines` 같은 필드 갈림은 두 파일을 같은 세션이
  들고 있어서 났다. G4 세션은 G9 조립기를 아예 안 읽는다
- **빠른 길을 못 고른다.** "origin: self-rendered" 는 앞뒤 맥락을 아는 세션이 판단을
  절약한 결과다. 지시서와 판정 기준만 받은 세션에는 절약할 맥락이 없다
- **로그가 남는다.** 지금은 무엇을 왜 그렇게 했는지가 대화에만 있고 대화는 사라진다
- **재시도가 자동이다.** 3회차에 중간에 멈춘 것이 사람이 다시 안 불러서였다
- **회차가 재현된다.** 같은 문서 + 같은 게이트 = 같은 실행

### 나빠지는 것 — 솔직히

- **디버깅이 멀어진다.** 실패가 대화가 아니라 `work/logs/G3-*.json` 에 있다.
  지금은 게이트가 막히면 그 자리에서 고친다. 세션이 분리되면 로그를 열어야 한다
- **시작 비용 × 7.** 에이전트·혼합 게이트 7개가 각각 세션을 띄운다.
  95분 예산에서 이게 얼마인지는 **재 봐야 안다**
- **컨텍스트 팩이 새 유지보수 대상이다.** 게이트가 읽어야 할 문서를 선언해 두면
  문서가 늘었을 때 팩이 갈린다. `run.mjs` 의 `reading:` 과 SKILL.md 를 대조하는 테스트가
  이미 있으니(`purity.test.mjs`) 거기에 붙인다
- **`--dangerously-skip-permissions` 를 루프에서 돈다.** 자식이 god-tibo 를 부르고
  Chrome 을 띄운다. 워크스페이스 밖으로 못 나가게 하는 것은 지금도 `stage.mjs` 의
  `guard()` 가 하지만, 권한을 끈 세션을 12번 도는 것은 다른 문제다. **채택 전에 정해야 한다**

### 무엇으로 판단할 것인가

제안을 채택할지는 **한 게이트로 재 보고 정한다.** G3(플랜)이 후보다 — 컨텍스트가 제일
많이 새고, 판정이 이미 강하고, 실패해도 되돌리기 싸다.

| 재는 것 | 통과 기준 |
| --- | --- |
| 컨텍스트 팩 크기 | 전량 주입 대비 1/3 이하 |
| G3 벽시계 | 지금(12분 예산) 대비 +50% 이내 |
| `check.mjs` 첫 통과율 | 지금과 같거나 높다 |
| 사람 개입 횟수 | 줄어든다 |

**하나라도 못 넘으면 채택하지 않는다.** 게이트 12개를 세션 12개로 바꾸는 것은
"게이트만 많아진다" 는 지적을 반복할 수 있는 변경이다.

## 기각한 대안

### harness-framework 를 플러그인으로 설치한다

```bash
claude plugin install harness@harness-framework -s project
```

**기각.** `/harness:init` 이 `docs/PRD.md` `USER_FLOW.md` `RULES.md` `phases/` 를 주입한다.
우리 `docs/` 에는 이미 ARCHITECTURE·ADR·GUIDE·PRD 가 있고 게이트 순서는 `gates.mjs` 가
소유한다(ADR-0001). 두 골격이 겹치면 **정본이 둘이 된다** — 이 프로젝트가 이미 한 번
당한 실패다(문서는 "표현을 쓴다", 산출물은 "안 쓴다").

가져올 것은 실행 모델이고, 그건 `execute.py` 200줄이다. 플러그인 전체가 아니다.

### phase/step 을 게이트 위에 새로 얹는다

**기각.** 게이트가 곧 step 이다. `phases/{task}/step{N}.md` 를 따로 만들면
SKILL.md 와 두 벌이 된다. 지시서는 이미 있다.

### 서브에이전트(Agent 도구)로 게이트를 위임한다

**보류.** 컨텍스트 격리라는 목적은 같고 비용이 훨씬 싸다. 다만 서브에이전트는
호출한 세션 안에서 산다 — 로그가 파일로 남지 않고, 재시도가 자동이 아니고,
회차 재현이 안 된다. **먼저 이쪽을 재 보는 것이 순서일 수 있다.**
G3 실측을 할 때 `--exec` 와 서브에이전트를 같이 재면 답이 나온다.
