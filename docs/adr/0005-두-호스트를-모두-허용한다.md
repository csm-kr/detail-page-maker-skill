# ADR-0005 — 두 호스트를 모두 허용하고 구동 호스트를 고정하지 않는다

**상태** 채택 · 2026-08-05

## 맥락

사용자는 Claude Code와 Codex를 둘 다 쓴다. 양쪽 CLI가 설치돼 있다는 전제다.
답은 명시적이었다 — "둘다 되게 하고, 그런데 스킬 설치를 로컬에 해야함."

현재 상태는 **양쪽이 인식하지만 순서가 갈릴 수 있다.**

- 사본이 `.claude/skills`와 `.agents/skills`에 109개 파일씩 동일하게 있어 둘 다 읽는다.
- 그런데 `SKILL.md`에 **"호스트가 Codex가 아니면 `claude-code.md`를 함께 읽는다"** 라는
  조건문이 있다. `claude-code.md`만 있고 `codex.md`가 없는 비대칭이 이 조건문을 낳았고,
  조건문이 호스트별로 다른 읽기 순서를 허용했다.

## 결정

**구동 호스트를 고정하지 않는다.** 어느 쪽에서 `start`해도 되고, 회차 중간에 바꿔도 된다.

| 구분 | 위치 | 호스트별 차이 |
| --- | --- | --- |
| 게이트 정의·순서·거부 | `lib/gates.mjs` | **없음** |
| 게이트 상태 | `<프로젝트>/work/gates.json` | **없음** |
| 단계 실행 | 각 단계 `run.mjs` | **없음** |
| 트래커 | `scripts/track.mjs` | **없음** |
| sub-agent 역할·lane | `references/{claude-code,codex}.md` | 있음 |

- **공유 상태는 `gates.json` 하나뿐이다.** 그래서 호스트를 바꿔도 이어서 진행된다.
- 게이트마다 `by_host`를 기록한다. 어느 게이트를 누가 했는지 나중에 볼 수 있어야 한다.
- `codex.md`를 신설해 비대칭을 없애고, `SKILL.md`의 "호스트가 Codex가 아니면" 조건문을
  제거한다.
- 두 호스트 문서는 **게이트 순서를 다시 적지 않는다.** 순서 목록이 `gates.mjs` 밖에
  나타나면 테스트가 실패한다.
- init은 어느 호스트에 설치할지만 묻는다(기본값 둘 다). **누가 구동할지는 묻지 않는다.**

## 결과

**좋아지는 것.** 브라우저 CDP가 한쪽에서만 살아 있거나 한쪽 세션이 길어졌을 때
그냥 다른 쪽에서 이어서 할 수 있다. 순서가 스크립트에 있으니 결과가 같다.

**나빠지는 것.** 회차마다 어느 게이트를 누가 했는지 갈릴 수 있다. 그것을 문제로 보지
않고 `by_host` 기록으로 관찰만 한다 — 결과가 같다면 누가 했는지는 성능 문제일 뿐이다.

**전제.** 두 호스트가 같은 워크스페이스 파일을 본다는 것. 다른 기계에서 나눠 하는 것은
범위 밖이다.

## 기각한 대안

| 대안 | 기각 이유 |
| --- | --- |
| Claude Code 단독 | 2회차가 이 구성으로 끝까지 돌았지만, 사용자가 둘 다 쓰기를 원한다 |
| Codex 단독 | god-tibo·hyperframes가 Codex 생태계지만 [ADR-0004](0004-인증만-호스트에-남긴다.md)에서 Codex 호스트가 불필요함을 확인했다 |
| 게이트별 호스트 고정 (G4·G6은 Codex) | 조정 비용이 크고, 어느 게이트를 누가 해야 하는지가 또 하나의 순서 규칙이 된다 — `gates.mjs` 단일 출처 원칙을 흐린다 |
| init이 구동 호스트를 묻고 다른 쪽을 거부 | 실익이 없다. 순서는 이미 스크립트가 강제한다 |
