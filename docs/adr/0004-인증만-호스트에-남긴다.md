# ADR-0004 — 스킬과 런타임은 로컬, 인증만 호스트에 남긴다

**상태** 채택 · 2026-08-05

## 맥락

사용자 방침은 "호스트에 깔지 않는다"다. 그런데 현재 `dependencies.json`은 자기와
모순돼 있다.

```json
"runtimes":    { "hyperframes": "project-local-runtime-for-motion" }
"host_skills": [ "hyperframes" ]
```

실제로 해석되는 쪽은 `host_skills`이고, `doctor`가 `C:\Users\csm81\.codex\skills\hyperframes`
를 보고한다. **틀린 쪽이 이기고 있었다.** 관련 코드는 세 곳에 퍼져 있다.

| 위치 | 현재 |
| --- | --- |
| `dependencies.json:17` | `"host_skills": ["hyperframes"]` |
| `scripts/detail-page.mjs:68` | `manifest.host_skills.map(...)` |
| `references/claude-code.md:17` | "`doctor`의 `host_skills.hyperframes`는 호스트 설치본을 찾는다" |

그리고 사용자 질문 — "이미지는 god-tibo 를 써야하니까 codex 가 필요해?"

**확인 결과 아니다.** `god-tibo-imagen`은 `~/.codex/auth.json`(실측 4.1 KB)과
`~/.codex/installation_id`를 읽어 `chatgpt.com/backend-api/codex/responses`로 POST하는
**순수 node 라이브러리**다. Codex 에이전트가 호스트일 필요가 없다 — 2회차를 Claude Code
에서 돌려 스틸 30장을 만들었다. 하지만 그 파일은 Codex CLI가 소유하므로 벤더링할 수 없다.

## 결정

**경계를 인증에 긋는다.**

| | 로컬 | 호스트 |
| --- | --- | --- |
| 스킬 | **전부** | 없음. 있으면 `start` 거부 |
| 런타임 (hyperframes, 폰트, python, ffmpeg 경로) | **전부** | 없음 |
| 인증 (`~/.codex/auth.json`, ChatGPT 로그인 세션) | 불가 | **여기뿐** |

- `host_skills` 개념을 **세 곳에서 동시에 없앤다.** 하나라도 남으면 `doctor`가 계속
  홈을 보고 통과시킨다.
- **hyperframes 는 두 개다.** 이 ADR 을 처음 쓸 때 둘을 섞어 썼는데, 실제로 확인하니
  다른 것이었다.

  | | 무엇 | 어디 | 처리 |
  | --- | --- | --- | --- |
  | 렌더러 | npm CLI `hyperframes` (`render-motion.mjs` 가 `npx hyperframes@0.7.90` 로 부른다) | npm | **`motion/` 에 로컬 설치 + 핀.** 실행 완료 |
  | 저작 가이드 | 호스트 스킬 `hyperframes` (SKILL.md + references, package.json 없음) | `~/.codex/skills/` | **미해결 — 아래** |

  옛 `host_skills: ["hyperframes"]` 와 `doctor` 가 가리킨 것은 **뒤쪽**이었다.
  앞쪽은 `npx` 로 매번 내려받고 있었으므로 프로젝트-로컬도 아니었다. 둘 다 문제였다.
- init은 `~/.codex/auth.json`의 **존재 여부만** 확인한다. **내용을 읽지도 출력하지도
  않는다.** 없으면 멈추고 사용자에게 `codex login`을 요청한다 — ChatGPT 로그인과 같은
  취급이며 **로그인은 사용자만 한다.**
- 호스트 홈 세 경로(`~/.claude/skills`, `~/.agents/skills`, `~/.codex/skills`)에
  detail-page 계열이 있으면 `start`가 거부한다. 로컬 방침을 게이트로 만든다.

## 결과

**좋아지는 것.** 방침이 문장이 아니라 게이트가 된다. 왜 인증만 예외인지 문서에 근거가
남아 다음 회차에 "이것도 로컬로 옮기자"는 헛수고를 하지 않는다.

**나빠지는 것.** 인증은 여전히 외부 의존이므로 만료되면 G6에서 막힌다. 완화:
`env.lock.json`이 30일보다 오래되면 `init --recheck`를 요구하고, init이 `--dry-run`으로
미리 검증한다.

## 미해결 — 저작 가이드 스킬 체인

호스트에 `hyperframes` 계열 스킬이 **7개** 있다.

```text
hyperframes  hyperframes-animation  hyperframes-cli  hyperframes-core
hyperframes-creative  hyperframes-keyframes  hyperframes-registry
```

G8 이 컴포지션 HTML 을 쓸 때 읽는 저작 지침이다(`hyperframes/SKILL.md` 가
"전체 계약은 `/hyperframes-core` 에 있다" 고 가리킨다). 렌더러가 아니라 **문서**다.

두 갈래이고 **정하지 않았다.**

| 안 | 내용 | 값 |
| --- | --- | --- |
| 번들 | 7개를 `orchestrator/.agents/skills/` 로 복사 | 방침(스킬은 로컬)에 맞는다. 대신 남의 스킬 7개를 우리 트리에 넣고 갱신을 따라가야 한다 |
| 호스트 유지 | 저작 지침은 호스트 것으로 둔다 | 트리가 가볍다. 대신 다른 기계에서 그 스킬이 없으면 G8 이 지침 없이 돈다 |

**렌더러가 로컬이므로 GIF 는 어느 쪽이든 구워진다.** 갈리는 것은 컴포지션의 품질이다.
`blockers()` 는 이것을 막지 않는다 — 막을지도 이 결정에 달렸다.

## 기각한 대안

| 대안 | 기각 이유 |
| --- | --- |
| `auth.json`을 워크스페이스로 복사 | 자격증명 복제다. Codex CLI가 갱신하면 사본이 만료되고, 평문 토큰이 프로젝트 폴더에 남는다 |
| 이미지 생성을 위해 Codex를 호스트로 고정 | 필요 없다. 순수 node 경로임을 확인했다 |
| `codex-cli` 폴백 provider를 기본으로 | 그쪽은 실제로 codex 바이너리를 요구하고 `--size`를 지원하지 않는다 |
| 방침을 문서에만 적는다 | 2회차에 그렇게 했고 호스트 의존이 남았다 |
