# ADR-0002 — 단계를 개별 스킬 11개 + 오케스트레이터로 분리한다

**상태** 채택 · 2026-08-05

## 맥락

`detail-page-maker-skill` 하나가 조사·기획·목업·생성·모션·조립·QA·납품을 다 한다.
그래서 **어느 일을 안 했는지 스킬 자신이 모른다.** 2회차에 13개를 누락하고도 QA를
통과했다.

사용자 요구는 명시적이었다 — "각 단계를 스킬로 만들어주고, 그걸 관리하는 오케스트레이터도
만들고 그것도 스킬로."

## 결정

스킬 13개로 쪼갠다.

```text
detail-page-init                  워크스페이스 1회. 환경·세팅·정리
detail-page-orchestrator          제작 진입점. 순서·상태·검사·보고·트래커
  └─ detail-page-g1-fact … g11-deliver   (11개)
```

- **오케스트레이터는 일을 하지 않는다.** 순서와 판정만 한다.
- 각 단계 스킬은 `run.mjs`(작업)와 `check.mjs`(판정)를 가진다.
  **판정은 그 단계가 소유하고 순서는 소유하지 않는다.**
- `G0`은 스킬이 아니라 오케스트레이터의 `start` 명령이다.
- init 스킬 이름은 `detail-page-init`이다. Claude Code에 `/init` 내장 명령이 있어
  그 이름을 쓸 수 없고 가릴 수도 없다. 사용자가 `$init`이라 부르면 이 스킬을 뜻한다는
  것을 오케스트레이터 문서에 적는다.
- 모든 단계 `description`에 **"오케스트레이터가 G_n 에서 호출한다 / 직접 호출하면
  거부된다"** 를 명시한다.

## 결과

**좋아지는 것.**

- 각 단계가 자기 산출물의 유무로 스스로를 판정한다.
- 단계별로 필요한 참고 문서만 물려 서브에이전트에 위임할 수 있다 — 컨텍스트 격리.
- 무엇을 안 했는지 표 한 장으로 보인다.

**나빠지는 것.**

- 호스트 스킬 목록이 13줄로 시끄러워진다. 완화: `description`에 직접 호출 금지를 적고,
  실제로 거부되므로 오호출이 사고가 되지 않는다.
- 13개를 동기화해야 한다. 완화: 원본 한 벌 ([ADR-0003](0003-스킬-원본은-한-벌이다.md)).
- 번들 의존 스킬(109개 파일)을 13번 복제하면 안 된다. 오케스트레이터 아래 **한 벌**만 둔다.

## 기각한 대안

| 대안 | 기각 이유 |
| --- | --- |
| 한 스킬 유지 + 내부 단계 분리 | 지금 구조다. 무엇을 안 했는지 스킬이 모른다는 문제가 그대로 남는다 |
| 7개로 묶는다 | 2회차 누락이 **전부 "묶여 있던 단계의 후속"** 이었다. 목업(G1.5)에 붙어 있던 무드 주입, 스틸 생성에 붙어 있던 선별, brief에 붙어 있던 컴포지션 재작성 — 묶으면 뒤쪽이 사라진다 |
| 단계를 스킬이 아닌 `references/` 문서로 | 호스트 목록에 뜨지 않아 위임 단위가 되지 못하고, 결국 지금과 같은 문서 진입점이다 |
| 접두를 `dp-`로 짧게 | 목록에서 묶여 보이지 않는다. `detail-page-`를 유지한다 |
