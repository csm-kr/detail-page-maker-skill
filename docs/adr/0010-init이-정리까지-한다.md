# ADR-0010 — init이 필요한 것만 남기고, 삭제하지 않고 `.trash/`로 옮긴다

**상태** 채택 · 2026-08-05

## 맥락

사용자 지시 — "init 은 필요한 것만 두고 정리하는 것까지 포함한다."

재구성이 끝나면 필요 없어지는 것이 여럿 남는다.

| 남는 것 | 왜 남는가 |
| --- | --- |
| 루트 `work/`의 11개 스크립트 | 단계 스킬로 옮기면 원본이 우회 경로가 된다 |
| `build-all.mjs` | `orchestrator run`이 대체한다 |
| 옛 단일 스킬의 스크립트 | 남기면 게이트를 안 거치는 실행 경로다 |
| `.claude/skills`·`.agents/skills`의 옛 복사본 | junction으로 바뀌면 죽은 사본이다 |
| `docs/reference/templates.md` (1,208줄) | G4 스킬 안으로 들어간다 |
| 옛 프로젝트·생성물 | 회차마다 새로 만들므로 누적된다 |

그런데 **워크스페이스 루트는 git 저장소가 아니다.** `.skill-src`만 repo다. 즉
`projects/`·`work/`·`motion/`·`data/`는 버전 관리 밖이고 **되돌릴 지점이 없다.**
2회차에 `rm -rf`로 프로젝트를 지웠고 그때 studio 서버를 죽여 복구하지 않았다 —
파괴적 동작이 부수 효과를 남긴 전례가 있다.

## 결정

**init이 정리한다. 단 삭제하지 않는다.**

```bash
node scripts/init.mjs --prune            # 기본 dry-run. 목록만 출력
node scripts/init.mjs --prune --apply    # .trash/<타임스탬프>/ 로 이동
```

### 3등급 분류

| 등급 | 처리 | 대상 |
| --- | --- | --- |
| **A 자동** | 목록 출력 후 이동 | junction 전환 후 남은 스킬 복사본, 빈 스켈레톤(`.detail-page/authoring`), 옮긴 뒤의 루트 `work/*.mjs`·`*.py`, `build-all.mjs`, 옛 단일 스킬의 `scripts/` |
| **B 확인** | **사용자에게 하나씩 묻는다** | 옛 프로젝트 디렉터리, `work/gen/`, `motion/out/`, 옛 목업, `docs/reference/templates.md`(이동 확인) |
| **C 제외** | **절대 건드리지 않는다** | `~/.codex/auth.json`과 모든 인증 · `.skill-src` · `projects/*/output/` · `projects/*/work/{SSOT.md, flow-plan.json, design-ref/}` · `docs/`(단 `reference/templates.md`는 G4 이동 후 B) |

### 규칙

- **삭제 대신 이동.** `.trash/<ISO 타임스탬프>/`에 원래 경로 구조를 유지해 옮긴다.
  되돌리려면 그대로 옮겨 놓으면 된다.
- `.trash/`는 init이 지우지 않는다. 사용자가 지운다.
- 이동 결과를 `env.lock.json.pruned`에 `{at, trash, entries}`로 기록한다.
- **프로세스를 죽이지 않는다.** 정리 대상이 사용 중이면 이동을 건너뛰고 사유를 출력한다.
  2회차처럼 서버를 죽여 길을 여는 일을 하지 않는다.
- 호스트 홈의 detail-page 계열도 같은 방식으로 `.trash/`로 옮긴다. 사용자 방침 위반을
  치우는 것이지만 그것도 삭제는 아니다.

### 출력 형태

```text
$ node scripts/init.mjs --prune

   work/build-all.mjs                          orchestrator run 이 대체
   work/build-page.mjs                         g9-build 로 이동됨

   motion/out/                                 재생성 가능하나 렌더 10분

 --apply 를 붙이면 .trash/2026-08-05T12-40/ 로 옮긴다. 삭제하지 않는다.
```

## 결과

**좋아지는 것.** 우회 경로가 실제로 없어진다(§강제 장치 6.4). 정리가 init에 있으므로
"나중에 치우자"가 남지 않는다. 되돌릴 수 있으므로 과감하게 정리할 수 있다.

**나빠지는 것.** `.trash/`가 디스크를 먹는다. init이 지우지 않으므로 사용자가 관리한다 —
자동 삭제를 붙이는 순간 이 결정의 안전성이 사라진다.

## 기각한 대안

| 대안 | 기각 이유 |
| --- | --- |
| `rm -rf`로 지운다 | 루트가 git이 아니어서 복구가 없다. 2회차에 실제로 부수 효과를 남겼다 |
| 정리를 사람이 손으로 | "나중에"가 되어 우회 경로가 남는다. 2회차에 `work/` 11개가 그대로 남아 있었다 |
| 정리 전용 스킬을 따로 만든다 | 실행되지 않는 단계가 하나 더 생긴다. init에 붙이면 세팅과 함께 반드시 돈다 |
| 루트를 git 저장소로 만들어 되돌림을 확보 | 검토할 만하지만 별개 결정이다. 생성물 수십 MB가 들어가고 `.skill-src`가 중첩 repo가 된다. `.trash/`가 더 작은 변경이다 |
| 자동 등급만 두고 B를 없앤다 | 발행물을 포함한 옛 프로젝트를 묻지 않고 옮기게 된다 |
