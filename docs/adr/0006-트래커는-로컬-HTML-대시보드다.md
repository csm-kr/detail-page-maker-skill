# ADR-0006 — 진행 트래커는 로컬 HTML 대시보드다

**상태** 채택 · 2026-08-05

## 맥락

사용자 요구 — "뭔가 시각적으로 어떤 단계인지 사용자가 알고싶을것 같은데 그걸 추적해서
전체 맵에서 그걸 반짝반짝하게 시각적으로 보여주는 그런 트래커."

2회차에는 진행 상황을 볼 방법이 없었다. 어느 단계인지, 얼마나 걸렸는지, 무엇이 남았는지
사용자가 알 수 있는 것은 내가 말한 것뿐이었다. 그리고 내가 말한 것은 틀렸다 —
13개를 누락하고 "전부 완료"라고 했다.

## 결정

`orchestrator track`이 **로컬 HTML 대시보드**를 띄운다.

| 항목 | 방식 |
| --- | --- |
| 서버 | node `http` 하나. 외부 의존 0. 기존 `lean-studio-server.mjs` 패턴 재사용 |
| 포트 | 9310 고정, 사용 중이면 +1씩 탐색 |
| 데이터 | `gates.json` + `env.lock.json`. **읽기만 한다** |
| 갱신 | `fs.watch` → SSE(`EventSource`). 폴링 없음 |
| 스타일 | 인라인 CSS. `@keyframes`로 진행 중 노드 `box-shadow` 맥동 |

### 노드 상태 5종

| 표시 | 뜻 | 시각 |
| --- | --- | --- |
| `✗` | 미착수 | 회색 외곽선 |
| `⟨⟨ ⟩⟩` | 진행 중 | **브랜드 컬러 발광 + 맥동** |
| `○` | 통과 | 채워진 원 |
| `⚠` | 무효화됨 (상류 해시 변경) | 노랑 + 원인 게이트 화살표 강조 |
| `⛔` | 거부 | 빨강 + 부족 항목 |

노드를 클릭하면 **거부 이유와 부족 항목**을 보여준다. 출처는 `check.mjs`의 마지막 실행
결과다 — 사람이 보는 것과 게이트가 판정하는 것이 같아야 한다.

### 두 가지 원칙

1. **트래커는 상태를 만들지 않는다.** `gates.json`을 읽을 뿐이다. 트래커가 상태를 쓰면
   상태가 두 곳에 생기고 갈린다.
2. **트래커는 막지 않는다.** 예산 초과에 `⚠`를 붙이지만 게이트가 아니다. 막으면
   "시간 때문에 검사를 건너뛴다"가 정당화된다.

## 결과

**좋아지는 것.** 전체 맵과 현재 위치가 한눈에 보인다. 예산 초과가 그 자리에서 보이므로
어느 게이트를 완화할지 판단할 근거가 쌓인다 ([ADR-0007](0007-벽시계-95분과-완화-규칙.md)).
게이트 상태를 사람이 직접 보므로 내 보고에 의존하지 않는다.

**나빠지는 것.** 서버 프로세스가 하나 더 뜬다. 스스로 띄운 것이므로 `killed.json`에
넣지 않고 `Ctrl+C`로 끈다. 브라우저 탭을 열어야 하므로 터미널만 보는 흐름에서는
`gates` 표를 그대로 쓴다.

## 기각한 대안

| 대안 | 기각 이유 |
| --- | --- |
| 터미널 `gates --watch` | 사용자가 원한 "전체 맵에서 반짝반짝"이 ANSI로는 약하다. 다만 `gates` 정적 표는 유지한다 |
| Artifact (claude.ai 호스팅) | 로컬 파일을 읽을 수 없어 실시간 상태를 볼 수 없다 |
| 로그 파일 tail | 맵이 없다. 어디까지 왔는지가 아니라 무엇이 지나갔는지만 보인다 |
| 기존 Studio 화면에 게이트 표 추가 | Studio는 G11에서만 열린다. 그때는 이미 끝났다 |
