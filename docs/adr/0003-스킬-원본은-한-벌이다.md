# ADR-0003 — 스킬 원본은 한 벌이고 두 호스트 경로는 junction 우선이다

**상태** 채택 · 2026-08-05

## 맥락

사용자 질문이 정확했다 — "`.skill-src` 같은게 있어야하나 의문."

현재 실측.

```text
.skill-src/skills   109개 파일   ← git 저장소 (브랜치 assets-default-square)
.claude/skills      109개 파일   ← Claude Code
.agents/skills      109개 파일   ← Codex
```

**같은 내용이 세 벌 있고 2회차에 이것을 손으로 동기화했다.** 스킬 문서를 고칠 때마다
세 곳을 맞췄고, 맞았는지는 파일 수를 세어 확인했다 — 내용 일치는 확인하지 않았다.
사본이 늘어난 이유는 두 호스트가 각자 다른 경로를 읽기 때문이다. 원본을 없앨 수는
없다 (git 이력이 `.skill-src`에만 있다).

## 결정

**원본은 `.skill-src/skills` 한 벌.** 편집은 여기만 한다. 두 호스트 경로는 init이 만든다.

| 모드 | 방법 | 언제 |
| --- | --- | --- |
| **junction** (우선) | 스킬별 디렉터리를 `mklink /J`로 연결. 관리자 권한 불필요 | 기본 |
| **복사** (폴백) | 파일 복사 + 해시 기록. 원본 수정 후 `init --sync` 필요 | junction 인식 실패 시 |

- init이 junction을 만든 뒤 **두 호스트가 실제로 그 스킬을 인식하는지 검증한다.**
  두 호스트의 스킬 탐색이 junction을 따르는지는 **미검증**이므로 검증 실패를 정상
  경로로 설계한다.
- 어느 모드인지 `env.lock.json.install.mode`에 기록한다.
- `.claude/skills`·`.agents/skills`는 **생성물**이다. 여기를 직접 고치면 다음 `init`에서
  덮어써진다. 그 사실을 오케스트레이터 문서에 적는다.
- 워크스페이스 루트는 git 저장소가 아니므로 `.gitignore`로 생성물을 표시할 수 없다.
  대신 두 디렉터리에 `GENERATED.md`(한 줄: 원본은 `.skill-src`)를 둔다.

## 결과

**좋아지는 것.** junction이면 원본 수정이 두 호스트에 **즉시** 반영된다. 동기화 작업이
사라지고, 사본은 확인 대상이 아니라 참조가 된다.

**나빠지는 것.** junction은 Windows 전용 개념이고 git이 잘 다루지 못한다. 그래서
`.skill-src`만 git 저장소로 두고 두 사본은 버전 관리 밖에 둔다. 복사 폴백에서는
`init --sync`를 잊으면 옛 사본이 돈다 — 해시 불일치를 `start`가 거부한다.

## 기각한 대안

| 대안 | 기각 이유 |
| --- | --- |
| `.skill-src`를 없애고 `.claude/skills`를 원본으로 | git 이력이 `.skill-src`에 있고, Codex 사본은 여전히 필요하다. 사본 2벌 문제가 그대로 남는다 |
| 세 벌 유지 + 동기화 스크립트 | 2회차 방식이다. 파일 수만 맞추고 내용은 갈릴 수 있다 |
| 심볼릭 링크(`mklink /D`) | 관리자 권한 또는 개발자 모드가 필요하다. junction은 필요 없다 |
| 호스트 홈에 한 벌 두고 양쪽이 공유 | **사용자 방침 위반.** 호스트 홈에는 아무것도 깔지 않는다 |
