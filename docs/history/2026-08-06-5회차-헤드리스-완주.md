# 5회차 — 헤드리스로 끝까지 걸어보기

4회차에서 `--exec` 를 만들고 G2 하나를 재 봤다. 5회차는 **새 회차를 열어 G1 부터
전 구간을 헤드리스로 완주**한다. 표본이 하나였던 것을 늘리는 것이 목적이고,
실제로는 그 과정에서 실행기의 치명적 결함 하나가 드러났다.

- 프로젝트 `해충끈끈이` · 공급처 도매꾹 28573280 · 기준작 쿠팡 9570309591
- 실물 사진 **0장** (판매자가 없다고 했다)

## 1. 실행기가 자식의 권한을 통째로 깨뜨리고 있었다

가장 큰 것부터. **4회차에 잰 G2 12.2분은 Bash 가 하나도 안 되는 상태에서 나온 값이다.**

### 증상

G1 세션이 두 회차 연속 이렇게 보고했다.

```
샌드박스가 node 를 막아 gate G1 --check 를 돌리지 못했고 …
```

같은 명령을 손으로 돌리면 거부 0건에 종료 코드 0 이었다. 그래서 **자식의 오진으로
치부했다.** 두 번이나.

### 실제 원인

`work/exec/G2-1.json` 에 거부 12건이 남고서야 보였다.

```
Bash: node -e "console.log(1+1)"        ← 이것조차 거부됐다
Bash: node ../../.skill-src/.../orchestrate.mjs gate G2 --check
Bash: python -c '…'                     ← 이건 정상 거부
PowerShell: …                           ← 이것도 정상 거부
```

`node -e "console.log(1+1)"` 은 `Bash(node *)` 에 걸릴 이유가 없다. 원인은 실행기였다.

```js
nodeSpawn(command, args, { shell: process.platform === "win32" })
```

Windows 에서 `claude` 는 `.cmd` 셔임이라 셸 없이 못 띄운다. 그런데 `shell: true` 면
Node 는 인자를 **이스케이프 없이 이어붙인다.** Node 가 그렇게 경고까지 하고 있었다.

```
[DEP0190] Passing args to a child process with shell option true can lead to
security vulnerabilities, as the arguments are not escaped, only concatenated.
```

그래서 `--allowedTools Read,…,Bash(node *)` 가 cmd.exe 에서 **공백과 괄호로 쪼개졌고**
자식은 깨진 허용 목록을 받았다. 결과적으로 자식의 Bash 는 전부 막혔다.

### 고침

```js
export function shellQuote(arg) {
  const value = String(arg);
  return /^[A-Za-z0-9_.:\\/=-]+$/.test(value) ? value : `"${value.replace(/"/g, '\\"')}"`;
}
```

실측으로 확인했다.

```
고침 전  거부 1건  →  "Bash 실행이 권한 승인 대기로 막혀서 결과를 얻지 못했습니다"
고침 후  거부 0건  →  "2"
```

같은 모양이 `g11/run.mjs` 와 `init/lib/vendor.mjs` 에도 있으나 그쪽은 인자가 단순
토큰뿐이라 해당되지 않는다.

### 배운 것 — 자식의 자기 보고를 버리면 진단도 같이 버린다

우리 규칙은 "**자식의 자기 보고는 통과가 아니다**" 였다. 그건 맞다. 그런데 우리는
보고를 판정에서 뺀 김에 **기록에서도 뺐다.** 그래서 자식이 정확히 말한 고장을
두 회차 동안 흘려보냈다.

`claude -p --output-format json` 은 `permission_denials` 를 준다. 실행기가 그걸 버리고
있었다. 이제 `work/exec/<게이트>-<n>.json` 의 `child.denials` 에 남고, 있으면 한 줄로
출력한다. **판정은 안 믿되 증상은 남긴다.**

## 2. 받은 것과 읽은 것은 다른 일이다

도매꾹 상세는 **800×16820 한 장**으로 온다. 세션이 그대로 열면 95×2000 축소본이라
문자가 사라진다. G1 1회차가 하네스 프레임 두 구간(약 13%)만 읽고 규격·소재·구성을
전부 `unknowns` 로 내렸다.

수집은 성공했는데 **읽을 수단이 없었다.** 그래서 `capture` 가 자른다.

```
lib/tiles.mjs   상한 1600px · 겹침 100px · PNG 헤더에서 크기를 직접 읽는다
                새 의존성 없다 — 자르는 것은 이미 필수 런타임인 ffmpeg
```

기준작(쿠팡)은 추출기가 780×1080 단위로 이미 쪼개므로 아무 일도 일어나지 않는다.
dmk 번들은 같은 상세 원본을 **두 자리에 똑같이 담아서**(해시 동일) 중복 12장이
나왔다. 내용 해시로 걷어냈다.

### 효과

| --- | --- | --- |
| 타공 | 구멍 **1개** | 구멍 **2개** (사이즈 도면으로 확정) |

타공 개수가 틀렸던 것이 특히 크다. G6 이 그대로 컷을 그렸으면 **실물에 없는 제품**이
30장 나왔을 것이다.

## 3. 팩이 자식에게 못 쓰는 경로를 줬다

`## 끝내는 법` 이 이런 줄을 bash 블록으로 줬다.

```bash
node C:\Users\...\orchestrate.mjs gate G1 --check
```

세션의 Bash 는 Git Bash 다. 거기서 백슬래시는 **이스케이프**라 인자가 `C:Users…` 로
뭉개진다. 팩이 주는 경로는 전부 POSIX 로 바꾸고 따옴표로 감쌌다.

## 4. 판매자에게 물은 것

**옵션 개수가 자료마다 달랐다.** G1 이 혼자 정하지 않고 표로 남겼다.

| 위치 | 원문 |
| --- | --- |
| 도매꾹 상품명 | `20X10 20X25` → 2종 |
| 상세 옵션·사이즈 도면 | `10x20 / 20x25 / 20x30cm` → 3종 |

도매꾹 `옵션선택` 드롭다운이 접힌 채 캡처돼 자료만으로는 못 푼다.
**판매자 확인: 2종.** SSOT 에 근거를 "캡처"가 아니라 "판매자 확인"으로 적고
`20×30cm` 를 화면 문자 금지로 걸었다.

> 캡처가 못 푸는 것이 있다는 사실 자체는 결함이 아니다. **혼자 정하지 않은 것**이
> 3회차와의 차이다.

## 5. 고친 게이트가 같은 회차에 반영되지 않았다 — 부모의 ESM 캐시

G7 이 세 번 연속 같은 사유로 거부됐다. 그런데 **같은 파일을 새 프로세스로 검사하니
그냥 통과했다.** G7 세션이 3회차 요약에 원인을 정확히 적어 놓았다.

`runCheck` 는 단계 스킬의 `check.mjs` 를 `import()` 로 부른다. ESM 은 한 번 부른 모듈을
프로세스가 끝날 때까지 캐시하고, `run --exec` 는 게이트 12개를 도는 동안 **한 프로세스로
살아 있다.**

이 설계에는 우회 플래그가 없고 불변 규칙에 **"게이트가 틀렸으면 게이트를 고친다"** 가
있다. 그게 정상 경로인데 **그 경로가 같은 회차 안에서 막혀 있었다.** 고쳐도 안 읽히니까.

G7 세션이 캐시 무력화로 고치고 테스트를 붙였다.

```js
export async function loadCheck(entry) {
  loadCheck.reads += 1;
  return import(`${url}?read=${loadCheck.reads}`);
}
```

## 6. 예산은 만드는 자리에서 봐야 한다

G10 이 `미디어 총량 12.6 MB 가 상한 12 MB 를 넘는다` 로 거부했다. 그런데 총량의 84%가
GIF 이고 GIF 를 굽는 것은 G8 이다. **G10 은 스크립트 게이트라 스스로 줄이지 못한다.**

숫자를 새로 정하지 않고 G10 이 보는 정책값 하나를 G8 도 같이 보게 했다. 다시 돌리자
G8 세션이 팔레트를 192색·성긴 디더로 고쳐 **12.63 → 10.45MB**, 속도는 그대로 맞췄다.

### G11 이 스스로를 영원히 STALE 로 만든다

파일 시각이 그대로 말한다.

```
09:59:48  work/anchors.json          ← G9 가 조립하며 함께 쓴 것
11:02:30  output/detail-page.html    ← G11 세션이 고쳤다 (G11 시작 10:17)
11:38:40  work/qa-report.json        ← G10 재실행
```

`gates.mjs` 에서 `output/detail-page.html` 은 **G9 의 산출물이자 G10 의 입력**이고
G11 의 산출물은 `work/report.md` 뿐이다. 그런데 정본은 G11 이 그 파일을 고치는 것을
**허락한다.**

> 저장 성공 전 공개 `output/detail-page.html` 을 직접 덮어쓰지 않으며, 저장 뒤 같은
> 780px QA 를 다시 수행하고 통과본만 공개한다. — `references/studio.md`

그래서 고리가 닫힌다.

```
G11 이 HTML 을 고친다 → G10 상류 변경 → G10 STALE → G11 선행 무효 → G11 STALE
        ↑                                                              │
        └──────────────────  G10 을 다시 돌려도 같은 자리  ←────────────┘
```

**선언(gates.mjs)과 정본(studio.md)이 어긋나 있다.** 게이트 그래프는 G11 이 그 파일을
소유하지 않는다고 하고, 정본은 조건부로 소유한다고 한다.

고리가 **영원히** 도는 것은 아니다 — G11 이 두 번째 실행에서 HTML 을 다시 쓰지 않으면
(멱등하면) G10 이 그대로 유효해지고 끝난다. 다만 5회차에는 세 시도가 전부 타임아웃이라
그 멱등한 통과를 한 번도 보지 못했다. 그래서 사람이 `--pass` 를 눌렀다.

고칠 방향이 두 갈래인데 **어느 쪽인지는 제품 결정이다.**

1. Studio 의 수정을 플랜으로 되먹여 G9 이 다시 조립한다 — HTML 의 저자를 하나로 둔다
2. `gates.mjs` 가 G11 도 그 파일의 저자라고 선언한다 — 대신 G10 재실행이 회차마다 붙는다

지금은 **보이게만** 해 뒀다. 실행기가 남의 산출물 해시를 미리 찍어 두고 바뀌면
`child.trespass` 에 남긴다. 5회차에 두 번 있었는데 둘 다 `git status` 를 열기 전에는
아무도 몰랐다.

## 7. 회차가 끝나고 스킬에 반영한 것

| 무엇이 문제였나 | 어떻게 고쳤나 |
| --- | --- |
| 자식의 진단이 사라진다 | `child.denials`·`child.timed_out`·`child.trespass` 를 로그에 남기고, 있으면 화면에 한 줄 낸다. **판정은 안 믿되 증상은 남긴다** |
| 타임아웃이 통과와 같아 보인다 | 이제 `통과 · N초 · 다만 자식은 죽인 것이다. 산출물이 반쪽일 수 있다` 를 붙인다 |
| 밧줄이 게이트마다 같았다 | `execTimeoutMs = 예산 × 3` (바닥 10분 · 천장 30분). 예산의 세 배를 넘겼으면 프롬프트가 아니라 게이트를 볼 자리다 |
| 남의 산출물을 만져도 몰랐다 | 실행기가 다른 게이트 산출물의 해시를 미리 찍고 바뀌면 남긴다. **막지는 않는다** — 판정은 언제나 `check.mjs` 다 |
| 출처 없는 `완벽` 이 통과했다 | 아래 |
| 예산을 만드는 자리에서 안 봤다 | G8 이 G10 과 **같은 정책값**을 본다 (§6) |
| 고친 게이트가 반영되지 않았다 | `loadCheck` 가 부를 때마다 디스크의 현재 판을 읽는다 (§5) |

### `완벽` — 규칙 충돌이 아니라 목록의 구멍이었다

처음엔 두 정본이 충돌한다고 봤다. `sales-story.md` 는 "과장이어도 원문에 있으면 쓴다",
SSOT 는 "`완벽` 은 근거 없는 절대 표현이다". 그래서 절대 표현을 통째로 막는 검사를
새로 만들 뻔했다.

**그건 3회차의 실패를 되풀이하는 것이었다.** G3 검사에는 이미 두 목록이 있다.

```
NEVER           완치 · 치료           출처가 있어도 안 쓴다
UNLESS_SOURCED  100% · 1위 · 무조건   `## 소구점` 에 출처가 있을 때만 쓴다
```

3회차에 이 목록이 무조건 금지였고 그래서 **소구점이 하나도 없는 페이지**가 나왔다.
일부러 푼 것이고 테스트로 고정돼 있다.

진짜 결함은 훨씬 작았다 — **`완벽` 이 두 목록 어디에도 없었다.** 출처 없이 지어내도
통과하는 상태였다. SSOT 의 판정문이 이미 정확했다: "**근거 없는** 절대 표현".
근거를 요구하면 된다. `UNLESS_SOURCED` 에 넣었다.

5회차 발행본은 그대로 통과한다 — `완벽 포획` 은 기준작 `detail-001` 에서 왔고
flow-map 의 `## 소구점` 에 출처가 적혀 있다.

> 검사를 새로 만들기 전에 **있는 검사를 먼저 읽는다.** 4회차에 hyperframes 계약을
> 안 읽고 시작해 두 번 조용히 실패한 것과 같은 종류의 실수다.
