# 퇴화 진단과 개선 계획

`sm-의견.md` 의 리뷰를 코드와 산출물에서 하나씩 확인했다. 전부 사실이었다.
비교 대상은 사용자가 지목한 `bd6b3d0` — 단일 스킬 시절의 정본이다.

---

## 1. 무엇이 사라졌는가

`bd6b3d0` 은 275KB 의 **도메인 지식**이었다.

| 문서 | 내용 | 지금 |
| --- | --- | --- |
| `references/commercial.md` | CR-001~020. 판매 서사, 카피 규칙, **공개 금지 목록** | 없음 |
| `references/taste.md` | TR-001~030. 시각 품질 | 없음 |
| `references/motion.md` | MR-001~020. GIF 증거 규칙 | 없음 |
| `policies/detail-page-flow-v1.json` | 결정적 흐름 검증 (pain 3~5, solution 1:1) | 없음 |
| `references/coupang-wing-detail-780.html` | 공통 visual ambition anchor | 없음 |
| `examples/해충-끈끈이-v4.html` | 완성 기준작 (같은 상품) | 없음 |
| `references/studio.md` + runtime 200KB | 사용자가 직접 고치는 편집 UI | 문서만 남고 G11 에 갇힘 |

지금의 12게이트는 **절차**만 남았다. 각 게이트의 "이 게이트가 없으면 무엇이 조용히

한 줄도 없다.

그래서 모든 검사가 "단계를 했는가"를 묻고 "결과가 좋은가"를 묻지 않는다.

### 기준작이 무엇을 하고 있었나

`bd6b3d0` 의 v4 (같은 상품) 를 실측했다.

```
헤드라인 66px / 서브 27px / eyebrow 22px
팔레트   #ffdf00 · #f12626 · #0c0d0f   (고채도 주색 + 경고색 + 근검정)
구조     13섹션. 이미지 위 텍스트 오버레이 4곳, 풀블리드 700~1040px 6곳
장치     회전 배지, 원형 benefit, stat strip, two-up 전후, 116px 대형 숫자
카피     "강력 점착" "생활방수" "50장 대용량" — 공급처 표현을 그대로 씀
고지     푸터에 ※ 한 줄. 본문에는 없음
```

현재 산출물:

```
헤드라인 60px  (근접)
팔레트   #7AA328 세이지 그린 + 흰색     ← 저채도. 포트폴리오 톤
구조     8섹션. 전부 `padding:104px 60px; text-align:center` 흰 박스에 이미지 아래 배치
         오버레이 0곳, 풀블리드 0곳
장치     없음
카피     "모르는 것은 모른다고 적었습니다"
고지     본문 섹션마다 `.trace` 각주
```

**차이는 취향이 아니라 구조다.** 지금 것은 텍스트를 이미지 위에 올릴 수 있는
CSS 가 아예 없다.

## 3. 원칙

1. **품질은 "단계 수행 여부"가 아니라 "기준작 대비"로 측정한다.**
   기준작 2개를 스킬 안에 두고, 실측 지표를 게이트가 검사한다.
2. **자산은 이미지가 먼저다.** 스틸 → GIF 로 흐른다. 도형으로 시작하지 않는다.
3. **공급처가 말한 것은 쓴다.** 다만 우리가 지어내지 않는다. 고지는 푸터 1줄.
4. **고객 화면에 제작 과정을 쓰지 않는다.** 결정적 금지어 검사로 막는다.
5. **막다른 길을 만들지 않는다.** 게이트가 요구하는 상태로 되돌아갈 경로를 함께 만든다.

## 4. 변경 계획

### P1 · 기준작을 스킬에 넣는다

- `orchestrator/references/benchmark/v4-reference.html` (base64 제거, 16KB)
- `orchestrator/references/benchmark/coupang-wing-780.html` (52KB)
- `orchestrator/references/benchmark/BENCHMARK.md` — 실측 지표표
- `lib/benchmark.mjs` — HTML 에서 지표를 뽑는 결정적 함수
- G9 check 가 이 지표를 검사: 헤드라인 ≥44px, 오버레이 섹션 ≥3, 풀블리드 ≥4,
  주색 채도 하한, 섹션 ≥10

### P2 · 카피 위생 + 서사 계약

- `lib/copy.mjs` — 제작자 언어 금지 패턴. G3(플랜)과 G9(HTML) 양쪽 검사
- `flow-plan` 스키마: `sections[].role`, `pains[]`, `solutions[]`
- G3 check: role 커버리지 + pain↔solution 1:1 + 순서
- SSOT 에 `manufacturer_claim` 절 신설. 페이지 푸터 고지 자동 생성

### P3 · 이미지 일관성

- G6 2단계: `--base` 로 hero 1장 → 나머지가 `references[0]` 로 받음
- 프롬프트에 문자·로고·브랜드 금지 블록 자동 주입
- `--regen` 으로 탈락분만 재생성 (막다른 길 #11 해소)
- `detail-page-init` 에 god-tibo 1장 스모크 테스트

### P4 · GIF 입력을 이미지로

- `method` 를 2개로: `still-motion` / `tibo-sequence`
- `brief.source_still` 필수. selection 에서 accept 된 컷이어야 함
- G8 check: 컴포지션 HTML 에 그 스틸 경로가 실제로 있는가
- `--scaffold` 로 템플릿에서 컴포지션 생성 (손작업 제거 → 시간)

### P5 · 왕복과 막다른 길 제거

- G4 에 god-tibo 실행 경로 추가
- G4+G5 병합 (STALE 왕복 제거)
- G1/G2 입력 잠금 분리
- G10 수량 하한을 플랜 대비로

### P6 · 검증

- 테스트 전량
