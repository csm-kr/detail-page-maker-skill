### 2. 조립기를 다시 썼다 — 여기가 퇴화의 실체였다

옛 `render.mjs` 는 **모든 섹션을 같은 흰 박스로 찍었다.** `padding:32px 24px` 에
`.infocard` 하나, 이미지는 글 아래. 텍스트를 이미지 위에 올릴 CSS 가 아예 없었다.

이제 `section.role` 이 레이아웃을 고른다. v4 의 구조를 옮겼다.

| role | 레이아웃 |
| --- | --- |
| `hero` `closing` | 풀블리드 이미지 + 셰이드 + 상/하단 오버레이 (+ CTA) |
| `pain` | 어두운 카피 판 + 풀블리드 미디어 |
| `solution` | 배경을 `dark → tint → brand` 로 돌려 가며 카피 + 미디어 |
| `compare` | 좌우 two-up + 태그 |
| `usage` | 카피 + 미디어 + 단계 그리드 |
| `spec` `caution` | 규격표 / 주의 목록 |

같이 고친 것:

- **푸터에 `contract_id` 와 공급처 URL 이 실려 있었다.** 지웠다. 푸터는 `footer_notice` 한 줄
- **`src` 가 `output/media/…` 였다.** HTML 이 `output/` 안에 있으므로 G10 이 전부
  `ASSET_MISSING` 으로 봤을 경로다. `media/…` 로 고쳤다
- **조립기는 `headline_lines`, 판정기는 `headline` 을 봤다.** 둘이 갈려 있어서 조립기를
  쓰지 못하고 사람이 HTML 을 손으로 만들었고, 판정기는 그것을 통과시켰다. 플랜 어휘로 통일
- **탈락한 컷까지 페이지에 실렸다.** 플랜은 선별 결과를 모른다. `accepted` 를 받게 했다
- **GIF 가 있는 섹션에서 스틸이 버려졌다.** 굽고 버린 것이다. 둘 다 싣는다

### 3. 제작자 언어를 화면에서 막았다

1회차에 본문으로 나간 문장들이다.

```
모르는 것은 모른다고 적었습니다
*유인 파장, 무독성은 공급처 표기가 없어 적지 않습니다
*두 표기가 서로 달라 양쪽을 그대로 옮깁니다
```

`scripts/lib/copy.mjs` 가 결정적으로 잡는다. **G3(플랜)과 G9(HTML) 양쪽**에서 본다 —
플랜에서 잡으면 빌드까지 가지 않는다. 기준작 v4 의 본문은 한 건도 걸리지 않는다.

`.trace` 클래스도 없앴다. 섹션마다 출처 각주를 다는 구조가 이것을 실어 냈다.

### 4. 판매 서사를 계약으로 되살렸다

`scripts/lib/story.mjs` + `references/sales-story.md`.
`hero` 가 처음, `pain` 이 첫 `solution` 보다 앞, `solution` 3개 이상, `closing` 이 마지막.

옛 정본은 "불편 3~5개를 인용 말풍선으로" 까지 요구했지만 **v4 는 그렇게 하지 않고도

공급처·쿠팡의 표현은 쓴다. `manufacturer_claim` 을 SSOT 1급 분류로 두고 고지는 푸터 한 줄.

### 5. 이미지 일관성 — 기준 컷

1회차에 `items[].references` 가 **30개 전부 비어 있었다.** 컷마다 따로 생성돼 같은
제품으로 보이지 않았고, 30장 중 18장이 탈락했다.

```
run.mjs --base     기준 컷 한 장. 나머지 전부의 canonical base
run.mjs            나머지. 기준 컷을 references[0] 로 받는다
run.mjs --regen    탈락한 컷만. 채택분은 건드리지 않는다
run.mjs --publish  채택분만 780px 발행
```

프롬프트에 문자·로고·브랜드 금지가 **자동으로** 붙는다 (`lib/prompt.mjs`).
PUREHABIT·LeafShield·NON-TOXIC 이 구워진 직접 원인이었다.

### 6. GIF 의 입력을 이미지로 바꿨다

1회차 컴포지션 **10개 전부 `<img>` 가 0건**이었다. CSS 사각형에 애니메이션을 걸었다.

수단을 둘로 좁혔고 둘 다 발행된 스틸에서 시작한다.

| 수단 | 무엇이 움직이나 |
| --- | --- |
| `still-motion` | 제품은 고정, 설명이 움직인다 (reveal / zoom / sequence / measure) |
| `tibo-sequence` | 스틸을 레퍼런스로 다음 장면을 생성해 이어 붙인다 |

두 번째는 god-tibo 가 **이미 갖고 있던 경로**다 (`prompts` + `references` + `gif`).
스킬이 한 번도 부르지 않았을 뿐이다. 딱붙 회차에서 실제로 돌려 확인했다.

- `brief.source_still` 필수. 채택된 컷이어야 한다
- G8 이 컴포지션 HTML 을 열어 그 스틸을 실제로 쓰는지 본다
- `--scaffold` 가 컴포지션을 만든다. 손으로 처음부터 쓰지 않는다
- 두 수단을 모두 써야 한다 (G3 검사)

### 7. G4 에 실행 경로를 만들었다

`run.mjs` 가 **체크리스트만 출력하고 끝났다.** 사람이 ChatGPT 대화로 가야 했고
23분 예산의 게이트가 가장 오래 걸렸다. 바로 옆 god-tibo 를 아무도 부르지 않았다.

`run.mjs --generate` 가 `templates.md` 의 12개 블록을 전량 조립해 섹션마다 프롬프트를
만들고, 무드 레퍼런스를 붙여 목업을 받고, 섹션↔파일 1:1 색인을 쓴다.
조립을 스크립트가 하면 블록을 빠뜨릴 방법이 없다.

### 8. 세팅 때 이미지 생성을 확인한다

`init` 이 인증 파일의 **존재**만 봤다. 이미지가 나오는지는 G6 에서 30장을 요청하고
나서야 알 수 있었다. 이제 한 장을 실제로 만들어 보고, 실패하면 `ready: false` 다.

### 9. 막다른 길을 없앴다

`lean-html-qa.mjs` 가 이미지 **28~32장**을 요구했다. 엄격한 선별이 12장만 채택했을 때
통과할 방법이 없었다 — **선별을 잘할수록 막히는 검사**였다.

임의의 범위를 없애고 **계획 대비**로 본다. G10 이 `selection.json` 의 채택 수와
`comps/index.json` 의 brief 수를 읽어 넘긴다.
