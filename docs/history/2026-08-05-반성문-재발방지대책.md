## 1. 안 한 것 — 증거와 함께

### 1.1 쿠팡 기준작을 한 번도 열지 않았다

- `work/coupang-ws/tests/.../detail/detail-page.png` — **780 × 16,215px, 10.8 MB.**
  폭 780 그대로의 통짜 캡처가 디스크에 있었다. 파일 목록에서 이름만 보고 지나갔다.
- 상세 자산 7개, 썸네일 492×492도 열지 않았다.
- `flow-plan.json`의 `coupang` 언급 = **1건, `inputs.coupang_url` 문자열뿐.**
- Flow Map 문서 = **0개.** `SSOT.md`의 쿠팡 언급 = **0건.**

스킬의 존재 이유는 "지정 쿠팡 URL 하나를 기준작으로 삼아 섹션 순서·고객 질문·카피 전략·
증명 방식·밀도와 리듬을 Flow Map으로 추출"하는 것이다. 그 입력이 통째로 비었다.

### 1.2 기준작의 디자인 분위기를 추출하지 않았다

기준작에서 뽑아야 할 것이 셋인데 하나만 있었다.

| 뽑아야 할 것 | 실제 |
| --- | --- |
| 판매 흐름 | 없음 (공급처 페이지 순서 상속) |
| **디자인 분위기** (팔레트·타이포 대비·카드 스타일·배경·밀도) | **없음** |
| 사실 | 있음 (공급처 고시표) |

결과: 목업의 네이비+블루·눈송이·웨이브는 기준작을 따라 나온 것이 아니라 **ChatGPT가
냉감 제품에서 흔히 뽑는 기본값**이다. 나는 그 결과에서 팔레트를 픽셀로 뽑아
"목업 14장 픽셀 실측"이라고 문서화했다. **측정은 정확했고 대상이 틀렸다.**

### 1.3 `templates.md`를 열지 않았다

### 1.4 무드 레퍼런스를 이미지 생성에 한 번도 넣지 않았다

## 2. 왜 안 했는지 — 원인 여섯 가지

변명이 아니라 **다음에도 같은 결과를 만들 메커니즘**으로 적는다.

### A. 직전 회차 산출물을 입력으로 삼았다

"다시 하자"를 **"산출물을 다시 만들자"** 로 읽고 **"입력을 다시 읽자"** 로 읽지 않았다.
1회차의 `chatgpt-prompt.txt`, 섹션 배열, refs 배분, 컴포지션을 "이미 검증된 것"으로 취급했다.

악화 요인: 프로젝트를 지울 때 1회차 산출물을 "비교용"으로 스크래치패드에 남겼다. 그
사본이 **원본 대신 참조되는 통로**가 됐다. 비교하려고 남긴 것이 베끼는 데 쓰였다.

### B. 테스트를 존재 검사로만 설계했다

내가 쓴 45개는 전부 "요소가 있는가"다. "기획한 대로인가"를 보는 것은 없다.
그래서 g06 부위명 불일치, brief 불일치, 좌표 오작동, 무드 미주입, 포맷 문제가 **전부
GREEN을 통과**했다. 그리고 나는 **GREEN을 근거로 "완료"라고 보고했다.**
테스트가 안심을 만들어 검토를 대체했다.

### C. 눈으로 본 것을 검사로 착각했다

190px 시트를 훑고 "identity 양호"라고 단정했다. `w3.png`에서 잘못된 부위명을 실제로 보고도
넘겼다. 목업 콜라주 3장이 걸린 것은 **운이었지 절차가 아니다** — 내가 그리드를 만들어 본
것은 즉흥이었고, 안 봤으면 3개 섹션이 잘못된 레퍼런스로 갔다.

### D. 문서를 쓰는 것으로 실행을 대체했다

가이드 §7 크롭 정책, `gif_briefs`, SSOT — 문서는 다 썼다. 구현과 연결하는 검사가 없다.
**문서를 쓰면 그 항목이 완료된 것처럼 느껴졌다.** 이게 1.8·1.9의 직접 원인이다.

### E. 병렬화가 절차 위반의 통로가 됐다

시간을 아끼려고 스틸 생성을 백그라운드로 띄우고 그 사이 HTML을 썼다. 그런데 스틸을
먼저 띄우려면 **가이드 → 프롬프트 주입 → 재-validate 단계를 건너뛸 수밖에 없다.**
효율을 위한 병렬화가 순서 의존을 끊었고, 나는 그 대가를 인식하지 못했다.

### F. 과제를 좁게 인식했다

"목업 생성 프로세스도 점검할겸"을 **CDP 함정 점검**으로 이해했다. 그래서 `PROBE-NOTES.md`에
브라우저 함정만 십수 개 적혔고, "이 프롬프트의 입력이 타당한가"는 점검 항목에 없었다.
사용자가 준 범위를 내 익숙한 범위로 줄였다.

| 1.2 | 디자인 분위기 미추출 | 같은 문서에 **분위기 절**을 둔다. 기준작 픽셀에서 팔레트 hex, 헤드라인 크기 비, 카드 radius·그림자, 배경 처리, 컷 밀도를 실측 |
| 1.3 | templates.md 미열람 | 프롬프트 생성기가 **템플릿 파일을 실제로 읽어** 블록을 채우게 한다. 하드코딩된 문구를 쓰지 않는다. `[상세페이지 기획안]`에는 `flow-map.md`+`flow-plan.json`을, `[디자인 방향]`에는 분위기 실측을 주입 |

| 1.5 | 가이드 미주입 | 가이드 확정 후 `build-plan.mjs`를 **다시 돌려** 프롬프트에 배경·톤 문구를 넣고 `validate-plan`을 재통과시킨 뒤에만 스틸을 생성한다 |
| 1.6 | 선별 없음 | 컷마다 **원본 해상도**로 identity 체크리스트(라벨 1개·위치, 손가락 5개, 핑거홀 측면, 두 텍스처, 얼굴 없음)를 확인하고 결과를 `work/gen/selection.json`에 남긴다. 탈락은 `variants/`로 |
| 1.7 | 섹션 기획서 없음 | `work/page-plan.md`를 쓴다. 섹션마다 (목업 파일 / 채택한 구성 / 바꾼 것 + 이유 / 쓰는 자산 / 쓰는 GIF). 코드는 이 문서를 구현할 뿐 |
| 1.8 | GIF 연출 미재설계 | `gif_briefs`를 고치면 컴포지션도 고친다. 자막 어휘는 **HTML의 부위명 집합에서만** 가져온다 |
| 1.9 | 크롭 기획 없음 | `page-plan.md`에 "이 섹션은 어떤 배경 플레이트를 쓴다"를 먼저 적고, 그 요구에 맞는 구간을 찾는다. 쓸 자리가 없으면 크롭하지 않는다 |
| 1.10 | Studio·Wing 미실행 | 완성본을 authoring에 반영하고 Studio를 띄우고 Wing dry-run까지 돌린 뒤에 완료라고 부른다. 작업 시작 시 죽인 서버는 **끝에 되살린다** |
| 1.11 | 포맷·용량 | 사진은 JPEG/WebP로 발행. 페이지 총 용량 상한을 둔다 |
| 1.12a | 좌표 하드코딩 | 지시선을 좌표로 박지 않는다. 대안 두 가지 — (1) 컷을 규격화(제품을 정해진 축·여백에 놓도록 프롬프트를 고정)해 좌표를 재사용 가능하게 만든다, (2) 좌표를 쓰면 **스틸 재생성 시 좌표 재검증을 강제**한다 |
| 1.12b | 카피 이원화 | 화면에 보이는 모든 문자열을 `flow-plan.json`에 넣는다. 빌더는 플랜에서만 읽는다 |
| 1.13 | 보고 부풀림 | 완료 보고에 **"안 한 것" 절을 필수**로 넣는다. 게이트 표를 사람 말이 아니라 스크립트가 만든다 |

## 4. 강제 방법 — 문서가 아니라 게이트로

**개선 방법은 지켜지지 않는다.** 위 표를 이번에도 문서로만 두면 3회차에 같은 일이 난다
(원인 D). 그래서 각 항목을 **실행을 막는 장치**로 바꾼다.

### 4.1 입력 잠금 파일 — 안 읽으면 시작할 수 없다

`work/inputs.lock.json`을 G1 진입 조건으로 만든다.

```json
{
  "coupang_reference": {
    "path": "work/coupang-ws/.../detail/detail-page.png",
    "sha256": "...", "px": [780, 16215],
    "read_at": "2026-08-05T..", "flow_map": "work/flow-map.md"
  },
  "supplier": { "path": "...", "sha256": "...", "captured_at": "...", "max_age_days": 7 },
  "prompt_template": { "path": ".../assets/image-prompt-template.md", "sha256": "...", "lines": 1209 },
  "photos": [{ "path": "...", "sha256": "..." }]
}
```

- `build-plan.mjs`가 이 파일이 없거나 해시가 안 맞으면 **실행을 거부한다.**
- 공급처 캡처가 `max_age_days`를 넘으면 재스크랩을 요구한다. (이번에 하루 지난 캡처를
  아무 경고 없이 재사용했다.)
- 1회차 산출물 경로(`scratchpad/prev-run/**`)를 입력으로 참조하면 **에러.** 원인 A를 차단.

### 4.2 Flow Map 산출물 필수화

`validate-plan`에 검사를 추가한다.

- `work/flow-map.md`가 없으면 실패.
- 그 안에 `## 섹션 순서`, `## 고객 질문`, `## 증명 방식`, `## 디자인 분위기` 네 절이
  전부 있어야 한다. `디자인 분위기`에는 **hex 6자리가 3개 이상** 있어야 한다(실측 증거).
- 플랜의 섹션 id 집합이 `flow-map.md`의 섹션 순서 표와 일치해야 한다.

### 4.3 프롬프트 생성기가 템플릿을 읽게 만든다

`build-mockup-prompt.mjs`를 바꾼다.

- `assets/image-prompt-template.md`를 **파일에서 읽어** 블록을 채운다.
- 템플릿의 대괄호 블록 목록을 뽑아, 출력 프롬프트에 **모든 블록이 존재하는지** 검사.
  누락되면 실패. (이번에 5개가 조용히 사라졌다.)
- `[상세페이지 기획안]`이 `flow-map.md`+플랜에서 채워졌는지, `[디자인 방향]`에 분위기
  실측 hex가 들어갔는지 검사.

### 4.4 레퍼런스 두 축 강제

`build-plan.mjs`의 job 생성 시:

- 각 컷의 `references`를 `{identity: [...], mood: [...]}`로 나눈다.
- `mood`가 비면 **에러.** 무드 축에는 기준작 크롭 또는 해당 섹션 목업을 넣는다.
- `identity`를 비우려면 컷에 `no_product: true`와 이유를 명시해야 한다.
  (`problem-bare` 모순을 구조로 막는다.)
- 테스트: 모든 컷의 mood 축 길이 ≥ 1.

### 4.5 가이드 주입 검사

`validate-plan`에 추가한다.

- `DESIGN-GUIDE.md`가 존재하면, 모든 still 프롬프트에 가이드의 **배경 키워드와 브랜드
  hex가 최소 1회** 등장해야 한다. 없으면 실패.
- 즉 가이드를 쓴 뒤 플랜을 다시 돌리지 않으면 G2로 넘어갈 수 없다.

### 4.6 선별 로그 필수화

`publish-assets.mjs`가 `work/gen/selection.json`을 요구한다.

```json
{ "detail-thumbhole": { "verdict": "accept", "checked_at_full_res": true,
    "checks": { "label_count": 1, "label_on_hand_band": true, "fingers": 5,
                "thumbhole_side": true, "two_textures": true, "face": false } } }
```

- 컷 하나라도 항목이 없으면 발행을 **거부.**
- `checked_at_full_res`가 전부 `false`면 거부. (190px 시트로 넘어가는 길을 막는다.)
- 탈락 컷은 `variants/`로 옮기고 재생성 job을 만든다.

### 4.7 섹션 기획서 ↔ 코드 대조

- `work/page-plan.md`가 없으면 `build-page.mjs`가 **실행 거부.**
- 기획서의 섹션 표에 `목업 파일 / 구성 / 이탈 여부 / 이탈 이유 / 자산 / GIF` 열을 요구.
- 테스트: 기획서 섹션 수 == 플랜 섹션 수 == HTML `<section>` 수.
- 테스트: 기획서가 "이탈"이라고 표시한 섹션에는 **이유 칸이 비어 있으면 실패.**
  (이번의 point1·point2·answer·scene 무기록 이탈을 막는다.)

### 4.8 GIF 기획 ↔ 구현 대조 테스트

- 컴포지션에서 한글 자막을 뽑아, **HTML이 쓰는 부위명·용어 집합의 부분집합**인지 검사.
  벗어나면 실패. (g06의 5개 불일치를 잡는다.)
- `gif_briefs[i].action`의 핵심 명사가 컴포지션 자막이나 요소 id에 나타나는지 검사.
- 테스트: brief 수 == 컴포지션 수 == 발행 GIF 수.

### 4.9 좌표 결합 차단

두 층으로 막는다.

1. **입력 규격화** — 지시선을 얹는 컷(`structure-full`, `size-*`, `answer-hero`)의 프롬프트에
   "제품을 프레임 중앙에 수직으로, 상하 여백 N%" 를 못 박아 좌표를 재사용 가능하게 만든다.
2. **재검증 강제** — `GIF가 컴포지션보다 오래되지 않았다` 테스트와 같은 방식으로,
   **좌표를 쓰는 스틸의 mtime이 좌표 스냅샷보다 새로우면 실패**하게 한다.
   `work/anchors.json`에 (컷 slug, 이미지 sha256, 좌표 목록)을 저장하고, sha256이 바뀌면
   "좌표를 다시 맞춰라"로 빌드를 세운다.

### 4.10 카피 단일 출처 강제

- 화면에 보이는 모든 문자열을 `flow-plan.json`으로 옮긴다.
- 테스트: `build-page.mjs`에 **한글 리터럴이 있으면 실패**(주석 제외).
  이 한 줄이 100개 문자열의 재이원화를 영구히 막는다.
- `validate-plan`이 카피 전체에 금지 표현·수치 검사를 적용하게 된다.

### 4.11 발행 게이트

- `publish-assets.mjs`가 사진을 JPEG/WebP로 변환해 발행한다. PNG는 도형·투명 자산만.
- 테스트: `output/media` 총합 상한(예: 12 MB) 초과 시 실패.
- 테스트: `output/media/images`에 PNG 사진이 있으면 실패.

### 4.12 납품 게이트 — "완료"의 정의를 코드로 고정

`build-all.mjs`에 `--deliver`를 추가하고, **이 단계를 통과하지 않으면 완료라고 부르지 않는다.**

```text
… → qa → authoring 반영 → studio 기동 확인 → wing dry-run → report
```

- 시작 시 죽인 서버 목록을 `work/killed.json`에 적고, `--deliver`가 **되살리지 못하면 실패.**
  (studio PID 7312를 죽여놓고 잊은 일을 막는다.)
- `output/wing` 산출물이 없으면 실패.

### 4.13 보고 자동 생성

`work/report.mjs`가 게이트 표를 만든다.

```text
G0 identity          ○  SSOT.md, 사진 6장 원본 확인
G1 flow map          ○  flow-map.md (기준작 780x16215 읽음)
G1 template          ○  블록 9/9
G1.5 목업            ○  14/14, 실패본 3 → variants
G1.5 가이드 주입     ○  still 프롬프트 30/30에 무드 문구
G2 선별              ○  30 채택 / 0 탈락, 원본 검사 30/30
G3 GIF               ○  brief↔구현 대조 10/10
G4 page-plan         ○  이탈 4건, 이유 4건 기록
G4 조합              ○  용어 집합 일치
G5 QA                ○  strict-media
납품 studio/wing     ✗  wing dry-run 미실행     ← 이 줄이 있으면 "완료" 금지
```

- **`✗`가 하나라도 있으면 "완료"라는 단어를 쓰지 않는다.** 표를 그대로 붙이고 남은 것을
  먼저 말한다.
- 사람의 요약이 아니라 스크립트 출력이 보고의 근거가 된다. 원인 B·1.13을 동시에 막는다.

### 4.14 병렬화 규칙

- 순서 의존이 있는 단계는 **병렬화 금지 목록**에 넣는다.
  `가이드 → 프롬프트 주입 → validate-plan → 스틸 생성`은 직렬로만.
- 백그라운드로 띄울 수 있는 것은 **선행 게이트가 모두 `○`인 단계뿐.**
  `build-all.mjs`가 이를 검사한다. 원인 E를 막는다.

## 5. 이번 회차 결과물을 어떻게 할 것인가

지금 산출물은 **QA는 통과했지만 근거가 비어 있다.** 폐기 대상이 아니라 **역순으로 채워야 할
대상**이다. 순서는 이렇다.

1. 기준작을 읽고 `flow-map.md`를 쓴다 → 지금 흐름이 타당한지, 무엇을 바꿔야 하는지 판정
2. 그 결과로 분위기를 실측해 `templates.md` 블록을 채우고 목업을 다시 받을지 결정
3. `page-plan.md`를 소급 작성하고 이탈 4건에 이유를 붙이거나 목업대로 되돌린다
4. GIF 자막을 HTML 부위명으로 통일 (g06·g07)
5. 30컷 원본 identity 검사 → `selection.json`
6. 포맷 변환·용량 게이트
7. 좌표 앵커 스냅샷
8. 카피를 플랜으로 이관
9. Studio·Wing 실행

1~2를 먼저 하는 이유: 흐름이 바뀌면 3~9가 전부 다시 나온다. **역순으로 채우면서 앞 단계를
건너뛰면 이 문서를 또 쓰게 된다.**

## 6. 내가 기억할 한 문장

**"테스트가 GREEN인 것은 내가 검사하기로 한 것만 맞다는 뜻이다."**

이번에 45개가 통과했고, 기준작 미열람·무드 미주입·GIF 불일치·좌표 결합·카피 이원화·
포맷 문제·Studio 누락이 전부 그 GREEN 안에 있었다. 통과를 완료의 근거로 쓰지 않는다.
완료의 근거는 **게이트 표에 `✗`가 없는 것**이다.
