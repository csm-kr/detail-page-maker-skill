# 헤드리스 실행기와 렌더 예산

> 이것도 execute.py 로 강제하자. hyperframes 가 240 말고 그 내에 잘 수행되게 하는
> 그런 테스트를 해서 그걸 잘 전달하게 하는 거 어때? 이걸로 전체 스킬 업데이트 해보는 거.
> 되면 헤드리스로 전체 스킬을 잘 수행하도록 문서 전달 잘 되게 하는 걸로 하자.

[ADR-0012](../adr/0012-게이트를-헤드리스-세션으로-실행한다.md) 를 검토에서 채택으로
옮기고 구현했다. 테스트 **376 → 411 통과.** 전부 실패를 먼저 보고 고쳤다.

---

## 1. 우리에게 없던 것은 실행기 하나였다

harness-framework 와 대조해 보면 이미 갖고 있던 것이 대부분이었다.

| harness | 우리 것 |
| --- | --- |
| `step{N}.md` 지시서 | 게이트별 `SKILL.md` |
| step 의 AC | `check.mjs` — **우리 게 더 강하다** |
| `index.json` 상태 | `gates.json` + 해시 사슬 — **우리 게 더 강하다** |
| `execute.py` 실행기 | **없었다** ← 이것만 |

그래서 프레임워크를 설치하지 않았다. `/harness:init` 이 PRD·RULES·phases 를 주입하는데
우리에겐 이미 다 있고 순서는 `gates.mjs` 가 소유한다(ADR-0001). **정본이 둘이 되는 것이
이 프로젝트가 방금 당한 실패다.**

가져온 것은 200줄짜리 실행 모델이다.

```
orchestrate gate G3 --exec
  ├─ 컨텍스트 팩            lib/contextpack.mjs
  ├─ claude -p (새 세션 · stdin · 30분)
  ├─ work/exec/G3-<n>.json + <n>.prompt.md
  ├─ check.mjs 를 **부모가 다시 돌린다**
  └─ 통과 → 기록 · 실패 → 사유를 넣어 재시도 (최대 3회)
```

### 가져오지 않은 것

harness 는 **자식이 `index.json` 에 "completed" 를 쓰면 그게 통과**다.
우리는 그 패턴을 이미 거부했고, 헤드리스로 가면서 낮추지 않았다.

```js
// lib/exec.mjs — 자식이 무엇을 보고했든 부모가 다시 판정한다
const verdict = await check(attempt);
```

테스트가 이것을 고정한다.

```js
test("자식이 끝났다고 해도 부모가 check 를 다시 돌린다", …)
```

3회차의 `origin: "self-rendered"` 는 자식이 "했다" 고 보고한 상태였다.
사람이 자식을 안 보게 되는 순간, 자기 보고를 믿는 것은 검사를 없애는 것과 같다.

## 2. 컨텍스트를 통째로 붓지 않는다

harness 의 `_load_guardrails()` 는 `CLAUDE.md` + `docs/**/*.md` 를 전부 넣는다.
그대로 하면 게이트마다 147KB 를 읽고, 그건 **"컨텍스트가 너무 많아서 잘 못한다" 를
12번 반복하는 것**이다.

무엇을 어떻게 넘기는지 갈랐다.

| 무엇 | 어떻게 | 왜 |
| --- | --- | --- |
| 지시서 | SKILL.md **본문** | 그 게이트가 할 일 자체다 |
| 정본 | `reads` **본문** | 읽히지 않아서 어긋난 것이 3회차의 실패다 |
| 입력 | **경로만** | 플랜 하나가 정본 전체보다 크다 |
| 앞 게이트 | **한 줄 요약** | 대화 맥락을 넘기면 분리가 무의미해진다 |
| 판정 | 지금 부족한 것 | 무엇으로 판정되는지 모르고 시작하면 다 하고 나서 거부당한다 |

실측 — 전량 147,013B, 상한 49,004B (1/3).

```
G1   9,984B  7%    G2  14,714B 10%    G3  30,402B 21%
G4  23,857B 16%    G5  19,853B 14%    G6  17,794B 12%
G7  15,879B 11%    G8   6,279B  4%    G11  9,441B  6%
```

상한은 사람이 고르지 않는다. `canonBytes() / 3` 으로 유도하고 게이트마다 확인한다 —
[하한을 손으로 골랐던 것](2026-08-06-화려함-속도-소구점.md)이 화려함이 빠진 직접
원인이었다. 같은 실수를 상한에서 반복하지 않는다.

### 상한이 실제로 잡았다

G4 가 처음에 이 기준을 넘었다. `templates.md`(26KB) 를 정본에 넣었기 때문이다.
그런데 그 파일은 `assemblePrompt()` 가 프로그램적으로 읽는다 — **코드의 입력이지
판단의 근거가 아니다.** 빼자 16% 가 됐다.

### `reads` 는 한 곳에만 있다

`run.mjs` 의 `reading:` 을 승격하려 했는데 두 문제가 있었다.

- `checklist()` 를 안 부르는 게이트(G5·G6·G8·G11)는 선언할 자리가 없다
- 목록이 두 벌이면 **사람이 보는 것과 세션이 받는 것이 달라진다**

그래서 `gates.mjs` 의 `reads` 하나가 소유하고, `checklist()` 의 `reading:` 인자를 없앴다.
`purity.test.mjs` 가 두 가지를 본다 — 선언한 정본이 실제로 있는가, run.mjs 가 따로
적고 있지 않은가.

옮기면서 4개 게이트가 정본을 처음 갖게 됐다.

| 게이트 | 새 정본 |
| --- | --- |
| G2 | `sales-story.md` — 소구점 계약을 여기서 읽는다 |
| G5 | `art-direction.md` |
| G6 | `assets.md` |
| G8 | `render-path.md` (새로 씀) |

## 3. 240초의 정체

3회차에 hyperframes CLI 가 240초에 타임아웃했다. Chrome 스크린샷으로 갈아탔고,
**그 뒤로 다시 시도하지 않았다.** 의존성은 계속 벤더링돼 있었고(3.3MB · 파일 259개)
문서는 계속 hyperframes 를 가리켰다.

재 봤다.

```
hyperframes --help     0.53초
hyperframes doctor     7.3초
  ✓ Chrome   cache: ~/.cache/hyperframes/chrome/chrome-headless-shell/win64-…/
  ✓ FFmpeg   ffmpeg 8.1.2
chrome 1프레임 780×520  0.9초
```

**CLI 는 살아 있다.** 240초는 렌더가 느린 것이 아니라 `@puppeteer/browsers` 가 첫
실행에서 Chrome 을 내려받은 시간이었다. 한 번의 실패가 경로를 죽은 것으로 만들었고,
아무도 다시 재지 않아서 우회가 굳었다.

같이 찾은 것 — CLI 에 우리가 필요한 것이 이미 있다.

```
hyperframes snapshot --output <dir> --frames <N> --at <초,…>
  Capture key frames as PNG screenshots
```

MP4 가 아니라 **PNG 시퀀스**다. 그대로 `gifasm.mjs` 에 넣을 수 있다 — 속도 제어는
우리가 소유하므로 조립기를 안 바꿔도 된다.

### 고친 방식이 중요하다

"이번엔 hyperframes 를 쓰자" 가 아니라 **재는 것을 게이트로** 만들었다.

```bash
node scripts/run.mjs --probe
```

`work/comps/render-probe.json` 에 경로마다 실측이 남는다. 없거나, 하루가 지났거나,
살아 있는 경로가 하나도 없으면 G8 이 거부한다. 예산은 그때 그 값 **240초** 그대로다 —
늘려서 통과시키지 않는다.

| 판정 | 언제 |
| --- | --- |
| `alive` | 예산 안에 끝났다 |
| `slow` | 끝나긴 했는데 예산을 넘었다. **조용히 통과시키지 않는다** |
| `dead` | 실패했다. 이유를 한 줄에 남긴다 |

**우회 자체가 잘못이 아니다. 우회했다는 사실이 안 적히는 것이 잘못이다.**
한 경로가 죽어도 다른 경로가 살아 있으면 통과하지만, 죽었다는 사실은 한 줄로
컨텍스트 팩과 체크리스트에 같이 들어간다.

그리고 규칙 하나를 어기고 있는 것을 찾았다. `measure` 패턴이 `rule.style.height` 를
트윈한다 — hyperframes 계약은 레이아웃 속성을 트윈하지 말라고 한다. `render-path.md` 에
적어 뒀다. 아직 안 고쳤다.

## 못 한 것

- **벽시계·첫 통과율·개입 횟수를 아직 못 쟀다.** `claude -p` 를 실제로 도는 회차가
  있어야 나온다. `work/exec/*.json` 에 다 남게는 해 뒀다
- **`--dangerously-skip-permissions` 를 루프에서 돈다.** 자식이 god-tibo 를 부르고
  Chrome 을 띄운다. 워크스페이스 밖으로 못 나가게 하는 것은 `guard()` 가 하지만,
  권한을 끈 세션을 7번 도는 것은 다른 문제다
- **`blocked` 상태를 안 들였다.** G6 의 컷 선별처럼 사람이 봐야 끝나는 자리가
  여전히 REJECTED 와 구분되지 않는다. 상태 기계를 건드리는 변경이라 뺐다
- **서브에이전트와 비교하지 않았다.** 목적이 같고 비용이 싸다
- **hyperframes 이펙트는 아직 네 패턴 그대로다.** 경로가 도는 것을 확인했을 뿐,
  `snapshot` 으로 갈아타지도 형광 마커를 넣지도 않았다
- **G1/G2 상호 무효화.** 앞 기록과 같다. `work/captures/<label>.lock.json` 으로 분리하면 된다
