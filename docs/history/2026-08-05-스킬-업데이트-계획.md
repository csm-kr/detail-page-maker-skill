## 1. 왜 지금 구조로는 안 되는가

현재 진입점은 문서다.

```text
SKILL.md 시작:
  1. 항상 references/workflow.md 를 읽는다
  2. 호스트가 Codex 가 아니면 claude-code.md 를 함께 읽는다
  3. 필요한 시점에만 … 를 읽는다
```

| 문서 진입점의 성질 | 2회차에 실제로 일어난 일 |
| --- | --- |
| 읽는 순서를 에이전트가 정한다 | `workflow.md`는 읽고 `templates.md`(1,208줄)는 안 읽었다 |
| 읽었는지 확인할 수 없다 | 기준작 캡처(780×16,215)를 안 열고 G1을 "확정"했다 |
| 호스트마다 읽는 문서가 다르다 | Codex 분기 조건문이 순서 차이를 허용한다 |
| **건너뛰어도 다음 단계가 돌아간다** | 가이드 주입을 건너뛰고 스틸 30장이 그대로 생성됐다 |
| 완료 판정이 에이전트의 말이다 | Studio·Wing·압축이 빠진 상태에서 "전부 완료" |
| **한 스킬이 12개 일을 다 한다** | 어느 일을 안 했는지 스킬 자신이 모른다 |
| **환경 세팅 단계가 없다** | `hyperframes`가 호스트 홈(`~/.codex/skills/`)에서 해석되고 있다 |

마지막 두 줄이 핵심이다. 단계를 쪼개면 각 단계가 자기 산출물의 유무로 스스로를 판정한다.
그리고 환경을 잠그지 않으면 로컬 방침이 조용히 깨진다.

## 3. `$init` — 환경 인터뷰와 로컬 세팅

### 3.1 왜 필요한가

지금은 세팅 단계가 없어서 이런 상태다.

- `dependencies.json`에 `"host_skills": ["hyperframes"]`가 있고, `doctor`가
  `C:\Users\csm81\.codex\skills\hyperframes`를 보고한다. **호스트 홈 의존이 남아 있다.**
- CDP·ChatGPT 로그인·god-tibo 인증은 G4에 가서야 막힌다. 23분짜리 구간 앞에서 멈춘다.
- 폰트·ffmpeg·python 유무를 각 단계가 따로 확인한다. 실패가 뒤에서 터진다.
- 프로젝트 루트 기본값이 `Documents\DetailPageStudio`라 2회차에 리포 밖에 프로젝트가
  생겼다가 지웠다.

**막힐 것은 앞에서 다 막는다.** 그것이 init의 목적이다.

### 3.2 절차

```bash
node scripts/init.mjs            # 대화형
node scripts/init.mjs --apply    # 인터뷰 답을 env.answers.json 에서 읽어 무인 실행
```

**1단계 — 탐지 (묻지 않는다).**

| 항목 | 방법 |
| --- | --- |
| OS·아키텍처 | `process.platform` |
| Node 버전 | `>= 22.15.0` 요구 |
| Python | `DETAIL_PAGE_PYTHON` → `python3` → `python` → `py` 후보 순회. Windows Store 별칭(exit 9009) 제외 |
| PIL / fontTools | 임포트 시도 |
| ffmpeg | `--version` |
| 브라우저 CDP | `BU_CDP_URL` → 9222 → 9223 (기존 `lib/cdp.mjs` 재사용) |
| 한글 폰트 | `NotoSansKR-VF.ttf` 등 후보 경로 |
| 디스크 여유 | 프로젝트당 미디어 예산 × 3 |
| 호스트 오염 | `~/.claude/skills`, `~/.agents/skills`, `~/.codex/skills`에 detail-page 계열이 있는지 |
| **god-tibo 인증** | `~/.codex/auth.json` + `~/.codex/installation_id` 존재 여부만. **내용은 읽지도 출력하지도 않는다** |
| 두 호스트 존재 | Claude Code·Codex 양쪽 CLI. 둘 다 있다고 전제하되 없으면 그 호스트 설치를 건너뛴다 |

**인증은 로컬로 옮길 수 없다 — 방침의 유일한 예외다.**

`god-tibo-imagen`은 `~/.codex/auth.json`(실측 4.1 KB)과 `installation_id`를 읽어
`chatgpt.com/backend-api/codex/responses`로 POST하는 **순수 node 라이브러리**다. Codex
에이전트가 호스트일 필요는 없다 — 2회차를 Claude Code에서 돌려 스틸 30장을 만들었다.
하지만 그 파일은 Codex CLI가 소유하므로 벤더링 대상이 아니다.

| | 로컬 | 호스트 |
| --- | --- | --- |
| 스킬 | **전부** | 없음 (있으면 `start` 거부) |
| 런타임 (hyperframes, 폰트) | **전부** | 없음 |
| 인증 (`~/.codex/auth.json`, ChatGPT 로그인 세션) | 불가 | **여기뿐** |

없으면 init이 멈추고 **사용자에게 `codex login`을 요청한다.** ChatGPT 로그인과 같은
취급이다 — 로그인은 사용자만 한다.

**2단계 — 인터뷰 (탐지로 알 수 없는 것만 묻는다).**

| 질문 | 기본값 | 왜 물어야 하는가 |
| --- | --- | --- |
| 어느 호스트를 쓰나 (Claude Code / Codex / 둘 다) | 둘 다 | 설치 대상 디렉터리 결정 |
| 프로젝트 루트 | `<워크스페이스>/projects` | 2회차에 `Documents`로 새어 나갔다 |
| **모델 얼굴을 어떻게 하나** (`none` / `crop-below-chin` / `allow`) | **없음 — 반드시 답한다** | 스킬 규칙이 아닌데 2회차에 내가 규칙으로 굳혔다. **부록 A.1** |
| ChatGPT 로그인이 되어 있나 | 확인 요청 | **로그인은 사용자만 한다.** G4 전제 |
| god-tibo 인증이 되어 있나 | `--dry-run`으로 검증 | G6 전제 |
| hyperframes를 로컬로 벤더링할까 | 예 | 지금 호스트 홈 의존을 끊는다 |
| 미디어 총량 상한 | 12 MB | G10 게이트 값. 근거는 §8 |
| 사진 포맷 | WebP q85 | G10 게이트 값 |
| 공급처 캡처 유효기간 | 7일 | G1 게이트 값(`max_age_days`) |
| 벽시계 목표 | 95분 | 범위 이탈 감지 기준 |

답은 `env.answers.json`에 저장해 **두 번 묻지 않는다.**

두 가지 규칙이 붙는다.

- **프로젝트마다 달라지는 것은 init이 묻지 않는다.** 두 URL과 실물 사진은
  `orchestrator start`의 입력이다. init은 워크스페이스 1회이므로 여기에 프로젝트 질문을
  섞으면 두 번째 프로젝트에서 옛 답이 조용히 재사용된다.
- **모델 얼굴에는 기본값이 없다.** 대화형에서 건너뛰면 다시 묻고, `--apply`에서
  `env.answers.json`에 `model_face` 키가 없으면 **exit 1**이다. 조용히 `none`으로 떨어지면
  2회차와 같은 결과가 되고, 그때는 그것이 내 판단이었는지 사용자 뜻이었는지 구분할 수 없다.
  프로젝트별로 바꾸려면 `start --model-face <값>`으로 덮어쓰고 그 값이
  `flow-plan.output.policy.model_face`에 기록된다.

**3단계 — 로컬 세팅 (전부 프로젝트-로컬).**

1. `.skill-src/skills/*`를 `.claude/skills/`와 `.agents/skills/`에 복사 (선택한 호스트만)
2. 번들 의존 스킬을 오케스트레이터 아래 **한 벌** 설치
3. `hyperframes`를 `motion/` 아래 프로젝트-로컬 런타임으로 벤더링 + 버전 핀
4. 폰트를 `runtime/fonts/`에 배치하거나 경로를 잠금 파일에 기록
5. `.gitignore` 확인 (생성물·런타임 제외)
6. **호스트 홈에 detail-page 계열이 있으면 경고하고 제거를 제안** — 사용자 방침
7. `work/env.lock.json` 작성

### 3.4 강제

- `orchestrator start`는 `env.lock.json`이 없거나 **설치 사본 해시가 어긋나면 거부한다.**
  → init 없이 제작을 시작할 수 없다.
- `env.lock.json`의 `hosts`에 없는 디렉터리에서 스킬이 발견되면 경고.
- **호스트 홈에 detail-page 계열 스킬이 있으면 `start`가 거부한다.** 로컬 방침을 게이트로.
- `policy.model_face`가 없으면 `start`가 거부한다. G4가 프롬프트에 주입할 때 한 번 더 본다.
- **`host_skills` 개념을 코드에서 없앤다.** 지금은 세 곳에 퍼져 있다.

  | 위치 | 현재 |
  | --- | --- |
  | `dependencies.json:17` | `"host_skills": ["hyperframes"]` |
  | `scripts/detail-page.mjs:68` | `manifest.host_skills.map(...)` — `doctor` 출력이 홈 경로를 본다 |
  | `references/claude-code.md:17` | "`doctor`의 `host_skills.hyperframes`는 호스트 설치본을 찾는다" |

  같은 `dependencies.json` 안에서 `runtimes.hyperframes`는 이미
  `"project-local-runtime-for-motion"`이다. **한 파일이 자기와 모순돼 있고**, 실제로 해석되는
  쪽은 `host_skills`다. 세 곳을 동시에 지우지 않으면 `doctor`가 계속 홈을 보고 통과시킨다.
- `env.lock.json`이 30일보다 오래되면 `init --recheck`를 요구 (CDP·로그인은 만료된다).

### 3.5 이름 충돌 주의

Claude Code에 `/init`이 **내장 명령으로 이미 있다**(CLAUDE.md 생성). 그래서 스킬 이름은
`detail-page-init`으로 하고, 사용자가 `$init`이라고 부르면 이 스킬을 뜻하는 것으로
오케스트레이터 문서에 적어 둔다. 내장 명령을 가릴 수 없다는 점을 문서에 명시한다.

## 4. 다 돌 수밖에 없게 만드는 장치 7개

문서에 "해라"라고 쓰는 것으로는 안 된다. 2회차가 증거다.

### 4.1 선행 게이트 거부

모든 단계 스킬 `scripts/run.mjs`의 첫 줄.

```js
requireEnv();                          // env.lock.json 없으면 exit 1
requireGates(project, ["G2", "G3"]);   // 미통과면 exit 1, 부족한 게이트를 출력
```

사용자가 `detail-page-g6-stills`를 직접 불러도 거부된다.

### 4.2 산출물 해시 체인 — 손으로 채운 산출물은 통과하지 못한다

```json
{ "G3": { "passed_at": "…",
          "inputs":  { "work/flow-map.md": "sha256:…", "work/SSOT.md": "sha256:…" },
          "outputs": { "flow-plan.json": "sha256:…" } } }
```

`flow-map.md` 없이 `flow-plan.json`을 만들어 두면 통과 기록을 쓸 수 없다.

### 4.3 무효화 전파 — 상류가 바뀌면 하류가 자동으로 ✗

`gates.json`을 읽을 때마다 기록된 입력 해시와 현재 해시를 비교해, 다르면 그 게이트와
**모든 하류를 `✗`로 되돌린다.** 가장 강한 장치다. 2회차 결함 대부분이
"상류를 바꿨는데 하류를 다시 안 돌린 것"이었다.

```text
DESIGN-GUIDE.md 수정      → G5 ✗ → G6~G11 ✗
structure-full.png 재생성 → G9 ✗ (앵커 해시 불일치)
gif_briefs 수정           → G8 ✗
env.lock.json 무효         → G0~G11 ✗
```

### 4.4 우회 경로 제거

- 루트에 흩어진 `work/build-*.mjs`, `publish-*.mjs`, `crop-bg.py`, `render-motion.mjs`,
  `verify-gifs.py`를 **해당 단계 스킬 안으로 옮긴다.**
- 루트에 직접 실행 가능한 빌드 스크립트를 남기지 않는다.
- `build-all.mjs`를 없애고 `orchestrator run`이 게이트를 순서대로 걸어간다.

### 4.5 `--force`를 만들지 않는다

우회 플래그를 처음부터 두지 않는다. 게이트가 틀렸으면 게이트를 고친다.
(2회차에 내가 만든 테스트를 통과시키는 최소한만 한 전례가 있다. 탈출구를 주면 그 길로 간다.)

### 4.6 완료 어휘 잠금

- `orchestrator report`만 완료를 선언할 수 있다. `✗`가 하나라도 있으면 **exit 1**.
- 오케스트레이터 `SKILL.md`에 규칙으로 박는다:
  **"`report`가 exit 0이 아니면 '완료'라는 단어를 쓰지 않는다. 보고에 표를 그대로 붙인다."**

### 4.7 순서 위반 시도를 테스트한다

`e2e`에 **거부가 기대 결과인 케이스**를 넣는다. §9.1 참조.

검사할 대상도 없었다.

### 수행 주체 — 완전 자동인 게이트는 12개 중 2개뿐이다

여기를 흐리면 `run`이 전부 돌려 준다고 오해하게 된다. **스킬은 에이전트가 읽는 것이고,
스크립트가 스킬을 호출할 수는 없다.**

| 주체 | 게이트 | 나뉘는 지점 |
| --- | --- | --- |
| **에이전트** | G1, G2, G3, G4, G7 | 판독·기획·카피·프롬프트. 전부 판단이다 |
| **스크립트** | G9, G10 | 조립과 검사. 결정적이다 |
| **혼합** | G5, G6, G8, G11 | 아래 |

| 혼합 게이트 | 스크립트가 하는 것 | 에이전트·사람이 하는 것 |
| --- | --- | --- |
| G5 | 무드 블록 주입, `validate-plan` 재실행 | 가이드의 무드 문장을 어느 컷에 붙일지 |
| G6 | batch 생성, 발행 파일명 매핑 | **원본 해상도로 보고 탈락시키는 선별** |
| G8 | 렌더, GIF 검증, 신선도 비교 | **컴포지션 재작성** (2회차에 여기를 건너뛰었다) |
| G11 | Wing export, 죽인 서버 복구 | Studio 확인 |

그래서 `run`은 "전부 자동"이 아니라 **"판단이 필요한 지점까지 자동"** 이다. 각 게이트의
`run.mjs`는 `"actor": "agent" | "script" | "mixed"`를 선언하고, 판단이 필요한 지점에서
**작업하지 않고 체크리스트와 참고 문서 경로만 출력하며 멈춘다.**

이 사실이 게이트 엔진의 필요성을 줄이는 것이 아니라 **키운다.** 12개 중 10개가 사람 또는
에이전트의 판단을 거치므로 순서를 문서에 맡기면 회차마다 갈린다. 판정은 언제나
`check.mjs`가 하고 — 주체가 누구든 **통과 조건은 같다.**

### 구 → 신 대응

| 기존 | 새 | 변경 이유 |
| --- | --- | --- |
| — | **INIT** | 신설. 환경·로컬 세팅을 앞에서 잠근다 |
| G0 | G0 + G1 | 진입과 사실 잠금 분리 |
| G1 | **G2 + G3** | **기준작 판독을 독립 게이트로** — 2회차 최대 누락 |
| G1.5 | **G4 + G5** | **무드 주입을 게이트로** 승격 |
| G2 | G6 | **선별**을 통과 조건으로 승격 |
| — | **G7** | 신설. 섹션별 레이아웃 기획 |
| G3 | G8 | brief↔구현 대조 추가 |
| G4 | G9 + G10 | 조립과 QA 분리, 앵커·포맷 조건 |
| G5 | **G11** | Studio·Wing까지가 완료 |

### 병렬화 규칙

```text
직렬 필수:  G2 → G3 → G4 → G5 → G6      (분위기·주입 의존)
직렬 필수:  G7 → G8,  G7 → G9
병렬 가능:  G1 ∥ G2                      (사실 추출 ∥ 기준작 판독)
```

`orchestrator run --parallel`은 **선행 게이트가 `○`인 단계만** 동시에 띄운다.
2회차에 스틸을 백그라운드로 앞당긴 것이 G5 누락의 직접 원인이었다.

## 6. 두 호스트 병용

> **순서와 검사는 스크립트에, 역할 배분만 호스트 문서에.**

| 구분 | 위치 | 호스트별 차이 |
| --- | --- | --- |
| 환경 잠금 | `work/env.lock.json` | 설치 대상만 다름 |
| 게이트 정의·순서·거부 | `orchestrator/scripts/lib/gates.mjs` | **없음** |
| 게이트 상태 | `<프로젝트>/work/gates.json` | **없음** |
| 단계 실행 | 각 단계 스킬 `scripts/run.mjs` | **없음** |
| sub-agent 역할·lane | `orchestrator/references/{claude-code,codex}.md` | 있음 |
| 진입 안내 | `orchestrator/SKILL.md` 5줄 | 없음 |

- 설치는 프로젝트-로컬 두 곳에 **동일 사본.** 홈에는 설치하지 않는다.
- `codex.md`를 신설한다. 지금은 `claude-code.md`만 있어 비대칭이고, 그 비대칭이
  "호스트가 Codex가 아니면 …" 조건문을 낳아 순서 차이를 허용했다.
- 두 호스트 문서는 **게이트 순서를 다시 적지 않는다.** 적으면 갈린다.
- 테스트: 호스트 문서에 게이트 id가 순서 목록으로 나타나면 실패.

```markdown
## 시작
1. `work/env.lock.json` 이 없으면 **detail-page-init 을 먼저 실행한다.**
2. `node scripts/orchestrate.mjs start --name … --supplier-url … --coupang-url …`
3. 출력된 게이트 표에서 **첫 번째 `✗` 게이트의 스킬을 호출한다.** 순서를 바꾸지 않는다.
4. 막히면 `gate <id> --check` 가 부족한 것을 한 줄로 알려준다.
5. `report` 가 exit 0 이 되기 전에는 **"완료"라고 말하지 않는다.** 표를 그대로 붙인다.
6. 호스트별 역할 배분은 claude-code.md 또는 codex.md. 순서는 양쪽이 같다.
```

| 명령 | 내용 |
| --- | --- |
| `start` | 프로젝트 생성 + `gates.json`·`inputs.lock.json` + 표 출력 |
| `gates` | 표 출력, 첫 `✗`와 호출할 스킬 이름 |
| `gate <id> --check` / `--pass` | 검사 / 검사 후 통과 기록(해시 포함) |
| `lock --read <path>` | 입력 파일을 읽고 해시 기록 |
| `run [--parallel]` | 남은 게이트를 순서대로 실행. **판단이 필요한 지점에서 멈추고 호출할 스킬 이름을 출력한다** (§5 수행 주체) |
| `report` | `report.md` 생성. `✗` 있으면 exit 1 |
| `doctor` | 런타임·CDP 확인 (env.lock 대조) |

## 8. 위험과 완화

| 위험 | 완화 |
| --- | --- |
| 스킬 목록이 시끄럽고 엉뚱한 단계가 자동 호출된다 | 모든 단계 `description`에 "오케스트레이터가 G_n 에서 호출한다 / 직접 호출하면 거부된다" 명시. 실제로 거부되므로 오호출이 사고가 되지 않는다 |
| 게이트 순서가 여러 문서에 중복돼 갈린다 | `gates.mjs` 단일 출처 + 중복 기재 금지 테스트 |
| 무효화 전파가 과민해 계속 ✗ 로 되돌아간다 | 해시 대상을 **의미 있는 산출물만**으로 제한 (플랜·가이드·앵커 이미지·brief). 로그·중간물 제외 |
| init이 무거워 매번 돌리기 싫어진다 | 워크스페이스 1회 + `--recheck`는 만료 항목만. 답은 `env.answers.json`에 저장 |

## 부록 A — `의문.md` 대응

`의문.md`의 6개 항목을 확인하고 설계에 반영한다. 확인 결과 **두 개는 내가 잘못 굳힌
것이었고, 하나는 쓰지 않은 기능이 있었다.**

### A.1 모델 얼굴이 나오면 안 되나 — 스킬 규칙이 아니었다

**확인.** 스킬 문서에서 "얼굴"이 나오는 곳은 전부 `art-direction.md`의 **폰트 얼굴**
얘기다. 인물 얼굴 정책은 스킬에 **없다.** 공급처 상세페이지에는 모델 얼굴이 있다.

즉 "인물 얼굴 노출 금지"는 1회차 가이드 §9의 문장을 내가 2회차 `SSOT.md` §3에 **규칙으로
옮겨 굳힌 것**이다. 근거 없는 제약을 사실처럼 적었고, 그 결과 히어로 플레이트에 스크림을
깔아 머리를 가린 것을 "가독성 개선"이라고 보고했다.

**판단: 금지 사항이 아니라 선택이다.** 다만 생성 얼굴에는 실제 위험이 있다.

| 위험 | 내용 |
| --- | --- |
| 실인물 유사 | 특정 인물을 닮게 나올 수 있다 |
| 어색함 | 손·팔보다 얼굴이 훨씬 잘 무너진다 |
| 동일성 유지 | 컷마다 다른 사람이 되기 쉽다. 14장 세트에서 특히 |

**반영.**

- **init 인터뷰의 필수 질문**으로 묻는다(§3.2). 값은 `none` / `crop-below-chin` / `allow` 셋이고
  `env.lock.json`의 `policy.model_face`와 `flow-plan.output.policy.model_face`에 기록된다.
- **기본값을 코드에 두지 않는다.** 대화형에서 건너뛰면 다시 묻고, `--apply`에서 키가 없으면
  init이 exit 1이다. `policy.model_face`가 없으면 `start`도 거부한다.
- G4·G6이 그 정책을 프롬프트에 주입한다. 정책과 어긋난 컷은 **G6 선별에서 탈락.**
- `allow`를 고르면 "동일 인물 유지"를 selection 체크리스트 항목으로 추가한다.
- 프로젝트마다 다르게 하려면 `start --model-face <값>`으로 덮어쓴다.

### A.2 Codex와 Claude Code를 둘 다 쓸 수 있나 — 지금도 되지만 순서가 갈릴 수 있다

**확인.** 현재 사본이 `.claude/skills`와 `.agents/skills` 두 곳에 각각 109개 파일로 동일하게
있어 **양쪽 다 인식한다.** 문제는 둘이다.

1. 순서 강제가 없어 호스트별·회차별로 읽는 문서가 갈린다 (§1)
2. `doctor`가 `hyperframes`를 `~/.codex/skills/hyperframes`에서 해석한다 — **호스트 의존**

**반영.** §3(init)이 hyperframes를 프로젝트-로컬로 벤더링하고 `dependencies.json`의
`host_skills`를 제거한다. `codex.md`를 신설해 비대칭을 없앤다. 순서는 `gates.mjs` 한 곳.

| 문제 제기 도해 (점선 윤곽, 화살표, 대비) | 구성 참조 + 필요한 부분 크롭 |
| 카드·pill·치수선·표 같은 구조 | CSS 재현 |
| **한글 텍스트** | **수확 금지.** 전부 HTML 텍스트 |
| **1:2 비율** | **수확 금지.** 발행 비율은 `assets.md` |

`harvest.md`는 **G4의 산출물**이다. 없으면 G4가 통과하지 못하고, 있어도 G7의 수단 열이
그것을 참조하지 않으면 G7이 거부한다. "무엇을 가져오고 무엇을 안 가져오는지"를 적지 않으면
2회차처럼 팔레트만 가져오고 끝난다.

### A.4 컴포넌트를 SVG로 해야 하나 — 아니다. 수단을 고르게 한다

사용자 지적이 맞다. 2회차의 "전부 인라인 SVG/CSS"는 **내 편의였고 목업의 강점을 버리는
선택**이었다. 이미지로 생성하는 안을 넣는다.

**G7 `page-plan.md`에 컴포넌트마다 수단 열을 필수로 만든다. 기본값을 두지 않는다.**

| 수단 | 적합한 대상 | 장점 | 단점 |
| --- | --- | --- | --- |
| **HTML 텍스트** | 모든 카피 | 편집·검색·줄바꿈 검수 가능. 우리 쪽 강점 | — |
| **CSS 재현** | 카드·패널·pill·치수선·정보표 | 가볍다. 토큰으로 색 통일 | 과장된 이펙트 표현 한계 |
| **인라인 SVG** | 단순 라인 아이콘 | 색 상속, 선명, 용량 0 | 귀여운·과장된 표현 불가 |
| **목업 크롭** | 배경 이펙트·장식 | 목업 강점 그대로 | 한글 없는 영역만. 해상도 한계 |
| **신규 생성** (목업 크롭을 레퍼런스로) | 이모지·아이콘 세트·문제 제기 도해 | 강점 유지 + 규격 자유 | 텍스트 금지. 용량 |

권장 조합: **텍스트=HTML, 구조=CSS, 장식·이펙트·이모지=크롭 또는 생성, 라인 아이콘=SVG.**

강제: `page-plan.md`의 수단 열이 **전부 SVG/CSS면 G7이 경고하고 이유를 요구한다.**
2회차 편향이 재발하는 것을 그 자리에서 잡는다.

### A.5 GIF는 왜 다 있는 걸 썼나 — 두 가지 답

**(1) 왜 있는 걸 썼나.** brief 10개는 2회차에 고쳤지만 컴포지션은 1회차 설계를 그대로
재렌더했다. 그래서 `g06`의 부위명 5개가 HTML과 전부 다르고 `g07`은 두 결 대비를 담지
못했다. **§4.3 무효화 전파가 이것을 자동으로 `✗`로 만든다** — brief 해시가 바뀌면 G8이
✗가 되어 컴포지션을 고치지 않고는 통과할 수 없다.

**(2) 다양한 생성 방법을 썼는가 — 아니다. 한 경로만 썼다.**

확인: 번들 `god-tibo`에 **쓰지 않은 GIF 경로가 있다.**

```text
media-tools.mjs:271   export async function createGif({ framePaths, outputPath, fps = 8, width = 768 })
tibo-batch.mjs:830    await createGif({ … })
job 스키마             "gif_path": null
```

즉 이미지 생성기가 프레임 시퀀스로 GIF를 만들 수 있는데 한 번도 쓰지 않았다.

**반영 — G8에서 brief마다 수단을 고른다. 기본값 없음.**

| 수단 | 적합 | 2회차 사용 |
| --- | --- | ---: |
| **HyperFrames** (CSS/GSAP) | 도해·치수선·콜아웃·마스크처럼 타이밍이 정확해야 하는 것 | 10 / 10 |
| **god-tibo `createGif`** (프레임 시퀀스) | 제품이 실제로 변하는 장면 — 당김, 착용 3단계, 흘러내림 | **0** |
| **ffmpeg** (스틸 → 시퀀스) | 색 순환, 하드컷 교체 | **0** |
| **목업 크롭 + CSS 오버레이** | 목업 이펙트를 그대로 움직이기 | **0** |

`gif_briefs[i].method`를 필수 필드로 만들고, 값이 없으면 G8이 거부한다.
그리고 **한 수단이 8개를 넘으면 경고**한다 — 다양성을 확인하는 것이 아니라, 편한 경로로
쏠렸는지 스스로 보게 하기 위한 것이다.
