# PRD — detail-page 스킬 재구성

## 1. 배경

`detail-page-maker-skill`은 공급처 URL과 기준 쿠팡 URL을 받아 폭 780px 상세페이지를
만든다. 2026-08-05 2회차 작업은 **QA를 전부 통과하고 완료를 보고했지만 근거가 비어
있었다.** 실측 증거.

| 항목 | 실측 |
| --- | --- |
| 벽시계 | 100분 (10:20 프로젝트 생성 → 12:00 `detail-page.html`) |
| 산출물 | 14섹션, 스틸 30장, GIF 10개, 회귀 테스트 45개 전부 GREEN |
| 미디어 용량 | 38 MB (사진 PNG 21.3 MB + GIF 16.4 MB) |
| 수행하지 않은 단계 | 기준작 판독, 무드 주입, 컷 선별, 레이아웃 기획, 컴포지션 재작성, Studio·Wing·압축 |
| 누락 개수 | 13 ([`반성문`](history/2026-08-05-반성문-재발방지대책.md) §1) |

**45개 테스트가 전부 통과한 채 6개 결함이 남았다.** 전부 "파일이 있는가"만 검사했기
때문이다. 근본 원인은 진입점이 문서라는 것이다 — 읽는 순서를 에이전트가 정하고,
읽었는지 확인할 수 없고, **건너뛰어도 다음 단계가 돌아간다.**

## 2. 문제 정의

| # | 문제 | 2회차의 증거 |
| ---: | --- | --- |
| P1 | 순서를 건너뛸 수 있다 | 무드 주입(G1.5 후속)을 건너뛰고 스틸 30장이 그대로 생성됐다 |
| P2 | 한 스킬이 12개 일을 해서 무엇을 안 했는지 스킬 자신이 모른다 | `templates.md` 1,208줄을 열지 않고 프롬프트를 썼다 |
| P3 | 완료 판정이 에이전트의 말이다 | Studio·Wing·압축이 빠진 상태로 "전부 완료" |
| P4 | 환경을 잠그는 단계가 없다 | `hyperframes`가 호스트 홈(`~/.codex/skills/`)에서 해석되고 있다 |
| P5 | 진행 상황이 보이지 않는다 | 어느 단계인지, 얼마나 걸렸는지 사용자가 알 방법이 없다 |
| P6 | 상류를 고쳐도 하류가 자동으로 다시 돌지 않는다 | GIF brief 10개를 고치고 컴포지션은 1회차 그대로 재렌더했다 |

## 3. 목표 / 비목표

### 목표

1. **모든 단계를 돌 수밖에 없다.** 건너뛰면 다음 단계가 실행되지 않는다
   ([ADR-0001](adr/0001-게이트-순서를-스크립트가-소유한다.md)).
2. 각 단계가 개별 스킬이고, 오케스트레이터가 순서를 소유한다
   ([ADR-0002](adr/0002-단계를-개별-스킬로-분리한다.md)).
3. **`detail-page-init` 한 번으로** 환경 인터뷰·로컬 세팅·**정리**가 끝난다.
   사용자가 `$init`이라 부르는 단계다. Claude Code에 `/init` 내장 명령이 있어 그 이름은 쓸 수 없다.
4. 스킬과 런타임은 프로젝트-로컬. 호스트 홈에는 아무것도 깔지 않는다.
5. Claude Code와 Codex **양쪽에서 같은 순서로** 돈다.
6. 어느 단계인지, 얼마나 걸렸는지 **눈에 보인다.**

### 비목표

- 시장 전체 검색·경쟁사 순위화·대량 후기 분석·A/B/C 조립
- 스킬을 다른 사람에게 배포하는 것. 1인 워크스페이스 전용이다
- 게이트를 통과시키기 위한 우회 플래그. `--force`는 만들지 않는다
- 인증을 로컬로 옮기는 것. 불가능하다 ([ADR-0004](adr/0004-인증만-호스트에-남긴다.md))

## 7. 제약

- 목업 생성은 ChatGPT 웹 대화(CDP)를 쓴다. **로그인은 사용자만 한다.**
- 이미지 생성은 `~/.codex/auth.json`을 요구한다. 로컬로 옮길 수 없다.
- 목업은 **한 대화에서 4장씩** 받는다. 병렬 탭은 다른 대화가 되어 톤이 갈린다
  (실측: 한 턴 10장은 2분 15초로 빠르지만 정렬·배경·아이콘이 갈렸다).
- 목업은 기획자료이며 발행하지 않는다. 배경 크롭은 한글이 없는 영역만.
- 공개물에 프롬프트·모델·경로·hash·QA 상태 같은 제작 메타데이터를 남기지 않는다.

### 해소된 것 — 브라우저 CDP

Chrome 136부터 **기본 프로필에서 `--remote-debugging-port` 가 무시된다.** 그래서
전용 프로필(`runtime/chrome-profile/`)로 두 번째 인스턴스를 띄운다. 사용자가 쓰던 창을
닫지 않아도 되고, 로그인이 그 프로필에 남아 다음 회차에도 쓰인다.

### 해소된 것 — hyperframes 는 두 개였다

렌더러(npm CLI)와 저작 가이드(호스트 스킬)가 다른 것이었다. 렌더러는 `motion/` 에 로컬
설치하고, 저작 가이드 7개와 `browser-harness` 를 오케스트레이터 아래로 번들했다.
**호스트 스킬 의존이 전부 사라졌다** ([ADR-0004](adr/0004-인증만-호스트에-남긴다.md)).
