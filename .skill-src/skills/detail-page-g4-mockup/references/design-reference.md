# G1.5 — Design Reference

G1 에서 Lean Page Plan 을 확정한 뒤 G2 이미지 생성으로 넘어가기 전에 읽는다.

## 무엇을 하는가

확정된 플랜과 실물 사진을 ChatGPT 에 넣어 **섹션마다 상세페이지 목업 한 장**을 받는다.
그 목업에서 무드를 추출해 `DESIGN-GUIDE.md` 를 쓰고, G2 의 still job 프롬프트와 G4 의 HTML
조립이 그 가이드를 따른다.

**목업은 기획자료다. 발행하지 않는다.** 이미지 생성 모델의 한글은 신뢰할 수 없다. 실측에서
헤드라인과 본문은 정확했지만 제품 라벨 글자가 깨졌고, 실물에 없는 위치에 라벨을 하나 더
만들었다. 카피는 전부 HTML 텍스트로 만든다.

## 산출물

```text
<프로젝트>/work/design-ref/
├── mockups/mock-<section-id>.png    섹션당 한 장. 발행하지 않는다
├── mockups/variants/                채택하지 않은 것. 실패 사유를 파일명에 남긴다
├── DESIGN-GUIDE.md                  G2·G4 가 읽는 무드 기준
└── chatgpt-prompt.txt               재현용 프롬프트 원문
```

목업을 `output/` 아래에 두지 않는다. `qa --strict-media` 가 `ORPHAN_MEDIA` 로 막는다.

## 절차

1. `node scripts/detail-page.mjs doctor` 로 `browser_cdp.ok` 를 확인한다. 실패하면 그 하나만
   요청하고 멈춘다. 이 단계는 건너뛰지 않는다.
2. ChatGPT 로그인을 확인한다. `#prompt-textarea` 가 있고 `[data-testid="login-button"]` 이
   없으면 로그인 상태다. **로그인은 사용자만 한다.**
3. 새 채팅을 연다. 앞선 채팅의 톤은 이어지지 않으므로 스타일 스펙을 매번 명시한다.
4. 실물 사진을 업로드한다. `cdp("DOM.setFileInputFiles", files=[...], nodeId=...)` 로 넣는다.
5. `assets/image-prompt-template.md` 를 기준으로 프롬프트를 만든다. 플랜의 섹션 id, 헤드라인
   2줄, 본문, 장면 지시를 채운다.
6. **4장씩 나눠 요청한다.** 파일명을 `01_<section-id>.png` 형식으로 붙이라고 지시한다.
7. `stop-button` 이 사라지고 `send-button` 이 돌아오면 그 턴이 끝난 것이다.
8. 결과를 회수한다. **`save_browser_fetch(src, path)` 를 쓴다.** 인라인 이미지와 artifact
   목록 두 경로를 모두 처리한다.
9. **회수한 장을 눈으로 분류한다.** 개수만 맞춰서는 안 된다 (아래 "콜라주" 참고).
   부족하거나 틀린 섹션만 재요청한다.
10. 목업 픽셀에서 팔레트를 추출해 `DESIGN-GUIDE.md` 를 쓴다. 실물과 대조해 identity 오류를
    같은 문서에 기록한다.

### 장수를 몇 장씩 요청하는가

| 방식 | 실측 | 판단 |
| --- | --- | --- |
| 한 턴에 10장 | 2분 15초. 파일명도 정확 | 빠르지만 **앞선 턴과 다른 해석을 만든다.** 정렬·배경·아이콘이 갈렸다 |
| 4장씩 나눠 4번 | 회당 3~7분 | 톤이 유지됐다. **이 방식을 쓴다** |
| 재요청 | 3장에 4분 20초 | 부족분은 **3장 이하로** 나눈다 |

대화가 길어질수록 느려진다. 2회차 실측에서 batch 1 이 4분, batch 3 이 7분이었다.
14장 + 재요청 3장에 총 23분이 걸렸다.

### 콜라주와 중복 — 반드시 눈으로 검사한다

**1회차 기록("각각 따로 명시하면 콜라주가 발생하지 않았다")은 틀렸다.** 2회차에서는 4장
요청에 **4분할 콜라주 2장 + 같은 섹션 중복 1장**이 나왔다. 4장 중 쓸 수 있는 것은 1장이었다.
파일 개수는 4개로 맞았기 때문에 개수 검사로는 잡히지 않는다.

"콜라주로 만들지 않는다" 한 줄로는 막히지 않는다. **한 파일의 내용을 규정한다.**

```text
- 결과는 N개의 파일이고, 한 파일에는 한 섹션만 들어간다.
- 한 이미지 안에 두 개 이상의 장면, 두 개 이상의 헤드라인, 위아래로 나뉜 여러 패널을 넣지 않는다.
- 여러 장을 한 캔버스에 격자로 배치한 콜라주, 시트, 모아보기 이미지를 만들지 않는다.
- 지정한 섹션을 빠뜨리거나 같은 섹션을 두 번 만들지 않는다. 목록과 파일이 1:1로 대응해야 한다.
```

이 문장으로 재요청한 3장은 전부 개별 페이지로 정확히 나왔다.

검사는 회수 직후 **축소 그리드 한 장**을 만들어 섹션별로 한 장씩 맞는지 본다. 틀린 것은
`variants/` 로 옮기고 실패 사유를 파일명에 남긴다.

프롬프트는 손으로 쓰지 않는다. 확정된 플랜에서 생성해야 플랜에 없는 표현이 섞이지 않는다.
1회차에는 프롬프트의 "톤 참고용" 흐름 줄에 근거 없는 표현이 섞여 목업 카드에 그대로 구워졌다.

## 업로드와 회수 — 이 방법을 쓴다

```python
upload_file("input[type=file][accept]", abs_path)   # DOM.setFileInputFiles 도 된다
save_browser_fetch(img_src, out_path)              # 브라우저 세션으로 받아 디스크에 직접 쓴다
```

`save_browser_fetch` 는 IPC 를 타지 않으므로 **청크 길이 제한과 무관하고, 이미지의 디코딩
상태와도 무관하다.** `naturalWidth` 가 `0x0` 인 화면 밖 이미지도 정상 회수됐다.
base64 를 12 KB 씩 `window` 에 누적하는 우회는 이제 필요 없다.

업로드본과 생성본은 `alt` 로 구분한다. 업로드본은 `alt` 가 원본 파일명이고 생성본은
"생성된 이미지" 로 시작한다. `src` 의 `id=file_...` 로 중복을 제거한 뒤 alt 로 갈라낸다.

**업로드 성공은 썸네일이 아니라 `send-button` 의 등장으로 판정한다.** 빈 컴포저에는 send 가
없고 첨부가 붙으면 생긴다. 썸네일은 22초 뒤에도 셀렉터에 안 걸릴 수 있고, src 는
`blob:` 이 아니라 `chatgpt.com/backend-api/estuary/content?id=file_...` 다.

## 브라우저 조작 함정

실측으로 걸린 것만 적는다.

| 함정 | 대응 |
| --- | --- |
| **활성 탭이 조작 중에 바뀐다** | 폴링 중 이미지 수가 16에서 7로 줄어 DOM 가상화로 오판했다. 실제로는 활성 탭이 다른 ChatGPT 대화로 바뀐 것이었다. **대화 id 를 잡아두고 조작마다 `page_info()["url"]` 로 확인한다** |
| `cdp()` 직접 호출이 활성 세션을 옮긴다 | `Emulation.setDeviceMetricsOverride` 를 부른 뒤 `js()` 가 다른 탭의 DOM 을 돌려줬다. 가능하면 `js()`·헬퍼만 쓴다 |
| `new_tab()` 으로 연 탭은 프로세스 종료 시 사라진다 | 다음 `browser-harness` 호출에서 `No target with given id found` 가 난다. **열기·대기·조작·캡처를 한 호출 안에서 끝낸다** |
| browser-harness 스크립트에 한글을 쓰면 `UnicodeEncodeError: surrogates not allowed` 로 죽는다 | 스크립트는 **ASCII 만. 주석도 안 된다.** 한글은 파일에서 `encoding="utf-8"` 로 읽고 JS 문자열은 `json.dumps()` 나 `\uXXXX` 로 넘긴다 |
| 한글이 든 **경로**도 같은 이유로 깨진다 | ASCII 경로로 복사해서 쓴다 |
| **IPC 타임아웃이 실패가 아니다** | `Input.insertText` 가 3번 전부 `TimeoutError` 를 던졌지만 컴포저에는 정상 입력돼 있었다. 예외를 잡고 글자 수를 확인한 뒤 전송한다. 맹목적 재시도는 중복 입력이 된다 |
| 대화가 길어지면 `js()` 자체가 타임아웃된다 | 이미지 20여 장에서 발생. **같은 대화 URL 을 새 탭으로 열면 풀린다.** 컴포저 초안은 새 탭에도 남아 있어 다시 입력하지 않아도 된다 |
| 오류 배너가 떠도 스레드는 살아 있다 | "문제가 발생했습니다. 다시 시도하세요." 가 떠 있는데 `send-button` 이 정상이었고 이후 요청도 성공했다. **배너로 실패 판정하지 않는다** |
| `Page.captureScreenshot` 이 IPC 타임아웃 | base64 가 크다. `capture_screenshot(path)` 헬퍼를 쓰고, 그래도 실패하면 `max_dim` 으로 줄인다 |
| 생성 결과가 `main img` 에 안 잡힌다 | artifact 목록으로 나오고 3개만 보인 뒤 "N개 더 보기" 로 접힌다. 목록을 펼치고 행의 `aria-label="파일 다운로드"` 버튼을 쓴다 |
| **결과 UI 경로가 턴마다 다르다** | 1회차는 artifact 목록, 2회차는 4턴 전부 인라인 이미지였다. 수집 코드는 두 경로를 모두 처리한다 |
| Chrome 이 연속 자동 다운로드를 막는다 | 10개를 한 번에 클릭하면 1개만 받아진다. **하나 클릭 → 파일 도착 확인 → 다음** 으로 순차 진행한다. `save_browser_fetch` 를 쓰면 이 문제가 없다 |
| 같은 파일 재업로드 시 모달이 뜨고 막힌다 | "이미 이 파일을 업로드했습니다". 재시도 전 모달을 닫는다. 업로드 실패로 오판하지 않는다 |
| 스크린샷 좌표 배율이 창마다 다르다 | 실측에서 1.25배였다. 좌표 클릭 대신 `data-testid`·`aria-label` 로 직접 클릭한다 |
| 규격이 회수 경로에 따라 다르다 | 다운로드 버튼은 요청 규격 원본을, 인라인 fetch 는 뷰어가 재인코딩한 크기를 준다. 비율은 같으므로 무드 판단에는 영향이 없다 |

## 완료 판정

`stop-button` 부재 + `send-button` 존재 + 기대 누적 장수, 세 조건을 함께 본다.
그리고 **판정 전에 URL 을 확인한다.** 개수만 보면 탭이 바뀐 것을 생성 완료로 오판한다.

## DESIGN-GUIDE.md 에 담는 것

목업을 눈으로 보고 쓴다. 추측하지 않고 **픽셀에서 값을 뽑는다.**

1. **지위** — 기획자료이고 발행하지 않는다는 것, 그 이유
2. **목업 목록** — 섹션별 파일명, 규격, 상태(양호/오류)
3. **컬러** — 역할별 hex. 헤드라인 1줄, 2줄, 본문, 카드 배경, 배경, 페이지 배경.
   **브랜드 컬러는 하나로 못 박는다.** 가이드에 없어 파생한 값은 파생임을 표시한다
4. **타이포** — 헤드라인 줄 수·정렬·강조 단위, 본문 크기 관계, 의미 단위 청킹 규칙.
   **강조가 줄 단위인지 단어 단위인지 구분해 적는다.** 실측에서는 단어 단위였고,
   줄 전체를 칠하면 목업의 인상이 사라졌다
5. **반복되는 구성 요소** — 목업 전체에서 재사용된 패턴. HTML 컴포넌트로 만들 단위.
   **여기가 이 문서의 핵심이다.** 요소마다 클래스 이름, 지름·radius·stroke·폰트 크기를
   목업 폭 기준 실측값과 발행 폭 환산값으로 함께 적는다. "카드가 있다" 로는 옮길 수 없다
6. **배경** — 형태, 채도 수준, 장식 요소의 개수와 크기 변화
7. **identity 및 표현 주의** — 실물과 대조해 발견한 오류를 표로. 어디서 틀렸고 어떻게 바로잡는지
8. **크롭 가능 영역** — 배경으로 발행할 수 있는 구간과 금지 구간. **한글이 있는 영역은 금지**
9. **HTML 이식 지침** — 요소별로 HTML 텍스트인지, CSS 재현인지, 새로 생성할 이미지인지
10. **따르지 않는 항목** — 목업이 그렇게 했어도 최종물에서 하지 않는 것

## 가이드를 쓰고 끝내지 않는다 — 가장 크게 실패한 지점

1회차에는 가이드를 잘 써 두고 **팔레트만 HTML 로 옮겼다.** 정보 카드, 아이콘, 번호 지시선,
지시선 pill, 치수선, 점선 강조, 컬러 스와치가 문서에만 있고 페이지에는 하나도 없었다.
페이지의 섹션 구조는 목업이 나오기 전에 짠 것 그대로였다. 색만 바뀌었으니 목업을 만든
20여 분이 사실상 버려졌고, "구성·아이콘·레이아웃 참고했냐" 는 질문에 아니라고 답해야 했다.

**가이드 §구성 요소를 회귀 테스트로 고정한다.** 문서로 적은 규칙은 지켜지지 않는다.

```js
// 클래스의 존재와 최소 개수를 검사한다
assert.ok(count(html, /<svg\b/g) >= 12, "아이콘을 이미지로 만들지 않는다");
assert.ok(count(html, /class="infocard/g) >= 3, "정보 카드가 없다");
assert.equal(count(structureSection, /class="co-num/g), 5, "번호 지시선 5개");
for (const cls of ["pin","inset","compare","chip","dim","trace","spec","trio","wave","snow"])
  assert.match(html, new RegExp(`class="[^"]*\\b${cls}\\b`), `${cls} 가 없다`);
```

목업이 고친 부위명·표현은 **HTML 에서 바로잡았는지도 테스트한다.** 실측에서 목업이 다섯째
부위를 "하단 밴드" 라고 잘못 적었고, 카드에 근거 없는 표현을 스스로 만들어 넣었다.

```js
assert.ok(html.includes("손가락 개구부") && !html.includes("하단 밴드"));
```

## 안전선

- 목업은 발행하지 않는다. `output/` 아래에 두지 않는다.
- 크롭해서 배경으로 쓸 때는 **한글이 없는 영역만** 쓴다.
- 목업 비율을 발행 컷에 그대로 적용하지 않는다. 목업은 페이지 전체를 한 장에 담은 것이고
  발행 컷은 섹션 안의 한 요소다. 비율 규칙은 `assets.md` 를 따른다.
- 실물에 없는 라벨·부품·인물이 목업에 들어왔으면 가이드에 오류로 적고 최종물에서 뺀다.
- 근거 없는 수치·인증·후기가 목업에 들어왔으면 같은 방식으로 뺀다.
- 목업 프롬프트에 넣은 사실은 플랜과 공급처 원문에서만 가져온다.
