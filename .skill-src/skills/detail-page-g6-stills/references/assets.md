# 이미지·GIF 제작

G2와 G3에서 읽는다. 기본 목표는 최종 페이지에 필요한 정지 이미지 약 30개와
GIF 약 10개다. 제품과 기준작에 따라 still 28~32개, GIF 8~12개 범위에서 AI가
중복 없이 조절할 수 있다.

## 이미지

내장 `god-tibo-gpt-image2-skill`의 `tibo-batch.mjs`만 사용한다. 별도 목적의
items를 한 job에 넣고 provider worker를 채워 한 번의 동시 batch로 실행한다.
Hero와 중요한 기능은 필요할 때만 대안 컷을 만든다.

각 item에는 다음을 지정한다.

- 섹션 역할과 고객에게 증명할 한 가지 내용
- 참조할 동일 SKU 사진과 유지할 제품 면·부품·수량·방향
- 제품 단독, 실제 사용, 구조 확대, 비교, 구성/규격 중 장면 유형
- 카메라, 배경, 조명, 제품 점유율, 허용되는 보조 효과
- 출력 폭 780px와 인접 이미지와의 차별점

AI 생성 이미지에는 한글을 넣지 않는다. 제품, 배경, 인물, 손, 사용 상황만 만들고
모든 한글 카피와 정확한 숫자·단위는 HTML 또는 검증된 영상 텍스트로 합성한다.

생성 결과는 Product Card와 나란히 비교한다. 제품 실루엣, 색, 비율, 구멍·버튼,
손잡이·끈·결합부, 로고·패턴, 구성품이 바뀐 컷은 사용하지 않는다. 배경과 조명은
바꿀 수 있지만 분위기를 성능 증거처럼 쓰지 않는다.

### 장면에 맞는 비율

폭 780px만 고정이고 높이는 장면이 정한다. 모든 컷을 한 비율로 뽑으면 배치 단계에서
CSS로 잘라내게 되고, 버려진 영역만큼 해상도와 구도를 낭비한다. 이미지 job을 만들기
전에 배치를 먼저 정하고 비율을 배정한다.

**기본은 정방형 780×780이다.** 아래 표에서 벗어날 이유를 대지 못하는 컷은 전부
정방형으로 만든다.

| 배치 | 권장 비율 |
| --- | --- |
| **기본 — 제품, 디테일, 사용 장면, 비교, 구성, 전후** | **정방형 (780×780)** |
| 카드나 카피를 위에 얹는 배경 플레이트 | 세로 (780×1040 기본, 780×1560은 예외) |
| 길이·거리·도달 범위를 보여주는 컷 | 가로 (780×440 등) |

세로를 남발하면 페이지가 통째로 늘어져 보인다. 실측: 세로 컷 10장을 전부
780×1560(1:2)으로 만든 페이지는 390px 모바일에서 한 컷이 화면 두 개 높이를 차지해
"이미지가 다 세로로 길다"는 지적을 받았다. 세로는 **카드를 얹어야 해서 높이가 필요한
플레이트에만** 쓰고, 그마저도 1:2가 아니라 780×1040(1:1.33)을 기본으로 한다.
1:2는 히어로처럼 화면을 통째로 먹어야 하는 한두 장에만 남긴다.

세로 컷은 인물을 가슴 아래로 잡는 경우가 많아 위아래에 빈 공간이 생기고, 그만큼 더
늘어져 보인다. 비율을 늘리기 전에 **제품이 그 높이를 실제로 채우는지** 먼저 본다.

`target_size`는 job 단위이므로 비율이 다르면 job을 나눠 실행한다. 이 제약 때문에 컷을
비율 버킷에 몰아넣기 쉬운데, 그 순서가 뒤집히면 안 된다. **정방형 job 하나를 기본으로
두고, 세로·가로가 꼭 필요한 컷만 따로 빼서 job을 추가한다.**

### 배경 플레이트

겹침 구성을 쓰기로 했다면 배경으로 쓸 컷을 **처음부터 배경용으로** 생성한다.
일반 컷을 배경으로 돌려 쓰면 제품이나 초점이 카드에 가려진다.

- 카드나 글자가 놓일 자리를 비운다. 어느 쪽을 비울지 프롬프트에 명시한다.
- 초점이 되는 피사체를 화면 가장자리로 밀고, 중앙은 톤만 남긴다.
- 대비를 낮추고 배경 노이즈를 줄인다. 위에 얹는 글자가 이겨야 한다.
- 배경 위 글자 색을 미리 정하고, 그 색이 배경의 밝은 부분과 어두운 부분 모두에서
  읽히는 톤인지 확인한다.

배경 플레이트도 공개 자산이면 still 수에 포함되고, HTML에서 참조하지 않으면
`ORPHAN_MEDIA`가 된다.

### 동일 구도 쌍은 레퍼런스를 이어붙인다

전후 비교, 모드 전환처럼 두 컷이 같은 프레임이어야 하는 쌍을 각각 독립 생성하면
카메라와 화각이 어긋나 비교가 성립하지 않는다. 반드시 순차로 만든다.

1. 기준이 되는 쪽(before, 기본 모드)을 먼저 생성하고 확정한다.
2. 그 결과 파일을 다음 job의 Image 1로 넣고, 카메라·화각·크롭·고정 요소의 픽셀
   위치를 그대로 재현하되 지정한 표면 상태나 분사 형태만 바꾸라고 지시한다.
3. 두 장을 위아래로 붙여 고정 요소가 같은 자리에 있는지 확인한다.

### 제품 위의 글자는 방향까지 잠근다

로고, 각인, 라벨은 위치만 잠그면 부족하다. 생성기는 글자를 화면 좌우 수평으로
눕히려 하기 때문에, 제품이 세로로 놓인 컷에서만 조용히 틀어진다.

- 글자가 제품의 **어느 축을 따라 읽히는지** 적는다. "제품의 긴 축을 따라
  뒤꿈치에서 앞코 방향으로 읽힌다"처럼 제품 기준으로 쓴다. 화면 기준으로 쓰면
  자세가 바뀔 때마다 틀린 지시가 된다.
- 그로부터 따라오는 결과를 한 문장 더 적는다. "따라서 제품이 세로로 서 있으면
  글자도 90도 돌아간다."
- 한 부품에 글자가 둘 이상이면 **서로 같은 방향**임을 명시한다. 같은 면에 인쇄된
  로고와 각인이 서로 다른 방향으로 나오는 것이 가장 흔한 실패다.
- 로고를 담은 도형에도 축이 있다. 타원이면 "제품이 세로면 타원도 세로로 길다"를
  함께 적는다.
- 오타나 비대칭 철자는 반전 여부를 눈으로 못 가린다. 읽는 방향을 글자 단위로
  적어 둔다.

### 교정 재생성은 다른 곳을 깨뜨린다

지적된 항목을 강하게 누르면 같은 컷의 다른 요소가 무너진다. 회전을 강제하자
같은 면의 각인이 좌우 반전으로 돌아온 사례가 있다.

- 교정본은 **원본과 같은 전체 점검을 다시 통과시킨다.** 고친 항목만 보지 않는다.
- 통과한 컷을 `work/ref/`에 넣어 다음 교정의 Image 1로 체인한다. 말로 다시
  설명하는 것보다 정확하다.
- 작은 글자가 반복해서 깨지면 **생략을 허용**한다. "이 크기에서 깨끗하게 못
  그리겠으면 아예 새기지 말라"가 반전된 글자보다 낫다.
- 한 컷을 안 두세 개로 동시에 뽑아 고르는 편이 순차 재시도보다 싸고 빠르다.

## GIF와 WebP

한 motion은 고객 질문 하나와 눈에 보이는 변화 하나만 맡는다. 정지 이미지로 충분한
정보에는 억지 motion을 붙이지 않는다. 약 10개 안에서 문제, 핵심 기능, 사용 과정,
비교·규격·구성을 제품에 맞게 배분한다.

기능에 맞는 움직임을 선택한다.

| 내용 | 적합한 변화 |
| --- | --- |
| 접기·설치 | 시작 → 조작 → 완료 |
| 수납·세척 | 전 상태 → 행동 → 결과 |
| 구조·소재 | 전체 → 부위 강조 → 설명 |
| 규격 | 가로/세로 측정 → 전체 수치 |
| 구성품 | 순차 등장 → 전체 정렬 |
| 사용법 | 단계별 상태 전환 → 완료 |

복잡한 장면은 HyperFrames의 결정론적 무음 MP4로 먼저 만들고 FFmpeg로 GIF와
animated WebP를 파생한다. 제품 자체를 생성형 모핑으로 움직이지 않는다. 고정된
제품 이미지 위 SVG, 마스크, 측정선, 콜아웃과 카드 애니메이션을 우선한다.

### 부품이 실제로 움직여야 할 때

펌프 손잡이, 뚜껑, 슬라이더처럼 제품의 한 부품이 움직이는 것 자체가 메시지인
motion이 있다. 이때도 같은 장면을 여러 장 생성해 교차시키지 않는다. 이미지 모델은
"구도만 유지하고 부품 위치만 바꿔라"를 지키지 못하고 매번 카메라와 배율을 다시
잡으므로, 프레임을 바꿀 때마다 제품이 커졌다 작아진다. `size_mode: "invariant"`도
픽셀 크기만 보존할 뿐 재구성을 막지 못한다.

기준 사진 한 장을 정하고 그 안에서 합성한다.

1. 움직일 부품과 그 부품을 잡은 손까지 포함하는 사각 영역을 정한다.
2. 같은 사진을 `background-image`로 쓰는 레이어를 그 좌표에 얹고 `x`/`y`로 옮긴다.
3. 원본에 남는 부품 자국은 배경색 패치로 덮고, 패치의 경계는 `mask-image`
   그라디언트로 지운다. 패치는 세로 이음매가 생기지 않도록 캔버스 전체 폭을 덮는다.
4. 이동으로 드러나는 축(펌프 봉 등)은 CSS 요소로 그리고 `scaleY`로 늘린다.
5. 자르는 높이는 움직이지 않아야 할 부품(헤드 상단, 밸브, 트리거) 바로 위에 둔다.

제품 본체와 인쇄 문구가 픽셀 단위로 고정되므로 드리프트가 원천적으로 생기지 않는다.

### 루프 등가

GIF는 마지막 프레임 다음에 첫 프레임이 온다. `t=data-duration`의 상태가 `t=0`과
같지 않으면 매 바퀴 눈에 띄게 튄다. 정성적인 "자연스러운 복귀"로 두지 말고 다음을
산술로 맞춘다.

- 모든 사이클 길이가 `data-duration`을 정확히 나눈다.
- 왕복 모션은 `yoyo: true`에 홀수 `repeat`을 써서 짝수 번 반전시킨다.
- 회전은 `data-duration` 동안 360의 정수배만 돈다.
- 한 방향으로만 차오르는 게이지·카운터·측정선은 사이클 끝에 시작값으로 되돌리는
  구간을 명시적으로 넣는다. 최댓값에서 끝내면 루프 경계에서 값이 급락한다.
- 마지막 구간에서 복귀시킨 요소는 `t=0`에서의 초기값과 같은지 프레임으로 확인한다.

### 고정 fps 하드 컷

프레임은 `n/fps` 시각에만 샘플링된다. 전환 구간이 그 시각에 걸치면 두 장면이 섞인
프레임이 남아 잔상처럼 보인다. 15fps 기준 한 프레임은 0.067초이므로, 장면을 바꾸는
`fromTo`는 **두 샘플 시각 사이에 완전히 가둔다**. 컷 지점 `i`에 대해 시작
`i - 0.05`, 길이 `0.04`면 `i - 0.067` 프레임은 이전 상태를, `i` 프레임은 다음
상태를 잡아 혼합 프레임이 생기지 않는다.

같은 시각에 놓은 zero-duration `set` 두 개로 장면을 바꾸지 않는다. seek 방향에 따라
적용 순서가 뒤집혀 전부 꺼진 검은 프레임이 나온다.

### GSAP `fromTo`의 즉시 렌더

`fromTo`는 `immediateRender`가 기본 `true`라 timeline 위치와 무관하게 **로드 시점에
from 값을 즉시 적용한다.** 뒤쪽 장면에 건 `fromTo`의 from 값이 첫 프레임을 덮어써
엉뚱한 장면이 보이거나 화면이 비는 원인이 된다. 위치가 `0`이 아닌 모든 `fromTo`에
`immediateRender: false`를 넣고, 초기 상태는 로드 시점의 `gsap.set`으로만 정한다.

### 오버레이 좌표

측정선, 콜아웃, 게이지 위치를 추정으로 쓰지 않는다. 완성된 배경 이미지를 실제로
열어 부품의 픽셀 좌표를 읽고 그 값으로 배치한 뒤, 렌더한 프레임에서 다시 확인한다.
제품이 프레임을 꽉 채워 치수선 여백이 없으면 배경 이미지를 캔버스 안에서
`transform: scale()`로 줄여 여백을 먼저 만들고 좌표를 그 배율로 환산한다.

### 모든 motion 공통 확인

- 첫 프레임부터 제품과 메시지가 보인다.
- 시작, 핵심 행동, 결과 또는 자연스러운 복귀가 있다.
- 손·소품·제품 크기와 위치가 이유 없이 튀지 않는다.
- 제품 색·형태·부품·비율·구성이 프레임마다 유지된다.
- 마지막 상태와 숫자가 정확하고 빈/검은 프레임이 없다.
- 780px canvas에서 한글, 점멸, loop, poster fallback이 정상이다.
- 첫 프레임과 마지막 프레임을 나란히 놓고 루프 이음매를 눈으로 확인한다.

## 병렬 제작

Planning agent가 still job과 GIF brief를 잠그면 이미지 provider batch를 즉시
시작한다. 공급처 사진만 필요한 motion은 이미지 생성과 동시에 진행하고, 생성 컷이
필요한 motion은 해당 컷이 통과하는 즉시 시작한다. sub-agent는 장면군 또는 motion
module을 나눠 제작하며 QA agent는 생산 session과 분리한다.

## 최종 미디어 QA

GIF의 배경으로만 쓰이고 페이지에 직접 걸리지 않는 원판은 `output/media/` 밖의 작업
폴더에 둔다. `qa --strict-media`는 `output/media/`의 모든 파일이 HTML에서 참조되기를
요구하므로, 원판을 함께 두면 `ORPHAN_MEDIA`로 실패한다. 공개 still 수도 이 기준으로
세므로 원판을 옮긴 뒤 28~32개 범위를 다시 확인한다.

- 파일이 실제로 열리고 계획한 섹션과 연결된다.
- 모든 정지 자산과 animation canvas가 780px 폭이다.
- GIF/animated WebP가 두 프레임 이상이며 poster-only가 아니다.
- 같은 주장을 still과 GIF로 연속 반복하지 않는다.
- 제품이 충분히 크게 보이고 사용 장면과 카피가 같은 내용을 말한다.
- 누락, 깨진 한글, 잘린 수치, 과도한 파일 크기를 수정한다.
