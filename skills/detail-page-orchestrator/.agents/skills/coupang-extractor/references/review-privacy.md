# 후기 개인정보와 권리

## 수집 허용 필드

- 순번, 별점, 적용한 별점 필터, 후기 본문, 선택 옵션, 작성일, 도움 수, 원본 페이지 번호, 중복 키, 미디어 개수

## 금지 필드

- 작성자 이름·닉네임·ID
- 프로필 이미지·링크·계정 링크
- 주문번호와 원본 후기 카드 HTML
- 쿠키·세션·토큰

DOM에서 후기 카드 구조를 찾더라도 작성자 노드는 payload를 만들기 전에 폐기한다. 디버그 출력에도 넣지 않는다. 본문에는 다음 패턴을 저장 전에 마스킹한다.

- 이메일 → `[REDACTED_EMAIL]`
- 휴대전화·일반전화 → `[REDACTED_PHONE]`
- `주문번호`, `order` 라벨 뒤 식별자 → `[REDACTED_ORDER]`

본문 동등성 키 `content_key`는 작성자 정보 없이 다음 정규화 값을 SHA-256으로 계산한다.

```text
rating | normalized_review_text | normalized_option | reviewed_at
```

동일한 내용·옵션·날짜의 서로 다른 공개 카드가 최신 100개에 함께 있을 수 있으므로 `dedupe_occurrence`를 1부터 부여하고 `dedupe_key`는 위 값 뒤에 occurrence를 붙여 계산한다. 보강 표본에서는 `content_key`별 최신 표본 개수를 multiset으로 차감해 실제 겹치는 수만 제외한다. 작성자나 내부 후기 ID는 이 구분에 사용하지 않는다.

후기 미디어는 기본 제외한다. `media_count`만 저장하며 이미지·영상 URL과 바이트는 수집하지 않는다. 모든 후기는 조사 참고 전용이고 광고 문구나 성능 사실로 자동 승격하지 않는다.

먼저 `모든 별점`과 `최신순`을 실제 선택·확인한 후기 최소 100개를 `latest_baseline`으로 저장한다. 그 뒤 최신 표본과 중복되지 않는 후기를 별점 필터로 수집해 `rating_stratified_supplement`로 구분한다. 보강 표본은 1·2점 합계 대 4·5점 합계를 2:1로 수집하고, 한 별점이 부족하면 같은 그룹의 다른 별점으로 재배분한다. 카드 자체 별점과 필터가 같은 후기만 저장한다. 3점은 최신 표본에는 포함될 수 있지만 2:1 보강 표본에서는 제외한다.
