# Codex 에서 실행

**순서는 여기 없다.** 게이트 순서·예산·거부 조건은 `scripts/lib/gates.mjs` 하나가
정의한다. 이 문서는 호스트 차이에서만 생기는 것 — 역할 배분과 lane — 만 다룬다.
Claude Code 쪽은 [`claude-code.md`](claude-code.md) 이고 **두 문서의 결과는 같아야 한다.**

이 문서가 없어서 이전 `SKILL.md` 에 **"호스트가 Codex 가 아니면 …"** 조건문이 생겼고,
그 조건문이 호스트별로 다른 읽기 순서를 허용했다. 대칭을 맞추는 것이 이 문서의 목적이다.

## 스킬 접근

Codex 는 `.agents/skills/` 를 읽는다. `detail-page-init` 이 `.skill-src/skills/` 원본을
여기로 연결한다 (junction 우선, 실패 시 복사).

`.agents/skills/` 를 직접 고치지 않는다. **생성물이다.** 다음 `init` 에서 덮어써진다.

`agents/*.yaml` 이 이 호스트의 카탈로그 항목이다. 실행 로직은 없다.

## 구동 호스트를 고정하지 않는다

어느 쪽에서 `start` 해도 되고 회차 중간에 바꿔도 된다. 공유 상태는
`<프로젝트>/work/gates.json` 하나뿐이다. 게이트마다 `by_host` 가 기록되므로 어느 단계를
누가 했는지 나중에 볼 수 있다.

## 인증은 이 호스트 쪽에 있다

이미지 생성은 `~/.codex/auth.json` 과 `~/.codex/installation_id` 를 읽는다.
**Codex 가 오케스트레이터일 필요는 없다** — 순수 node 라이브러리가 그 파일만 본다.
하지만 그 파일은 Codex CLI 가 소유하므로 로컬로 벤더링할 수 없다.

없으면 `codex login` 을 **사용자가** 한다. 내가 대신 하지 않는다.

## 역할 배분

| 역할 | 무엇을 받나 | 무엇을 돌려주나 |
| --- | --- | --- |
| **사실** | 공급처 캡처 · 실물 사진 | `work/SSOT.md` |
| **판독** | 기준작 캡처 | `work/flow-map.md` |
| **기획** | 위 둘 | 플랜 초안. **쪼개지 않는다** |
| **목업** | 플랜 · 실물 사진 · 무드 레퍼런스 | 목업 · 가이드 · 수확 계획 |
| **제작** | 발행 플랜 | 스틸 · 컴포지션 · GIF |
| **검수** | 완성물 | 판정. **생산자와 다른 세션에서** |

sub-agent 에 위임할 때 그 단계의 `SKILL.md` 와 `references/` 만 물려 보낸다.

## lane

```text
브라우저 lane = 1       (직렬 강제)
분석 lane   = 다수      (병렬)
생성 lane   = provider 동시성 그대로 (agent slot 과 별개)
```

## 이 호스트에서 조심할 것

| 함정 | 대응 |
| --- | --- |
| 파일 단위로 개별 지정해 위임하면 값만 채운 표가 돌아온다 | 무엇을 판단해야 하는지 함께 준다. 파일 목록만 주면 검사 대신 나열을 한다 |
| 이미지 provider 를 `codex-cli` 폴백으로 두면 `--size` 가 무시된다 | `private-codex` 를 쓴다. 폴백은 크기를 지원하지 않는다 |
| 인증 파일 내용을 로그·manifest 에 넣지 않는다 | 존재 여부만 확인한다 |

## 완료 어휘

`orchestrate report` 가 exit 0 이 아니면 **"완료" 라는 단어를 쓰지 않는다.**
게이트 표를 그대로 붙인다.
