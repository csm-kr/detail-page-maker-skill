# Commercial Effects and Immediate Claim Proof

상세페이지에서 이미지·GIF·그래픽 효과를 구매 판단에 직접 연결하는 실행 계약이다.
효과의 수가 아니라 `무엇이 달라졌는지 1초 안에 읽히는가`를 적극성의 기준으로
삼는다.

## 목차

1. 고객 화면 우선
2. 소구 직후 증명
3. 적극적인 이펙트
4. 패턴별 사용례
5. 배경 이미지 장면
6. 상품 구성
7. 금지와 QA

## 1. 고객 화면 우선

고객 화면은 제작 과정이 아니라 고객의 문제와 제품이 주는 변화를 말한다.

- `제조사 확인`, `MANUFACTURER_CLAIM`, `SSOT`, `ImageGen`, `God Tibo`,
  `HyperFrames`, `실물 구조를 기준으로 재구성`, `검수 완료`를 공개 카피에 쓰지
  않는다.
- 제조사 제공 기능은 내부 fact ledger에만 출처를 남긴다. 공개 화면에서는 제품
  장면, 고객 편익, 허용된 정성 변화로 번역한다.
- 이미지·GIF의 생성 방식은 manifest와 QA에만 기록한다.
- 고객은 `무엇으로 만들었는가`보다 `내 상황에서 무엇이 달라지는가`를 먼저 본다.

커머셜 문장은
[`commercial-copy-tone-guide.md`](commercial-copy-tone-guide.md)의
`상황 → 감정 → 변화 → 증거 캡션` 순서를 사용한다.

## 2. 소구 직후 증명

핵심 소구마다 다음 모듈을 하나의 결속 단위로 만든다.

```text
소구 헤드라인
→ 짧은 고객 편익
→ 전용 정지 이미지 또는 GIF
→ 무엇을 볼지 알려 주는 한 줄 캡션
```

- 소구와 증거 사이에 다른 주제의 섹션을 넣지 않는다.
- 후반에 `DETAIL PROOF`, `근거 모음`, `GIF 모음`을 따로 만들지 않는다.
- 같은 증거를 정적 이미지와 GIF로 연속 반복하지 않는다.
- 정적 이미지는 첫 상태·제품 전체·재질을, GIF는 비교·전환·사용 순서를 맡긴다.
- 소구-증거 거리는 최종 QA에서 `same-section | next-section | separated`로 기록하고
  `separated`는 실패다.

## 3. 적극적인 이펙트

적극적인 이펙트는 움직임의 양이 아니라 정보 상태의 선명한 변화다.

한 모듈에는 다음을 기본으로 한다.

- 주 효과 1개: 비교, 전환, 절차, 하강 막대, 구성 공개 중 하나
- 보조 효과 0~2개: 라이트 스윕, 윤곽선, 포인터, 카운트, 제한된 입자
- 결과 홀드: 전체 길이의 20% 이상

주 효과 없이 카메라 줌, 광선, 파동, 입자만 있으면 증거 GIF로 인정하지 않는다.
보조 효과가 제품보다 크거나 첫 메시지를 가리면 삭제한다.

## 4. 패턴별 사용례

### 슬라이드 비교

같은 카메라·축척·제품 위치의 두 상태를 화면 폭의 절반 이상 이동하는 와이프로
비교한다.

```text
상태 A 0.8초 홀드
→ 분할선·마스크 동기 이동
→ 50:50 비교
→ 상태 B 0.8초 홀드
```

타이트형↔루즈핏, 착용 전↔착용 후, 무거운 스타일↔가벼운 스타일처럼 차이가 한 축에
있을 때 사용한다.

### 하강 막대

근거가 정성 방향만 허용될 때 사용한다.

- 같은 기준선 위 두 막대를 먼저 보여 준다.
- 첫 막대는 `착용 전`, 두 번째 막대는 `착용 후`처럼 상태만 표시한다.
- 두 번째 막대가 명확히 낮아지고 꺾인 하강 화살표가 결과에 도착한다.
- °C, %, 시간, 시험기관, 정밀 눈금과 가짜 열화상 범례를 만들지 않는다.
- 실제 착용 이미지와 같은 화면 또는 바로 다음 화면에 둔다.

### 스타일 매치컷

같은 모델·같은 제품·같은 포즈를 유지하고 의상·장소만 전환한다.

- 얼굴·체형·헤어·손가락·제품 길이·라벨 위치를 고정한다.
- 옷차림마다 0.7초 이상 홀드한다.
- 디졸브만 하지 말고 옷 색 또는 배경의 형태를 이용한 매치컷을 사용한다.
- 스타일 변화가 제품 색·길이·주름 구조를 바꾸면 실패다.

### 길이 리빌

제품의 긴 실루엣이 구매 판단인 경우 상단부터 손등까지 한 번에 보이도록 마스크를
연다. 제품 자체를 늘이거나 왜곡하지 않는다. 마지막에는 전체 47cm 비례가 보이는
프레임을 홀드한다.

### 상품 구성 리빌

가장 정확한 한 쌍 이미지를 기준으로 다음 순서를 사용한다.

```text
한 제품 윤곽 확인
→ 두 번째 제품 공개
→ 두 제품에 짧은 라이트 스윕
→ `2장 / 1세트` 카운트 고정
```

빛, 윤곽선, 카운트는 실제 수량을 읽게 도울 뿐 제품을 추가하거나 구조를 바꾸지
않는다.

### 국소 강조

엄지홀, 라벨, 봉제선처럼 실제 좌표가 중요한 요소에만 사용한다. 라이트 스윕,
윤곽선, 포인터는 한 번 지나가고 결과 프레임에서 정지한다.

## 5. 배경 이미지 장면

몰입형 배경 이미지는 문제·스타일·피날레처럼 감정을 맡는 장에서 사용한다.

- 모델·제품의 반대쪽 빈 공간을 카피 안전영역으로 확보한다.
- 800px 기준 좌우 48~64px, 상하 72px 이상을 기본으로 둔다.
- 글자 뒤에는 방향성 그라데이션, 불투명 패널, 충분한 그림자 중 하나만 쓴다.
- 사진 위 카피는 헤드라인 1개와 짧은 보조 문장 1개를 넘기지 않는다.
- 제품 실루엣, 손, 엄지홀, 라벨, 얼굴을 글자로 가리지 않는다.
- 규격·주의사항·표는 배경 이미지 위에 올리지 않고 고대비 정보 장으로 분리한다.

## 6. 상품 구성

상품 구성은 상세 증거 갤러리가 아니라 구매 전 한 번에 확인하는 결정 장이다.

- 제품 동일성이 가장 좋은 한 쌍 이미지 하나를 사용한다.
- `화이트`, `2장`, `1세트`처럼 확인된 구성만 표시한다.
- 전면·후면·라벨·봉제 확대를 같은 화면에 모두 넣지 않는다.
- 상세 구조는 해당 소구의 즉시 증명 모듈로 이동한다.
- 표는 규격·구성·주의사항을 정확히 정리하는 역할로 유지한다.

## 7. 금지와 QA

다음은 하드 실패다.

1. 고객 화면에 제작 방식·근거 분류·승인 상태가 노출됨
2. 소구와 전용 증거 사이에 다른 주제가 끼어 있음
3. 페이지 후반에 여러 GIF를 한꺼번에 모은 proof 갤러리가 있음
4. 비교선은 움직이지만 실제 상태가 바뀌지 않음
5. 그래프가 임의 숫자·눈금·시험 조건을 만듦
6. 스타일 전환 중 모델 또는 제품 아이덴티티가 바뀜
7. 상품 구성 리빌에서 제품 수량·외곽·라벨이 달라짐
8. 배경 이미지 위 카피가 제품·얼굴·손을 가림
9. 카메라 줌·빛·입자만 있고 구매 판단 정보가 변하지 않음
10. `prefers-reduced-motion`에서 같은 주장을 이해할 포스터가 없음
