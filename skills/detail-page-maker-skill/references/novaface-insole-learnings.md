## 1. 적용 범위

도매꾹 `60851997` 노바페이스 발편한 기능성깔창을 실제 촬영 원본, 공급처 원문,
레거시 생성 이미지, HyperFrames GIF와 수정 가능한 HTML로 완성하며 얻은 규칙을
정리한다. 현행 신규 자산은 God Tibo를 사용한다. 제품 고유 문구와 구조는 다른
상품에 복제하지 않고 검수 방법만 재사용한다.

## 2. 제품 동일성

### 원본 역할을 분리한다

- 사용자가 촬영한 원본은 제품 사실과 부품 위치를 판단하는 `input`이다.
- 누끼와 다각도 복원본은 제품 형상을 잠그는 `ssot`다.
- 상용 연출 이미지는 SSOT를 참조한 파생 에셋이다.
- 거친 누끼와 촬영 배경을 그대로 광고 장면으로 쓰지 않는다.

### 한 제품도 면과 부품을 분리한다

노바페이스에서 다음 혼합이 반복 실패를 만들었다.

| 기준 | 보이는 요소 |
|---|---|
| 윗면 | 회색 에어메시, 회색 뒤꿈치 패치, 올라온 뒤꿈치 둘레와 안쪽 아치 |
| 아랫면 | 흰 PU 에어셀, 원형 에어홀, 뒤꿈치 중앙 블루쿠션 |
| 블루쿠션 문자 | 두 줄 `ZOOM SPORTS`, 쿠션과 제품 장축을 따름 |
| 흰 PU 각인 | 실제품의 `STORTS`, 임의로 SPORTS로 교정하지 않음 |

철자만 맞아도 통과가 아니다. 읽기 방향, 두 줄 순서, 부품 장축, 굽힘 뒤 원근과
표면 결합을 함께 비교한다.

## 3. 주장과 증거

한 부품에 한 주장, 한 주장에 한 전용 에셋을 연결한다.

| 주장 | 전용 증거 | 금지 |
|---|---|---|
| 에어홀 | 앞꿈치·중족부 원형 홀에서만 시작하는 공기 흐름 | 구멍 없는 블루쿠션에서 바람 시작 |
| 에어셀 | 흰 PU의 실제 비정형 다각 셀 홈 추적 | 규칙적인 육각형 도장, 블루쿠션 동시 강조 |
| 블루쿠션 | 아랫면 뒤꿈치 중앙 접점과 실제 파란 부품 확대 | 에어셀 명칭, 중족부로 위치 이동 |
| 유연함 | 사용자 승인 J자 휨 구도와 제품 외곽 곡률 | 제품 재생성, 인쇄를 가르는 자유 곡선 |
| 입체 굴곡 | 윗면 뒤꿈치 포켓과 보이는 측면 아치 경계 | 의료 교정, 압력 분산, 통증 완화 확대 |
| 사이즈 | 255mm에서 260 선택의 포인터 도착·눌림·결과 | 설명 카피와 GIF 결과 중복, 하단 빈 공간 |

구조의 존재가 성능 결과를 자동으로 증명하지 않는다. 공급처 근거가 구조까지면
카피도 `이어집니다`, `올라와 있습니다`, `굴곡을 따라갑니다`처럼 관찰 범위에서
멈춘다.

## 4. God Tibo 생성 이미지

1. 실제품 원본 여러 장을 참조해 제품의 전체 형태를 먼저 이해한다.
2. 누끼 SSOT와 윗면·아랫면 구조 지도를 함께 준다.
3. 상용 장면은 배경, 손, 신발 맥락과 조명을 개선하되 제품 형상을 새로 발명하지
   않는다.
4. 기존 GIF의 휨과 구도가 사용자 승인됐으면 피크 프레임을 첫 참조로 사용하고,
   실제품 사진은 문자·부품·표면 교정 참조로 둔다.
5. 고유 인쇄를 반복해서 틀리면 깨진 글자를 패치하지 않는다. 무문자 부품을 만든
   뒤 SSOT 글리프 SVG path를 제품과 같은 HyperFrames 그룹에 붙인다.
6. 손과 제품 접점의 자글거림, 손가락 수, 표면 노이즈와 인쇄 변형을 100% 확대해
   검사한다.
7. 한 이미지에서 제품의 여러 기능을 모두 설명하지 않는다. 소구별 거리와 구도를
   바꾼다.

## 5. GIF와 HyperFrames

기본 방식은 `hybrid`다. God Tibo로 명확한 start·middle·end를 만들고
HyperFrames로 결정적 변화를 저작한다.

### 한 GIF 한 변화

- 첫 프레임에서 대상 부품과 상태를 알 수 있어야 한다.
- 중간 프레임은 선이 지나가는 장식이 아니라 실제 변화가 보여야 한다.
- 마지막 프레임은 주장 결과를 0.6초 이상 읽을 수 있어야 한다.
- 루프 복귀 시 제품 위치와 밝기가 튀지 않아야 한다.

### 모든 증거 레이어는 제품과 함께 움직인다

셀 외곽, 아치 곡선, 인쇄 SVG, 접점 파동과 카메라를 하나의 `product-scene`
변환 그룹에 묶는다. 확대 중 선이 제품에서 미끄러지면 하드 실패다.

### 비교는 끝 상태를 보여 준다

윗면과 아랫면, 좌우 소재 비교는 양 끝 상태를 각각 홀드한 뒤 50:50으로 정리한다.
중앙에서 짧게 왕복하거나 단순 스캔선만 통과시키지 않는다.

### 모션 타이포

- HTML과 같은 글꼴 계열, 굵기와 색을 쓴다.
- 800×800 기준 상태 라벨 18px·700 이상에서 시작하고 390px 카드에서 다시 읽는다.
- 한글은 단어·조사·어미 중간을 끊지 않는다.
- 화살표와 포인터는 대상 중심에 도착한 뒤 눌림·리플·반발 순서로 반응한다.

## 6. 카피와 레이아웃

- 문제 질문은 세 개 이상 두고 뒤 섹션이 각각 답하게 한다.
- 후기처럼 읽히는 메시지는 별점, 실명과 구매 인증을 만들지 않고 서로 다른
  선택 이유를 맡긴다.
- `사용자 제공 실제품`, `생성 연출`, `공급처 기준`, 파일 버전과 QA 설명은
  고객 화면에서 제거한다.
- 사진 위 카피는 제품 실루엣과 겹치지 않고 안전영역과 대비를 확보한다.
- 말풍선 꼬리는 본체와 같은 불투명 색의 SVG 곡선으로 연결한다.
- 인접 섹션은 주장, 거리, 배경과 레이아웃 중 두 가지 이상을 다르게 한다.
- 같은 삽입 장면을 정적 이미지와 GIF로 연속 반복하지 않는다.
- 고객 용어는 `윗면`, `아랫면`, `에어홀`, `에어셀`, `블루쿠션`으로 고정한다.

## 7. Studio v1

노바페이스에서 유지할 편집 계약은 다음과 같다.

- 미리보기 기본 폭 360px
- 문구 저장 키는 DOM 순번이 아닌 `section ID + text layer ID`
- 이미지 저장 키는 `asset ID` 또는 `section ID + image layer ID`
- 사용자가 지정한 수정 HTML이 localStorage보다 우선
- 문구 변경 뒤 ResizeObserver와 MutationObserver로 iframe 높이를 다시 계산
- 자동 높이 오차 0~1px, 수동 `+100`은 정확히 100px, `딱 맞춤`은 0~1px 복귀
- CSS, 이미지와 GIF를 포함한 단일 HTML 내보내기
- 신규 에셋은 승인 작업면을 통과한 `approved` 경로만 교체 가능

Studio v2의 복잡한 작업 센터는 사용자 화면으로 실행하지 않는다. v1의 세 작업면인
`상세 편집 → 에셋 승인 → 최종 출력`만 활성 기준으로 사용한다. God Tibo, 제품
SSOT와 회귀 검사가 사용하는 확장 도메인·서버·런타임은 지원 라이브러리로 유지한다.

## 8. 재사용 체크리스트

1. 실제 원본을 변경하지 않고 `input`에 보존했는가
2. 누끼·다각도·표면 지도를 `ssot`로 승인했는가
3. 부품마다 이름·위치·면을 분리했는가
4. 주장마다 전용 이미지 또는 GIF가 있는가
5. God Tibo 결과가 SSOT의 형상·색·문자·결합과 무노이즈 품질을 보존하는가
6. GIF의 첫·중간·마지막에 같은 주장 하나가 읽히는가
7. 신규 에셋이 모두 pending에서 시작했는가
8. 사용자가 각 에셋을 승인 또는 반려했는가
9. HTML이 approved 경로만 새로 참조하는가
10. 360·800px, 자동 높이, 단일 HTML과 GIF 재생을 검수했는가
