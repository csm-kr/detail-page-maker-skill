# 상세페이지 GIF 모션 패턴 라이브러리

## 채택 범위

- 채택 상태: `ADOPTED`
- 근거 사례: `projects/domeggook-60851997` 깔창 상세페이지의 게시용 GIF 11개
- 적용 대상: 상세페이지용 800×800 증거 GIF의 패턴 선택, 레이어 구성, 타임라인, QA
- 적용 제외: 사례 상품의 카피, 색상, 부품명, GIF 개수, 타임라인 좌표의 직접 복제
- 되돌림 조건: 정적 이미지가 같은 주장을 더 명확히 증명하거나, 사용자 조작이 필요한
  비교 도구여서 GIF가 아닌 실제 인터랙티브 UI가 필요한 경우

이 문서는 특정 깔창의 모션을 다른 상품에 복사하기 위한 문서가 아니다. 실제 제품
근거에 맞는 움직임을 고를 수 있도록 구현 패턴만 추상화한 라이브러리다.

## 선택 순서

1. 먼저 `한 GIF가 증명할 주장 하나`를 적는다.
2. 시작 상태와 결과 상태가 실제로 다른지 확인한다.
3. 아래 질문에서 처음 맞는 패턴 하나를 기본 패턴으로 고른다.

| 질문 | 기본 패턴 |
|---|---|
| 같은 구도에서 두 재질·상태의 차이를 비교하는가? | `MOTION-COMPARE-WIPE` |
| 제품의 앞·뒤, 상면·하면처럼 물리적 반대 면을 공개하는가? | `MOTION-FACE-FLIP` |
| 제품의 실제 외곽·곡률·경로를 따라 설명해야 하는가? | `MOTION-STRUCTURE-TRACE` |
| 한 접점·구멍·발생 지점만 강조하는가? | `MOTION-LOCAL-EFFECT` |
| 수치 없이 상태가 내려가는 방향을 단계적으로 보여 주는가? | `MOTION-BAR-DROP` |
| 같은 제품이 서로 다른 옷차림에 자연스럽게 이어지는가? | `MOTION-STYLE-MATCH-CUT` |
| 입력값이 어떤 선택 결과로 이어지는지 설명하는가? | `MOTION-SELECTION` |
| 삽입·조립·설치의 시간 순서가 핵심인가? | `MOTION-PROCEDURE` |
| 판매 구성과 제품 전체를 상업적으로 공개하는가? | `MOTION-HERO-REVEAL` |

두 패턴이 필요해 보여도 하나를 주 패턴으로 둔다. 보조 효과는 주 패턴의 증거를
강화할 때만 추가한다.

## `MOTION-BAR-DROP` — 단계형 하강 막대

### 사용 조건

- 제조사 제공 기능의 방향은 공개할 수 있지만 수치·시험 조건은 제공되지 않았다.
- `높은 상태 → 낮아지는 흐름` 자체가 고객 이해에 도움이 된다.

막대 3~5개를 왼쪽에서 오른쪽으로 명확히 낮추고, 상단을 잇는 꺾인 하강선과
따뜻한 색에서 시원한 색으로 넘어가는 제한된 색 변화를 함께 사용한다. 숫자, °C,
퍼센트, 시험기관과 정밀 눈금은 만들지 않는다. 실제 제품 또는 착용 장면을 같은
화면에 유지해 추상 그래픽만 광고의 주인공이 되지 않게 한다.

### 하드 실패

- 막대 높이가 거의 같아 방향이 읽히지 않음
- 꺾은선만 흔들리고 시작·결과 상태가 분명하지 않음
- 근거 없는 수치·시험 결과처럼 보이는 축과 눈금이 추가됨
- 제품 없이 그래프만 남아 어떤 장점을 설명하는지 알 수 없음

## `MOTION-STYLE-MATCH-CUT` — 스타일 매치컷

### 사용 조건

- 같은 제품·같은 착용 범위를 유지하며 서로 다른 일상 옷차림의 조화를 보여 준다.
- 스타일 적합성이 핵심 장점이며 제품이 의상 전환 중 사라지거나 변형되지 않는다.

모델 포즈와 팔 위치를 고정하고 의상·배경만 2~4개 장면으로 매치컷한다. 제품의
길이, 위쪽 밴드, 엄지홀, 손등 라벨 위치를 전환 전후 같은 좌표에 가깝게 유지한다.
짧은 컬러 스윕이나 플래시를 전환 브리지로 사용할 수 있지만 착용 제품을 가리지
않는다.

### 하드 실패

- 장면마다 제품 길이·핏·색이 바뀜
- 위쪽 밴드가 꼬이거나 꽈배기처럼 겹침
- 손등 라벨이 손바닥·팔 안쪽으로 이동함
- 의상 전환보다 제품 정체 변화가 더 크게 보임

## `MOTION-COMPARE-WIPE` — 비교 슬라이더·와이프

### 사용 조건

- 두 상태가 같은 카메라, 크롭, 제품 위치를 공유한다.
- 차이가 공간적으로 겹쳐 있어 분할선 이동이 비교를 돕는다.
- 두 상태를 각각 홀드할 가치가 있다.

### 레이어

```text
compare-scene
├─ media-a
├─ media-b
├─ reveal-mask
├─ divider
├─ travel-indicator
└─ state-labels
```

### 타임라인

1. 첫 상태를 화면의 약 70~80%로 홀드한다.
2. 분할선과 마스크를 같은 값으로 화면 폭의 절반 이상 이동한다.
3. 반대 상태를 약 70~80%로 홀드한다.
4. 필요할 때만 50:50 비교 상태로 정리한다.

### 하드 실패

- 분할선만 움직이고 실제 노출 영역은 바뀌지 않음
- 두 이미지의 제품 위치·비율·원근이 달라 경계에서 점프함
- 중앙 근처에서 짧게 흔들려 양쪽 상태를 확인할 수 없음
- 시작·결과 라벨 없이 장식용 스캔처럼 보임

## `MOTION-FACE-FLIP` — 물리적 면 뒤집기

### 사용 조건

- 상면·하면, 앞·뒤처럼 실제로 반대 면인 두 자산을 공개한다.
- 회전축이 제품의 실제 뒤집기 방향과 맞는다.

### 레이어

```text
flip-scene
├─ face-a
├─ face-b
├─ axis-or-step
└─ state-label
```

### 타임라인

1. `face-a`를 충분히 보여 준다.
2. `rotationY: 0 → 88`과 약한 축소로 접어 숨긴다.
3. `face-b`를 `rotationY: -88 → 0`으로 펼친다.
4. 전환 중점에서 상태 라벨을 결과 면으로 바꾼다.
5. 결과 면을 홀드한다.

`90deg`의 완전한 엣지 상태를 길게 유지하지 않는다. 두 면이 동시에 보이거나
교차 용해처럼 겹치지 않게 한다.

### 하드 실패

- 앞면과 뒷면의 외곽·스케일이 달라 다른 제품처럼 보임
- 제품 수량이 전환 중 늘거나 줄어듦
- 회전축 없이 opacity만 교차해 물리적 뒤집기로 읽히지 않음
- 라벨은 바뀌었지만 실제 면은 바뀌지 않음

## `MOTION-STRUCTURE-TRACE` — 제품 추적 오버레이

### 사용 조건

- 제품의 실제 셀 외곽, 아치, 굽힘 곡선, 봉제선처럼 위치와 형상이 주장이다.
- 선이나 마스크가 제품 사진의 실제 구조를 따라가야 한다.

### 레이어

```text
product-scene
├─ product-media
├─ local-mask
├─ svg-outline-or-path
├─ scan-or-marker
└─ structure-label
```

제품과 모든 오버레이를 같은 `product-scene` 안에 둔다. 카메라 푸시, pan, scale,
rotation은 이 부모 그룹에만 적용한다. 오버레이 좌표는 제품 이미지의 로컬 좌표로
관리한다.

### 변형

- 외곽 추적: 실제 비정형 부품마다 별도 SVG path
- 곡선 그리기: `strokeDasharray`와 `strokeDashoffset`
- 순차 공개: scan → outline → label
- 상향 구조: 곡선 뒤에 제한된 화살표·리본

### 하드 실패

- 제품 확대 중 선이 구조에서 미끄러짐
- 실제 셀 대신 동일한 정육각형 아이콘을 반복함
- 한 GIF에서 서로 다른 두 부품을 동시에 확대·발광·라벨링함
- 구조의 존재만으로 교정·치료·압력 분산 같은 결과를 주장함

## `MOTION-LOCAL-EFFECT` — 국소 이펙트 올리기

### 사용 조건

- 실제 구멍, 접점, 버튼, 발밑처럼 효과의 시작 좌표가 명확하다.
- 이펙트가 제품 상태를 대신하지 않고 위치를 읽게 돕는다.

### 레이어

```text
effect-scene
├─ media
├─ target-zone
├─ pulse-or-ripple
├─ optional-path
└─ state-label
```

### 타임라인

1. 대상 부위가 보이는 포스터 상태
2. target zone을 짧게 확인
3. 실제 좌표에서 펄스·리플·파동 시작
4. 결과 상태 또는 위치 라벨 홀드
5. 효과를 줄여 포스터 상태로 복귀

### 하드 실패

- 구멍이 아닌 막힌 부품에서 공기·빛이 시작됨
- 접점이 아니라 부품의 기하학적 중앙에 리플을 둠
- 이펙트가 제품보다 커서 무엇을 강조하는지 모호함
- 광선·파동만 지나가고 시작과 결과의 의미가 같음
- 분위기 효과를 정량 성능이나 의료 효능의 증거처럼 사용함

## `MOTION-SELECTION` — 선택 규칙 인터랙션

### 사용 조건

- 입력값, 목표 옵션, 결과 규칙이 한 화면에서 이어진다.
- 실제 선택 절차를 짧게 시연하면 표보다 이해가 빨라진다.

### 타임라인

1. 입력값과 옵션을 먼저 모두 보여 준다.
2. 커서가 목표 카드 내부로 이동한다.
3. 2~4프레임의 눌림을 보여 준다.
4. 클릭 리플, 카드 활성색, 결과 라벨 순으로 바꾼다.
5. 입력값과 결과 사이 화살표를 그린다.

커서 중심, 클릭 리플, 활성 카드가 같은 좌표를 사용해야 한다. 값과 결과 사이의
화살표는 컨테이너 중앙이 아니라 두 텍스트 bounding box 사이의 시각 중앙에 둔다.

## `MOTION-PROCEDURE` — 사용 순서 가이드

### 사용 조건

- 삽입, 조립, 장착처럼 시간 순서를 빼면 오해가 생긴다.
- 실제 사용 장면과 방향을 근거 자산으로 확인할 수 있다.

### 타임라인

1. 준비 상태를 보여 준다.
2. 한 단계의 방향 가이드를 실제 대상 위에 표시한다.
3. 대상과 가이드가 같은 방향으로 이동한다.
4. 완료 상태와 다음 행동을 짧게 홀드한다.

한 화면에서 여러 화살표를 동시에 움직이지 않는다. 발이 들어간 신발에 깔창을
억지로 넣는 식의 물리적으로 불가능한 절차를 만들지 않는다.

## `MOTION-HERO-REVEAL` — 판매 구성 공개

### 사용 조건

- 기능보다 제품 전체, 수량, 구성품을 기억시키는 것이 목적이다.
- 실제 판매 구성과 제품 수량이 확정되어 있다.

카메라 푸시, 약한 링·빛, 짧은 구성 카피만 사용한다. 기능 이펙트나 존재하지 않는
부품을 추가하지 않는다. 제품 수량과 고유 인쇄가 첫·중간·마지막에서 유지되어야 한다.

정확한 시간은 장면에 맞게 바꾸되 다음 비율을 기본으로 한다.

| 구간 | 역할 |
|---|---|
| 0.0–0.8초 | 첫 프레임부터 읽히는 포스터 상태 |
| 0.8–1.8초 | 변화의 원인 또는 조작 시작 |
| 1.8–3.4초 | 핵심 동작과 증거 구축 |
| 3.4–4.2초 | 결과 상태 홀드 |
| 4.2–4.8초 | 갑작스러운 점프 없이 루프 정리 |

## 제작 전 체크

- 정적 사진보다 시간 변화가 주장을 더 잘 설명하는가?
- 시작 상태와 결과 상태의 이름을 한 문장씩 쓸 수 있는가?
- `claim_id`와 `component_id`가 각각 하나인가?
- 사용할 패턴이 실제 제품 근거와 맞는가?
- 제품, 오버레이, 커서, 라벨의 좌표계를 한 장면 그룹 안에서 관리할 수 있는가?
- 첫 프레임이 빈 화면이 아니라 포스터로 읽히는가?
- GIF가 상세페이지의 정적 이미지·카피와 같은 내용을 중복하지 않는가?
