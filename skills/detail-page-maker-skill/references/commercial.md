# 제품 근거·Flow Map·카피

G0와 G1에서만 읽는다. 목적은 지정 쿠팡의 판매 논리를 현재 제품에 맞게 빠르게
재구성하는 것이며, 경쟁시장 보고서를 만드는 것이 아니다.

## Product Card

실제 제품 사진이 있으면 identity의 최우선 기준이다. 없으면 공급처 동일 SKU의
사진을 쓴다. 사진 자체의 공개 사용 권리와 identity 참고 권리는 구분한다.

Product Card에는 실제 사용할 사실만 기록한다.

```yaml
identity: 실루엣, 색, 면, 부품, 수량, 문자, 방향
facts: 구성, 규격, 소재, 사용법, 주의사항
claims: 공급처 원문, 적용 조건, 공개 가능 여부
unknowns: 확인되지 않아 공개하지 않을 항목
```

사진으로 보이는 구조는 보이는 범위까지만 말한다. 제조사가 제공한 기능은 원문보다
범위를 넓히지 않는다. 성능, 인증, 의료 효과, 방수 등급, 지속 시간, 판매량, 순위,
별점과 후기는 확인 가능한 근거가 없으면 쓰지 않는다.

## Coupang Flow Map

지정 URL의 각 패널을 다음 형식으로 압축한다.

| 항목 | 기록할 내용 |
| --- | --- |
| role | 시선 확보, 문제, 해결, 원리, 증거, 사용, 옵션, 확신 |
| question | 고객이 이 패널에서 묻는 한 가지 질문 |
| copy_strategy | 결과 우선, 대조, 단계, 안심 등 문장 전략 |
| proof | 제품컷, 사용 장면, 비교, 구조 확대, GIF 등 |
| rhythm | 밀도, 여백, 색 전환, 다음 패널 연결 |
| adaptation | 현재 상품의 fact와 새 카피 |

Flow Map은 기준작 순서를 우선하되 현재 상품에 없는 기능은 복사하지 않는다. 필요하면
다음 범용 흐름으로 빈 곳만 보완한다.

```text
시선 확보 → 문제 공감 → 핵심 장점 → 작동 원리 → 시각적 증거
→ 사용 방법 → 옵션 선택 → 구매 확신
```

## 카피

- 특징보다 고객이 얻는 변화와 사용 장면을 먼저 말한다.
- 한 패널은 한 질문, 한 핵심 메시지, 한 주 시각만 담당한다.
- 헤드라인은 보통 1~3줄이며 마지막 줄에 핵심 결과가 남게 한다.
- 브라우저 자동 줄바꿈에 맡기지 말고 의미 단위마다 `<br>`을 명시한다.
- 조사와 명사, 숫자와 단위, 제품명과 옵션명을 서로 다른 줄로 찢지 않는다.
- 짧게 스크롤해도 제목과 주 시각만으로 장점과 증거가 함께 이해되어야 한다.
- 실제 후기가 아니면 작성자, 별점, 구매 인증이 있는 후기처럼 꾸미지 않는다.

예시:

```html
<h2>복잡한 설치 없이<br>끼우면 바로 사용</h2>
```

`강력한 내구성`처럼 검증이 필요한 말 대신 확인 가능한 경우 `두꺼운 구조와 보강된
마감`처럼 눈으로 증명할 수 있는 표현을 쓴다. 단, 안전 문구에 매몰되지 말고 확인된
장점은 고객 효익으로 분명하고 크게 말한다.

## 권리 경계

동일 SKU라도 다른 판매자가 만든 고유 사진, 그래픽, 문장, 후기의 사용 권리가
자동으로 생기지 않는다. 섹션 순서, 구매 질문, 카피 공식, 증명 방식과 리듬은
재구성할 수 있지만 권리 없는 원본 표현과 자산은 직접 복제하지 않는다.

## Lean Page Plan

여러 기획 문서를 만들지 말고 다음을 한 파일이나 구조화 artifact에 담는다.

- Product Card와 Coupang Flow Map
- 섹션별 고객 질문, 자사 카피, 연결 fact, 주매체
- 약 30개 still job: 역할, 장면, 제품 면, 배경, 조명, 점유율
- 약 10개 GIF brief: 질문, 시작/행동/결과, 변화, 길이, 배치
- 의미 단위 줄바꿈과 780px acceptance check

사용자 중간 승인을 기다리지 않고 이 계획에서 바로 제작을 시작한다.
