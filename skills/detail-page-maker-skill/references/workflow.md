# 제작 워크플로

## 목차

1. 입력
2. 공급처 근거
3. 제품 SSOT
4. 기획
5. 에셋
6. 조립
7. 게시

## 1. 입력

첫 입력은 실제 공급처 상품 URL 하나다. 상품번호가 있으면 프로젝트 ID에 사용한다. 이후 사용자가 제공한 실사진을 제품 사실 SSOT에 추가한다.

## 2. 공급처 근거

- 대표·상세 원본과 locator를 보존한다.
- 사진, 치수·재질·구조, 공급처 주장, 기획 단서를 분리한다.
- 가격·MOQ·옵션은 수집 시각이 있는 변동 정보로 취급한다.
- 로그인·캡차·OCR 추정값을 승인 사실로 올리지 않는다.

## 3. 제품 SSOT

우선순위:

1. 사용자가 촬영한 동일 SKU 원본
2. 공급처 원본
3. 승인된 제품 컷아웃
4. 승인된 ImageGen 파생 제품 뷰

생성 결과는 원본을 덮어쓰지 않는다.

## 4. 기획

기본 구매 서사:

```text
제품·가치 인지
→ 생활 상황과 문제
→ 제품 구조가 해결하는 방식
→ 구조·치수·재질 증거
→ 사용 장면
→ 선택·관리·구매 확인
```

핵심 소구는 `승인 사실 × 고객이 원하는 변화 × 시각 증명 가능성`으로 선정한다.

## 5. 에셋

- 제품 포함 이미지와 GIF는 개별 승인한다.
- 순수 배경·빛·입자는 묶음 승인할 수 있다.
- ImageGen은 승인된 제품 참조를 사용한다.
- HyperFrames 한 GIF는 한 주장만 설명한다.
- 재생성은 후보 한 개를 새 버전으로 만든다.

## 6. 조립

필수 에셋 승인과 해시를 확인한다. 조립 manifest에 실제 사용 버전을 기록한다. 조립 뒤 에셋·GIF는 읽기 전용이며 HTML 배치와 카피만 편집한다.

## 7. 게시

검토용 초안과 게시용 결과를 구분한다. 게시용은 97점 이상, 하드 실패 0건, 사용자 최종 승인이 필요하다.
