# 시작 전 인터뷰

새 상세페이지 제작 요청은 여기서 시작한다. 6항목을 받아내고 `brief`로 검증해
제작 프롬프트 하나로 굳힌 뒤에야 G0으로 들어간다. 인터뷰를 건너뛰고 공급처
URL만으로 제작을 시작하지 않는다.

## 받아야 할 6항목

| 항목 | 필수 | 합격 기준 |
| --- | --- | --- |
| 공급처 URL | 필수 | `http(s)` 로 시작하는 같은 SKU의 공급처 상품 페이지 |
| 쿠팡 URL | 필수 | `coupang.com` 호스트이고 경로에 `/vp/products/` 포함 |
| 실제 사진 | 선택 | 워크스페이스에 실재하는 폴더·`.zip` 경로. 없으면 `없음` |
| 브랜드명 | 필수 | 상세페이지에 그대로 노출할 이름 |
| 제품명 | 필수 | 카테고리 이름이 아닌 실제 판매명. 최소 두 덩어리 |
| 추가 의견 | 선택 | 이 제품에서 강조할 것·금지할 것. 없으면 `없음` |

## 진행 방식

1. 6항목을 한 번에 묻는다. 사용자가 이미 준 값은 다시 묻지 않는다.
2. 받은 값을 `brief.json`으로 적고 `brief` 명령에 넣는다.
3. `ok=false`면 명령이 돌려준 `followups`의 질문만 그대로 다시 묻는다. 스스로
   값을 지어내거나 "아마 이걸 뜻할 것"으로 넘겨짚지 않는다.
4. `ok=true`가 될 때까지 2~3을 반복한다.
5. 완성된 프롬프트를 사용자에게 한 번 보여 주고 확인을 받는다.
6. 확인받은 프롬프트를 이 run의 지시로 삼아 [`build-flow.md`](build-flow.md)의
   실행 순서로 들어간다.

확인은 5번 한 번뿐이다. 그 뒤로는 `.html` 산출물이 나올 때까지 되묻지 않고
스킬의 gate 정책대로 진행한다.

## 되물어야 하는 답

| 답 | 코드 | 다시 묻는 이유 |
| --- | --- | --- |
| "도매꾹에서 봤음" | `not_a_url` | 근거 수집기가 열 수 있는 주소가 아니다 |
| 스마트스토어·네이버 링크 | `not_coupang` | 따라갈 판매 논리의 기준은 쿠팡 상품 페이지다 |
| 쿠팡 검색·목록 링크 | `not_product_page` | 검색 페이지에는 뜯을 상세 구성이 없다 |
| "팔토시" | `too_generic` | 카테고리 이름이라 제목·카피의 기준이 되지 못한다 |
| 없는 `.zip` 경로 | `photos_not_found` | 있다고 적힌 원본이 실제로 없으면 plan-once fast path가 거짓이 된다 |
| 값에 섞인 `<!-- -->` | `unsafe_marker` | 프롬프트 템플릿의 블록 마커를 깨뜨린다 |

## 명령

```sh
node scripts/detail-page.mjs brief --input "<brief.json>" --json
node scripts/detail-page.mjs brief --input "<brief.json>" --output "<prompt.md>"
```

- `--input`은 파일 경로와 인라인 JSON을 모두 받는다.
- `--workspace`는 실제 사진 경로를 확인할 기준 폴더다. 기본값은 이 스킬이
  설치된 워크스페이스다.
- `--install-section`은 기본 `auto`다. `auto`는 의존성 폐포 검사가 통과하면
  `#1` 설치 절차를 빼고, 실패하면 붙인다. `include`·`omit`으로 고정할 수 있다.
- `--output` 없이 실행하면 프롬프트를 표준출력으로만 낸다. 워크스페이스 루트에
  프롬프트를 남기지 않는다.

## 프롬프트 계약

프롬프트 본문은 [`../assets/brief-prompt-template.md`](../assets/brief-prompt-template.md)
하나만 쓴다. 인터뷰로 받은 6항목만 자리표시자에 들어가고 기본 명령, 쿠팡
상세페이지 제작 핵심 팁 10항목, 안티패턴, 마감 코멘트는 매 run 같은 내용이다.

- 프롬프트를 손으로 적거나 팁 항목을 요약·생략하지 않는다.
- 사용자 답변 안의 `{{...}}`는 값으로 취급하고 두 번 치환하지 않는다.
- 실제 사진이 없으면 공급처 이미지를 제품 동일성 SSOT로 삼는다는 문장이
  자동으로 들어간다. 사진이 없다는 이유로 제작을 멈추지 않는다.
- 템플릿을 고칠 일이 생기면 `scripts/tests/brief-prompt.test.mjs`의 불변 블록
  검사를 함께 고친다.

## 안티패턴

- 인터뷰 없이 제작을 시작한다.
- 부족한 답을 그럴듯하게 보충해 `ok=true`를 만든다.
- 프롬프트를 보여 주지 않고 G0으로 넘어간다.
- 확인받은 프롬프트와 다른 지시로 제작한다.
