# 제품 SSOT·ImageGen 동일성 규약

이 문서의 모든 ImageGen 생성·편집은
`.agents/skills/god-tibo-gpt-image2-skill/scripts/tibo-batch.mjs`로만 실행한다.
새 장면은 `controllable`, 기존 장면 교정은 첫 참조를 Image 1로 둔
`invariant` 작업으로 기록하며 기본 배치 크기는 8장이다.

## 자산 위계

1. 사용자가 직접 수정하고 SSOT로 승격한 제품 참조
2. 사용자가 제공한 동일 SKU 실제품 촬영 원본
3. 공급처 원본
4. 동일성 검수를 통과한 ImageGen 상용 파생 소재

실제 촬영본은 기본적으로 소비자 화면에 바로 쓰는 완성 소재가 아니라 제품 정체성 기준이다. 거친 누끼, 촬영 책상, 비상업 조명은 공개 자산으로 자동 승격하지 않는다.

## 사용자 승격 SSOT

사용자가 생성·수정 이미지를 명시적으로 SSOT로 승격하면 다음을 manifest에 기록한다.

- 파일명과 승격 시각
- 사용자가 수정했거나 승인했다는 provenance
- 구조 판단에 사용할 역할
- 공개 페이지 직접 사용 여부
- 다른 원본과 충돌할 때의 우선순위

노바페이스의 `Flux2-Klein_00355_.png`는 측면 두께, 굽힘 곡선, 에어셀과 블루쿠션의 상대 위치를 판단하는 사용자 승격 SSOT다.

## 면 지도

| 면 | 반드시 보이는 구조 | 보이면 안 되는 구조 |
|---|---|---|
| 윗면 | 회색 에어메시, 회색 뒤꿈치 접촉 패치 | 블루쿠션, 아랫면 에어셀 |
| 아랫면 | 흰색 PU 입체 에어셀, 앞꿈치·중족부 에어홀, 뒤꿈치 중앙 블루쿠션 | 회색 힐 접촉 패치 |

## 명칭 레지스트리

- 둥근 입체 완충 구조: `에어셀`
- 실제로 뚫린 원형 구멍: `에어홀`
- 아랫면 뒤꿈치 중앙의 파란 고체 부품: `블루쿠션`
- 블루쿠션의 제품 인쇄: `ZOOM SPORTS`
- 흰 PU 본체의 양각: `STORTS`

`통풍홀`, `타공`, `구멍`, `블루 패드`, `힐 포인트`를 같은 페이지에서 혼용하지 않는다.

## 위치형 부품 검수

“뒤꿈치에 있다”만으로 승인하지 않는다.

- 전체 길이 대비 부품 길이
- 해당 구역 폭 대비 부품 폭
- 부품 바깥의 셀 테두리 여유
- 장축 방향
- 인접 에어홀과의 거리
- 다른 면에서의 노출 여부

한 장면에서 위치 오류가 발견되면 같은 구조가 나오는 모든 이미지·GIF를 다시 검사한다.

## 기능-구조 인과 지도

시각 효과는 실제 구조에서 시작해야 한다.

- 통풍 효과 → 앞꿈치·중족부의 실제 에어홀
- 쿠션 파동 → 에어셀 또는 블루쿠션
- 굽힘 곡선 → PU 본체
- 윗면 접촉 → 에어메시

구멍이 없는 블루쿠션에서 바람이 나오면 하드 실패다. 블루쿠션 표면과 가장자리에는 통풍 광선·입자·바람의 시작점을 두지 않는다.

### 인접 부품 역할 분리

- 에어셀과 블루쿠션은 모두 쿠션과 관련된 시각 언어를 사용할 수 있어도 하나의 부품으로 합치지 않는다.
- 에어셀 에셋은 흰 PU 본체의 입체 셀을 주인공으로 두고 블루쿠션은 비강조 상태로 남긴다.
- 블루쿠션 에셋은 뒤꿈치 중앙의 파란 고체 부품과 실제 접점을 주인공으로 두고 에어셀 전체를 기능 주체처럼 말하지 않는다.
- 한 이미지나 GIF의 제목, 활성 마스크, 파동 중심, 상태 라벨은 하나의 `component_id`와 일치해야 한다.
- 형태가 보인다는 이유만으로 지지력, 고정력, 교정, 압력 분산 결과를 생성 이미지가 증명한 것으로 처리하지 않는다.

## ImageGen 프롬프트 필수 블록

1. 제품 역할과 보이는 면
2. surface map의 보존 대상
3. 위치형 부품의 상대 비율
4. 고유 인쇄와 읽혀야 할 정확한 문자
5. 효과 시작점과 금지 영역
6. 카메라·조명·안전 여백
7. 바꾸면 안 되는 형상·색상·부품 수

## 승인 게이트

- 실루엣과 길이·폭 비율
- 윗면·아랫면 분리
- 에어셀과 에어홀 구분
- 블루쿠션 위치·크기
- `ZOOM SPORTS` 보존
- 사용 장면에서 물리적으로 올바른 면
- 첫·중간·마지막 프레임의 제품 동일성

하나라도 불확실하면 공개 자산으로 승격하지 않는다.

## 고유 인쇄 보존과 보정

- 고유 인쇄는 작은 장식이 아니라 제품 동일성이다. 한 소재에서 보존됐다고 다른 소재를 자동 승인하지 않는다.
- `ZOOM SPORTS`가 보여야 하는 에어홀·블루쿠션·유연함 장면을 각각 확대해 철자·줄 순서·방향·부품 안쪽 위치를 검사한다.
- ImageGen이 인쇄를 누락하거나 글자를 왜곡하면 우선 승인된 실제 부품 패치를 결과 이미지 안에 원근·각도·조명까지 맞춰 합성하거나 해당 장면을 다시 만든다.
- 패치도 원근·조명 경계가 어색하거나 ImageGen이 읽기 방향을 반복해서 뒤집으면, 깨진 글자를 지운 이미지를 쓰지 말고 해당 부품을 처음부터 무문자 상태로 다시 생성한다.
- 무문자 부품 위에는 SSOT 확대본의 글리프 외곽을 전용 SVG path로 재구성할 수 있다. 일반 폰트 텍스트는 금지하며, path는 제품 이미지·추적선과 같은 `product-scene` 안에서 동일한 scale·x·y·rotation을 받아야 한다.
- 정적 확대와 GIF 첫·중간·마지막 프레임에서 철자, 두 줄 순서, 뒤꿈치→앞꿈치 읽기 방향, 부품 안쪽 여백이 모두 같아야 한다. SVG를 썼다면 원본 확대 크롭과 path 접촉판도 함께 승인한다.

## 사용 상황 ImageGen 분리

- 사용 상황 하나마다 `신발 종류 / 장소 / 행동 / 조명` 중 둘 이상을 달리한다.
- 제품 동일성이 필요 없는 배경에는 제품을 생성하지 않는다. 군화·작업화·운동화·일상화 같은 무브랜드 신발만 보여 주고 제품 구조 주장은 인접 HTML·GIF가 맡는다.
- 생성 장수 목표는 각 장면이 다른 구매 질문을 답할 때만 의미가 있다. 같은 구도와 배경을 색만 바꾼 이미지는 장수로 세지 않는다.

## 좌우 한 쌍과 장축 인쇄

- 좌우 제품은 길이·외곽 실루엣·표면 패턴·부품 수가 같고 안쪽 아치만 좌우 거울 대칭이어야 한다.
- 윗면 한 쌍에서 두 제품 모두 같은 방향으로 파였거나 한쪽 아치가 사라지면 `duplicated-same-foot` 하드 실패다.
- 검수 접촉판에는 두 제품의 뒤꿈치 높이와 앞꿈치 끝을 맞춘 뒤 안쪽 아치가 중앙을 향하는지 표시한다.
- 제품 인쇄는 정확한 철자만으로 승인하지 않는다. 블루쿠션의 장축과 제품의 긴 방향을 따라 자연스럽게 휘거나 기울어야 한다.
- `ZOOM`과 `SPORTS`의 줄 순서, 글자 간격, 부품 안쪽 여백, 장축 각도를 확대 대조한다. 흰 PU 양각은 별도로 `STORTS`인지 대조한다.
- 굽힌 제품에서 흰 PU `STORTS`가 화면 수평으로 보이면 철자가 맞아도 실패다. 양각의 기준선이 굽어진 깔창의 긴 축과 원근을 따라야 한다.
- 사용 장면·제품 인셋·피날레처럼 제품이 작게 들어가는 곳에서도 길이 비율, 로고 방향, 장축 얼라인을 별도 검사한다.

## 부품별 문자 회귀 감사

- 블루쿠션의 `ZOOM SPORTS`와 흰 PU 본체의 `STORTS`는 서로 다른 검사 항목이다. 한쪽 통과로 다른 쪽을 승인하지 않는다.
- 금지 철자는 블루쿠션의 `ZZOM`·`ZZOOM`·`SIORTS`와 흰 PU의 `SPORTS`·`SIORTS`다. 현재 공개 HTML이 참조하는 파일과 GIF 첫·중간·마지막 프레임에서 하나라도 보이면 하드 실패다.
- ImageGen 교정 프롬프트는 `바꿀 문자`, `그대로 둘 구조`, `금지 철자`, `부품 장축 방향`을 별도 문장으로 쓴다.
- 폐기한 소재는 추적을 위해 남길 수 있지만 manifest의 `deprecated`에 기록하고 공개 HTML·CSS·HyperFrames composition 참조 수가 0인지 확인한다.

## 승인된 GIF 프레임을 구도 SSOT로 쓰는 교정

- 기존 GIF의 휨·손 위치·카메라·여백·효과 타이밍이 승인됐다면 애니메이션을 새로 상상하지 않는다.
- 해당 GIF에서 의도가 가장 잘 읽히는 프레임을 1번 참조 이미지로 추출하고, 그 프레임의 구도·포즈·휨을 잠근다.
- 실제품 사진은 2번 이후 참조로 넣어 로고, 각인, 부품 위치, 표면 질감, 손 디테일만 교정한다.
- ImageGen 프롬프트에는 `1번 이미지의 구도와 포즈 고정`, `실제품 참조는 디테일 교정 전용`, `HTML·SVG·HyperFrames 그래픽 제거`를 명시한다.
- 교정본에는 모션 카드·곡선·배지·캡션을 굽지 않는다. 기존 HyperFrames 레이어를 그대로 재사용해 편집성과 모션 일관성을 보존한다.
- 결과는 기존 GIF 프레임과 나란히 비교해 제품 실루엣·손 접점·휨 방향이 바뀌지 않았는지 먼저 보고, 그다음 로고와 미세 질감을 확대 검사한다.

## 맥락 카드의 제품 노출

- 사용 맥락 장면의 목적이 신발 종류·장소·행동이라면 제품 인셋을 의무로 넣지 않는다.
- 작은 제품 반복이 사진의 초점이나 카드 정렬을 흐리면 제거하고, 제품 동일성은 인접 제품 확대·GIF·구성 섹션으로 증명한다.
- 피날레나 실제 삽입처럼 제품 존재 자체가 메시지인 장면에서는 길이·로고·장축을 다시 검수해 제품을 유지한다.

## 로고 글리프 위상 게이트

- OCR 철자 일치만으로 고유 인쇄를 승인하지 않는다. 원본을 수평으로 회전한 확대 크롭을 만들고 글자별 외곽선, 내부 빈 공간, 열린 방향, 획 두께를 비교한다.
- `ZOOM`처럼 전용 글리프를 쓰는 인쇄는 일반 폰트로 다시 쓰지 않는다. 두 `O`가 왼쪽 열린 `⊃`형이라면 둘 다 같은 열린 방향과 간격을 유지해야 한다.
- 닫힌 사각형, `D`형, 괄호 조각처럼 글리프 위상이 달라지면 철자가 읽혀도 하드 실패다.
- ImageGen 교정은 전체 장면을 다시 만들기보다 `바꿀 잉크`, `보존할 제품 구조`, `정확한 글리프 형태`, `금지 형태`를 분리해 한 번에 하나만 수정한다.
- 로고가 작게 보이는 GIF용 원본도 3배 이상 확대 크롭으로 승인한 뒤 HyperFrames에 넣는다.

## 면 방향 노출 게이트

- 아랫면을 보여 주는 장면에서는 흰 PU·에어셀·에어홀·블루쿠션만 주 표면으로 읽혀야 한다. 긴 가장자리에 회색 윗면 원단이 넓게 노출되면 실패다.
- 윗면 원단은 물리적으로 불가피한 얇은 접합선만 허용한다. 넓은 회색 띠나 패턴이 보이면 흰 PU 가장자리 셀로 재생성한다.
- 굽힘 장면은 `현재 보이는 면`, `가장자리에서 허용할 면`, `숨길 반대면`을 ImageGen 프롬프트에 각각 명시한다.

## 입체 구조 모션용 키비주얼

- ImageGen 프롬프트에서 모션으로 추적할 구조를 먼저 지정한다. 예: `뒤꿈치 둘레`, `안쪽 아치 굴곡`, `흰 PU 다각형 셀`.
- 생성본 승인 시 전체 분위기보다 추적 구조의 위치·윤곽·면 방향을 먼저 실제품 SSOT와 비교한다.
- 윗면 아치 장면에는 파란 블루쿠션·아랫면 에어홀·제품에 없는 로고를 생성하지 않는다.
- 생성본 위의 HyperFrames 선은 눈으로 대충 배치하지 않는다. 800×800 승인 프레임에서 실제 구조 좌표를 기록하고 제품과 같은 transform 그룹으로 이동시킨다.
- 에어셀은 셀 중앙이 아니라 패인 홈을 따라 각 path 좌표를 기록한다. 규칙적인 육각형 복제보다 사진 속 비정형 다각형을 우선한다.
- 아치 장면은 눈에 보이는 뒤꿈치 포켓과 측면 경계만 추적한다. 제품 밖의 큰 원, 평평한 중앙부를 가르는 선, 근거 없는 상향 화살표는 만들지 않는다.
