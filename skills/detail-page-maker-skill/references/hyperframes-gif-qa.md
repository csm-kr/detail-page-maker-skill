# HyperFrames GIF·전후 비교 규약

## 목적

GIF는 장식이 아니라 바로 옆 주장에 대한 시간 기반 증거다. 한 GIF는 상태 변화, 사용 과정, 대응 관계, 데이터 변화 중 하나만 맡는다.

## 허용되는 모션 역할

- 제품 공개: 윗면 → 뒤집기 → 아랫면
- 전후 상태: 닿기 전 → 닿을 때
- 구조 흐름: 공기 유입 → 에어홀 통과
- 실제 동작: 굽힘, 삽입, 조립
- 선택 규칙: 발길이 입력 → 사이즈 선택
- 구성 확인: 좌우 한 세트
- 소재 비교: 윗면 강조 → 아랫면 강조

## 비교 하드 게이트

1. 시작과 결과의 상태명이 화면에 존재한다.
2. 제품 또는 정보 상태가 실제로 달라진다.
3. 움직이는 선·스캔·빛만 지나가고 상태가 같으면 실패다.
4. 전환 중에도 무엇이 바뀌는지 알 수 있는 축·화살표·단계가 있다.
5. 윗면·아랫면 비교는 물리적 뒤집기 또는 명시된 분할 비교로 보인다.
6. 같은 제품이 중복 생성되거나 면이 섞이지 않는다.

## 첫·중간·마지막 프레임

- 첫 프레임: 제품과 주장이 즉시 보인다. 빈 프레임·거의 투명한 제목을 허용하지 않는다.
- 중간 프레임: 변화의 원인이 읽힌다.
- 마지막 프레임: 결과 상태와 제품 정체성이 동시에 보인다.
- 루프: 마지막에서 첫 프레임으로 돌아갈 때 갑작스러운 흰 화면이나 제품 점프가 없다.

## 한글 타이포

GIF 안의 제목도 HTML과 같은 줄바꿈 규칙을 적용한다.

- 의미 덩어리마다 줄을 고정한다.
- `부 / 드럽게`, `따 / 라`, `넣어 / 주세요` 같은 분절은 하드 실패다.
- 800×800에서 제목은 보통 34~52px, 한 줄 8~16자를 우선한다.
- 800×800의 상태 라벨·화살표 문구·작은 설명은 18px 이상, 700 이상 굵기를 기본값으로 한다. 390px HTML 카드 안에서 축소된 실제 크기로 읽히지 않으면 크게 다시 렌더한다.
- 제품 위에 긴 제목을 얹지 말고 불투명 패널 또는 어두운 안전영역을 사용한다.
- HyperFrames의 폰트 패밀리·굵기 단계·색 토큰은 바깥 HTML과 같은 계열을 사용한다. GIF만 얇거나 다른 계열로 보이면 실패다.
- 두 줄 제목은 의미 단위뿐 아니라 실제 글리프 bounding box가 겹치지 않도록 line-height와 줄 간격을 검사한다.

## 구조 효과 좌표

- 공기 경로는 실제 에어홀 내부에서 시작한다.
- 블루쿠션에는 통풍 경로를 두지 않는다.
- 쿠션 파동은 블루쿠션 또는 에어셀의 접촉 지점과 중심이 맞아야 한다.
- 사이즈 커서와 활성 숫자, 안내 화살표는 같은 좌표 체계를 사용한다.
- 선택 포인터는 목표 카드 내부에 완전히 들어온 뒤 2~4프레임의 눌림을 보여 주고, 그 다음 활성색·결과 라벨이 바뀌어야 한다. 예시 값이 `260`이면 포인터 중심과 눌림 파동 모두 260 카드 안에 있어야 한다.
- 값→결과 화살표는 전체 컨테이너의 수학적 중앙이 아니라 왼쪽 텍스트 끝과 오른쪽 텍스트 시작 사이의 시각 중앙에 둔다. 양쪽 실제 간격을 bounding box로 비교한다.
- 점선 원·화살표·스캔선이 제품과 무관한 곳을 가리키면 실패다.
- 좌우 비교는 중앙에서 짧게 흔들지 않는다. 첫 상태를 한쪽 끝에서 홀드하고 분할선·커서가 화면 폭의 절반 이상을 이동해 반대 상태를 홀드한 뒤, 필요하면 50:50으로 정리한다.

## 인접 부품 의미 분리

- 한 GIF의 `claim_id`와 `component_id`는 각각 하나를 기본으로 한다.
- 같은 화면에 인접 부품이 보여도 활성 마스크·확대·파동·라벨은 주장 대상 부품에만 적용한다.
- 에어셀 GIF는 흰 PU의 입체 셀이 순차적으로 드러나고 높이·배열이 읽혀야 한다. 블루쿠션 접촉 파동을 재사용하지 않는다.
- 블루쿠션 GIF는 뒤꿈치 접촉 전후와 파란 부품의 위치를 보여 준다. 제목이나 상태 라벨에 에어셀을 쓰지 않는다.
- 다른 부품의 기존 GIF를 파일명과 카피만 바꿔 재사용하면 하드 실패다.
- 첫·중간·마지막 접촉판에 `주장 대상 영역` 오버레이를 별도 QA 레이어로 표시해 모든 강조가 같은 부품 안에 머무는지 확인한다. 이 QA 오버레이는 공개 GIF에 넣지 않는다.

## 제작·렌더 기준

- paused seek timeline
- full-duration clip
- 결정적 GSAP 속성
- transform·opacity 중심 모션
- `hyperframes check` 오류·경고 0
- 게시용 무음 무한 반복 GIF
- QA용 MP4와 첫·중간·마지막 프레임 접촉판

## 페이지 내 중복 감사

GIF 수가 많아도 별도 `제목 + 정사각 GIF` 섹션을 반복하지 않는다.

- 기능 설명 안에 GIF를 통합할 수 있으면 통합한다.
- 인접 GIF는 역할·제품 거리·배경·레이아웃 중 둘 이상이 달라야 한다.
- 정적 사진으로 충분한 정보는 움직이지 않는다.
- 같은 제품 각도와 같은 카피가 연속되면 하나를 제거하거나 역할을 바꾼다.

## 승인 증거

- 3프레임 접촉판
- GIF 프레임 수·길이·SHA-256 manifest
- 브라우저에서 실제 `.gif` currentSrc
- 시간차 스크린샷 해시 변화
- 제품 동일성 표
- 비교 상태 라벨과 실제 변화의 대응

## 제품 인쇄 회귀 게이트

- 고유 인쇄가 있는 부품은 GIF 첫·중간·마지막 프레임에서 모두 확인한다.
- ImageGen 배경에 인쇄가 빠졌을 때는 승인된 실제 부품 패치를 이미지 픽셀에 합성하거나 소스를 다시 만든다.
- 일반 폰트의 DOM·SVG 텍스트로 제품 인쇄를 대체하는 방식은 금지한다. 예외는 무문자 부품 위에 SSOT 글리프를 전용 SVG path로 재구성하고 제품과 같은 `product-scene`에 넣은 경우다.
- SVG path 예외를 썼다면 `글리프 외곽·열린 방향·두 줄 순서·뒤꿈치→앞꿈치 읽기 방향·부품 장축·안쪽 여백`을 원본 확대본과 비교하고 첫·중간·마지막 프레임 모두 통과해야 한다.
- 에어홀·블루쿠션·유연함처럼 동일 부품이 반복되는 장면은 각각 검사한다. 한 장면만 통과해도 전체 통과로 처리하지 않는다.

## 중복 시연 병합

- 동일한 사용법을 정적 사진과 GIF가 연속 설명하면 한 섹션으로 합친다.
- 삽입처럼 시간 변화가 핵심이면 GIF만 남기고, 제목·설명은 HTML에서 한 번만 제공한다.
- FAQ나 표처럼 펼쳐서 한눈에 보는 것이 우선인 정보는 사용자가 요청하면 초기 `open` 상태로 제공한다.

## 제품 장축·착화 장면 게이트

- 고유 인쇄가 있는 제품은 정적 원본과 GIF 첫·중간·마지막에서 같은 철자·줄 순서·장축 방향을 유지한다.
- 굽힘 장면의 곡선은 제품의 실제 휘어지는 윤곽 위쪽에 놓고 제품을 가르지 않는다. 선만 움직이고 제품 형상이 읽히지 않으면 실패다.
- 군화·작업화·운동화·일상화는 각 신발을 실제로 착화한 행동 장면으로 보여 준다. 벗어 둔 신발만 보이면 사용 증거로 세지 않는다.
- 착화 후 편안함은 발광만으로 과장하지 않고 `신발 안에 제품이 들어감 → 자연스러운 보행 → 발 아래의 제한된 파동` 순서로 표현한다. 치료·통증 제거·수치 개선을 암시하지 않는다.

## 제품 문자 렌더 회귀 게이트

- 블루쿠션은 정확한 `ZOOM SPORTS`, 흰 PU 본체는 정확한 `STORTS`를 첫·중간·마지막 프레임에서 각각 확인한다.
- 블루쿠션의 `ZZOM`·`ZZOOM`·`SIORTS`, 흰 PU의 `SPORTS`·`SIORTS`가 보이는 프레임은 즉시 폐기한다.
- 굽힘 곡선의 오목·볼록 방향은 실제 제품 굽힘과 같아야 하고, 선은 제품 구조를 가리지 않는다.
- 결과 정보바가 늦게 등장해 하단을 비워 두면 첫 프레임부터 유지하거나 다른 정보로 공간을 채운다.
- HyperFrames `check --strict`의 lint·runtime·layout·contrast 오류와 경고를 모두 0으로 만든 뒤 MP4와 GIF를 렌더한다.
- 이미 승인된 GIF의 움직임을 교정할 때는 대표 프레임을 구도 SSOT로 추출하고 ImageGen에는 제품 디테일만 수정시킨다. HyperFrames 타임라인·곡선·텍스트 레이어는 동일하게 유지한 뒤 전·후 접촉판으로 모션 회귀를 확인한다.
- 접촉·쿠션 이펙트의 원과 파동은 부품 중앙이 아니라 실제 접지광과 뒤꿈치 접점의 중심에 둔다. 대표 프레임을 확대해 이펙트 중심과 접점의 픽셀 오프셋을 측정하고 0에 가깝게 보정한다.
- 굽힘 GIF의 제품 문자는 철자뿐 아니라 각 프레임에서 제품 장축과 함께 회전·원근 변형되는지 확인한다. 화면 수평으로 고정된 `STORTS`는 하드 실패다.

## 굽힘 GIF 면·로고 회귀 게이트

- 아랫면 굽힘 장면의 첫·중간·마지막 프레임에서 회색 윗면 원단이 긴 띠로 노출되지 않는지 확인한다.
- 블루쿠션 인쇄는 철자뿐 아니라 원본 글리프의 열린 방향과 내부 빈 공간까지 확대 비교한다. 일반 폰트로 보정한 로고는 승인하지 않는다.
- 로고 확대 크롭, 전체 제품 프레임, 5프레임 GIF 접촉판을 함께 저장한다.
- 제품 프레임을 교체한 뒤 `hyperframes check`를 다시 통과시키고, 최종 GIF의 크기·프레임 수·길이·SHA-256을 manifest에 갱신한다.

## 제품 추적 오버레이 그룹 게이트

- 제품 이미지 위에 셀 외곽·아치 곡선·접점·스캔선을 얹고 카메라 푸시를 줄 때 제품만 확대하지 않는다.
- 제품 이미지와 그 위의 모든 추적 오버레이를 하나의 `product-scene` 그룹에 넣고 같은 scale·x·y·rotation을 적용한다.
- 첫·중간·마지막 프레임에서 오버레이와 제품 구조의 픽셀 오프셋을 비교한다. 중간 프레임에서만 선이 미끄러져도 실패다.
- 육각형 에어셀은 정육각형 아이콘을 복제하지 않는다. 실제 셀마다 보이는 비정형 외곽을 별도 SVG path로 따고, 선이 셀 경계 밖으로 나가지 않게 확대 캡처로 승인한다.
- 에어셀 장면은 흰색 PU 셀만 확대·발광·윤곽 처리한다. 블루쿠션은 프레임 밖으로 빼거나 비활성 상태로 남기고 강조선·라벨·공기 이펙트를 붙이지 않는다.
- 에어셀 path는 돌출 면의 중앙이 아니라 셀 사이의 패인 홈을 따라야 한다. 대표 프레임에 100px 좌표 그리드를 얹어 각 꼭짓점을 기록하고 렌더 접촉판에서 다시 겹쳐 본다.
- 아치 GIF는 뒤꿈치 포켓과 눈에 보이는 측면 굴곡만 추적한다. 제품 밖 원형 펄스, 임의의 상향 화살표, 평평한 중앙부를 가르는 장식선은 하드 실패다.
- 제품 인쇄와 구조 곡선이 겹치면 구조 곡선을 실제 외곽 쪽으로 옮긴다. 증거선이 제품 문자를 가리는 상태는 통과시키지 않는다.
- 루프 첫 프레임은 제품·헤드라인·결과바가 함께 읽히는 포스터 상태여야 한다. `fromTo` 진입 모션을 쓰더라도 첫 프레임 opacity를 0으로 두지 않는다.
