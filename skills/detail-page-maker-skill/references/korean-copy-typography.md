# 한글 카피·타이포·말풍선 QA 규약

## 제목 줄바꿈

- 한 줄은 의미 덩어리 8~16자를 우선한다.
- 명사와 조사, 어간과 어미, 복합어 중간을 자르지 않는다.
- 2줄 제목은 `상황 또는 원인 / 결과 또는 편익` 구조를 우선한다.
- 3줄이 필요하면 각 줄의 역할이 달라야 한다.
- 자동 `text-wrap: balance`에만 맡기지 않고 핵심 제목은 `<br>`로 의미 단위를 고정한다.

### 실패 예시

- `발이 닿는 면은 부 / 드럽게`
- `발의 움직임을 따 / 라`
- `노바페이스를 넣어 / 주세요`

### 통과 예시

- `발이 닿는 면은 부드럽게 / 바닥은 탄탄하게`
- `발의 움직임을 따라 / 유연하게`
- `기존 깔창은 빼고 / 노바페이스를 넣어주세요`

## 카피 위계

1. eyebrow: 분류·순서·기능명
2. headline: 한 화면의 구매 이유
3. support: 근거가 허용하는 짧은 설명
4. label: 제품 부품·수치·단계

한 화면에서 서로 다른 큰 문장 두 개가 경쟁하지 않게 한다.

## 상업 어투

- 생활 상황을 먼저 말하고 바로 제품 구조로 답한다.
- 제작 메타, 검수 과정, 원본 보존 설명을 소비자 카피에 쓰지 않는다.
- 근거 없는 최상급, 치료·교정·완치, 수치 개선을 만들지 않는다.
- 합성 공감 문장은 실제 후기처럼 따옴표·별점·신원을 붙이지 않는다.
- `실물 그대로`, `원문 기준`, `ImageGen 연출`은 research와 manifest에만 둔다.

## 문제 질문

최소 3개의 질문을 사용하되 뒤 섹션에서 실제로 답할 수 있어야 한다.

- 질문: 신발 안이 더 답답해지지 않을까?
- 답: 에어메시와 앞꿈치·중족부 에어홀
- 질문: 두꺼워서 신발이 꽉 끼지 않을까?
- 답: 기존 깔창을 빼고 넣는 사용법
- 질문: 어떤 사이즈를 골라야 할까?
- 답: 발길이 기준 사이즈 선택

## 사진 위 글자

- 제품 실루엣과 제목 bounding box가 겹치지 않는다.
- 밝은 사진에는 충분한 어두운 그라데이션 또는 불투명 패널을 쓴다.
- 작은 설명을 복잡한 사진 위에 직접 올리지 않는다.
- 360px에서 본문 13px, 주요 설명 15px, 제목 35px 수준을 하한으로 검토한다.

## 말풍선

- 꼬리는 회전한 사각형이 아니라 SVG 곡선 path로 만든다.
- 말풍선 본체와 이어지는 어깨는 넓고, 끝으로 갈수록 부드럽게 가늘어진다.
- 꼬리의 그림자는 본체와 같은 방향을 유지한다.
- 왼쪽·오른쪽 말풍선은 단순 미러링할 수 있지만 질문 배치와 제품을 가리지 않는지 다시 확인한다.
- 꼬리가 본체에서 떨어지거나 점·꼬리 중심이 어긋나면 실패다.
- 본체와 꼬리는 같은 불투명 단색으로 칠한다. `rgba` 반투명 면이 겹쳐 접합부만 진해지면 실패다.
- 꼬리 SVG의 시작 부분을 본체 아래로 1~2px 겹치되 색상과 그림자 방향은 같게 유지한다.
- 접합부에 1px 헤어라인이 보이면 path에 본체와 같은 색의 stroke를 주고 3~6px 겹쳐 안티앨리어싱 틈을 닫는다.

## 소비자용 면 명칭

- 공개 카피·alt·GIF 라벨은 `윗면 / 아랫면`을 사용한다.
- `상면 / 하면`은 내부 구조표·개발 키로만 사용할 수 있다.
- 한 페이지 안에서 `TOP / UPPER / 윗면`을 큰 제목으로 혼용하지 않는다. 영문은 작은 분류 라벨에만 두고 한국어 명칭을 주어로 삼는다.

## 후기처럼 읽히는 소구 메시지

- 실제 후기 표본이 없으면 별점·실명·구매 인증·구매자 출처를 만들지 않는다.
- 대신 섹션 성격을 `사용 장면으로 보는 선택 이유`처럼 밝히고, 승인된 제품 소구를 자연스러운 1인칭 편익 문장으로 쓴다.
- 최소 3개 메시지가 서로 다른 구매 이유를 맡는다. 예: 오래 서는 날의 포근한 지지, 에어홀을 통한 통기, 발길이 기준의 쉬운 사이즈 선택.
- `좋았어요`만 반복하지 말고 `상황 → 구조 또는 선택법 → 편익`을 한 문장 안에 넣는다.
- 따옴표는 장식으로만 쓸 수 있으며 실제 인용처럼 보이는 작성자·별점·날짜와 결합하지 않는다.

## 반응형 증거

320·360·390·768·800px에서 다음을 확인한다.

- 단어 중간 분절
- 고아 한 글자
- 제품과 제목 겹침
- 카드 내부 잘림
- 말풍선 꼬리와 본체 연결
- 부모 `overflow:hidden`에 가려진 텍스트

## 편집 가능한 말풍선·박스 레이어

- 말풍선은 본체, 텍스트, SVG 꼬리를 하나의 그룹으로 저장하되 각각 독립 layer ID를 가진다.
- inspector에서 본체의 `x/y/width/height/radius/fill`, 텍스트의 정렬·크기·행간, 꼬리의 방향·끝점·곡률을 수정할 수 있게 한다.
- 꼬리 시작점은 본체 경계에 종속시키고 끝점만 이동하게 해, 본체를 옮겨도 접합부가 벌어지지 않게 한다.
- 텍스트·GIF·이미지 박스에는 안전영역, 8px 그리드, 인접 요소 edge/center 스냅을 제공한다.
- GIF 박스는 위치·크기·crop·`object-position`·poster·재시작을 바꿀 수 있게 하고, 타임라인 자체 편집은 HyperFrames 원본으로 연결한다.
- 편집 결과는 DOM 순서가 아니라 안정된 layer ID와 section ID에 저장하며, 320·390·800px별 오버라이드를 분리한다.

## HTML과 GIF의 타이포 동기화

- GIF 제목·라벨·설명은 바깥 HTML과 같은 한글 폰트 스택과 색·굵기 토큰을 사용한다.
- 큰 제목은 900~950, 상태 라벨과 작은 설명은 700 이상을 기본으로 하고 390px 카드 안의 실제 축소 크기로 읽는다.
- 폰트 파일이 없을 때는 HTML과 HyperFrames가 같은 검증된 로컬 fallback 순서를 사용한다. 한쪽만 다른 fallback으로 렌더링하지 않는다.
- 굵기를 높인 뒤에는 line-height를 함께 다시 측정한다. 두 줄의 글리프 bounding box가 겹치면 시각적으로 괜찮아 보여도 실패다.
- 밝은 사진 위 작은 문구는 불투명 패널 또는 충분한 어두운 배경을 사용해 WCAG AA 대비 경고를 0으로 만든다.
