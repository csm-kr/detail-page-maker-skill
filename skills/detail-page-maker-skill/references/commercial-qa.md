## 검사

- 제품 고유 문자는 HTML 검색만 하지 말고 실제 이미지 픽셀과 GIF 프레임에서 확인한다.
- 고유 인쇄를 SVG path로 재구성했다면 일반 폰트가 아닌 SSOT 글리프 외곽인지, 제품과 같은 변환 그룹인지, 뒤꿈치→앞꿈치 읽기 방향과 두 줄 순서가 맞는지 검사한다.
- 같은 레이아웃이 연속 반복되지 않게 한다.
- 의미 있는 구매자 텍스트는 모바일에서 14px 미만으로 두지 않는다.
- 기능 효과는 실제 구조에서 시작해야 한다.
- 각 공개 `claim_id`는 승인된 `fact_id`, 직접 근거 `evidence_asset_id`, 실제 `section_id`를 가져야 한다. 하나라도 비면 하드 실패다.
- 한 에셋을 에어셀과 블루쿠션처럼 서로 다른 부품의 직접 증거로 중복 등록하지 않는다. 공통 제품 전체컷도 고객 HTML에서는 한 번만 사용하고 기능 증거는 부품별로 둔다.
- 생성 장면을 독립 시험 결과처럼 쓰지 않는다. 출처가 고정된
  `MANUFACTURER_CLAIM`의 정성적 설명 이미지·GIF는 허용하되, 숫자가 없으면
  정성 그래프에 임의 눈금·온도·비율·시간을 넣지 않는다.
- 제작 메타, 가짜 후기 출처, 근거 없는 효능 표현을 구매자 화면에서 제거한다.
- 고객용 iframe·검토 캡처·게시 HTML에서 `구매 질문`, `확인 근거`, `DESIGN RULE`, `REVIEW`, `DRAFT`, `SSOT`, `REV-`, `ImageGen`, `HyperFrames`, 에셋 ID·버전·경로, `제작 예정`을 검사한다.
- 위 문자열은 Studio 제어 화면과 프로젝트 기록에는 허용하지만 고객 화면에서 하나라도 보이면 하드 실패다.
- 검토본도 고객 화면과 동일한 콘텐츠 면을 사용한다. `display:none`으로 제작 메타를 고객 DOM에 남겨 통과시키지 않는다.

## 360px 정사각 광고 캡처 게이트

- CSS 뷰포트 폭을 정확히 360px로 고정하고 `scroll-behavior: auto` 상태에서 장면별 절대 위치를 기록한다.
- 한 장 안에 핵심 카피와 제품·사용 장면이 함께 완결되도록 선택한다. 제목·문장·제품이 프레임 가장자리에서 잘리면 위치를 다시 잡는다.
- 원본 360×360 브라우저 캡처를 먼저 보존한 뒤 Lanczos로 1000×1000 PNG를 만들고, 같은 이미지에서 JPG를 파생한다.
- PNG 9장과 JPG 9장은 모두 1000×1000인지 자동 검사하고 3×3 접촉판으로 글자 겹침, 로고, 크롭, 장면 중복을 최종 확인한다.
- 모바일 섹션이 세로로 길어 카피와 제품을 한 화면에 담을 수 없으면 동일 360px 렌더의 인접 카피·제품 영역만 연결한다. 다른 장면이나 다른 제품을 합성하지 않는다.
