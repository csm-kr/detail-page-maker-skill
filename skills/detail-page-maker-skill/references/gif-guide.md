# GIF Production Guide

이 문서는 상세페이지 GIF의 필수 제작 순서와 프로젝트 간 학습을 누적하는 실행
가이드다. 새 상세페이지를 시작할 때 먼저 읽고, 작업을 마칠 때 프로젝트 학습 원장에
반드시 한 항목을 추가한다.

## 목차

1. 문서 라우팅
2. 프로젝트 필수 산출물
3. GIF 필요성 판정
4. 제작 순서
5. 패턴 선택
6. HyperFrames 구현 계약
7. QA와 상세페이지 삽입
8. 프로젝트 종료 학습
9. 프로젝트 학습 원장

## 1. 문서 라우팅

이 파일은 전체 제작 순서와 누적 규칙만 소유한다. 상세 구현과 긴 QA 목록을
중복하지 않고 다음 문서로 라우팅한다.

| 필요 | 읽을 문서 |
|---|---|
| HyperFrames 원본·레이어·렌더 계약 | [`hyperframes.md`](hyperframes.md) |
| 슬라이더·뒤집기·추적 오버레이 등 패턴 선택 | [`gif-motion-pattern-library.md`](gif-motion-pattern-library.md) |
| 첫·중간·마지막 프레임과 제품 동일성 QA | [`hyperframes-gif-qa.md`](hyperframes-gif-qa.md) |
| 상용 장점 직후 증거와 적극적 FX | [`commercial-effects-and-claim-proof.md`](commercial-effects-and-claim-proof.md) |

GIF를 새로 만들거나 수정할 때는 이 파일을 읽은 뒤 위 세 문서를 작업 단계에 맞게
읽는다. 정적 이미지만 사용하는 상세페이지도 프로젝트의 `planning/GIF.md`에 GIF를
쓰지 않은 이유를 기록한다.

## 2. 프로젝트 필수 산출물

새 프로젝트는 `planning/GIF.md`를 가진다. 프로젝트 초기화 스크립트가 템플릿을
자동 생성하며, GIF가 없더라도 삭제하지 않는다.

프로젝트의 각 GIF 계획에는 다음 필드를 채운다.

```text
gif_id
section_id
claim_id
component_id
fact_id
motion_required
motion_reason
start_state
end_state
pattern_id
claim_fx
outer_copy
inner_copy
source_assets
product_ssot
forbidden_claims
composition_path
render_path
poster_path
qa_report
approval_status
```

- `motion_required`: `yes | no`
- `pattern_id`: 패턴 라이브러리의 `MOTION-*` ID
- `claim_fx`: 주장과 직접 연결된 주 효과 1개 이상
- `outer_copy`: 상세페이지에서 고객 편익을 설명하는 문장
- `inner_copy`: 상태·단계·수량만 남긴 짧은 GIF 내부 라벨
- `source_assets`: 실제 제품·승인 이미지·배경을 역할별로 기록
- `approval_status`: `planned | rendered | qa_passed | user_approved | assembled`

한 GIF는 `claim_id` 하나와 `component_id` 하나를 기본으로 한다. 서로 다른 부품을
한 GIF가 동시에 증명하게 하지 않는다.

핵심 장점은 정지 이미지로 소개한 직후 전용 GIF로 증명한다. 완성된 GIF를 페이지
뒤쪽 증거 갤러리에 다시 모으지 않는다. 비교 와이프·쿨 스윕·스타일 매치컷·길이
공개·구성 공개·치수 위치 가이드는 주장에 맞을 때 적극 사용한다. 모든 GIF에는
주장과 직접 연결된 주 효과가 최소 1개 있어야 하며, 이펙트만 남고 제품 변화가
읽히지 않는 모션은 실패다.

상세페이지 외부 카피와 GIF 내부 문구는 역할을 나눈다. 외부는 고객 상황과 편익을
설명하고, 내부는 `TIGHT / LOOSE`, `3 STEP`, `2 PCS`, `약 47 cm` 같은 짧은
상태·단계·수량 라벨만 둔다. 같은 문장을 안팎에서 반복하지 않는다.

## 3. GIF 필요성 판정

다음 중 하나가 참일 때만 GIF를 계획한다.

- 시작 상태와 결과 상태의 차이가 구매 판단에 필요하다.
- 사용 순서를 정지 이미지 한 장으로 설명하면 오해가 생긴다.
- 제품의 실제 외곽·접점·경로를 시간 순서로 따라가야 구조가 읽힌다.
- 입력값과 선택 결과의 관계를 짧은 시연으로 설명해야 한다.

다음은 정적 이미지로 남긴다.

- 제품 전체 모습이나 판매 수량만 확인하면 충분한 경우
- 움직이는 장식이 없어도 주장과 증거가 이미 명확한 경우
- 효과의 시작점이나 결과 상태를 실제 제품 근거로 확인할 수 없는 경우
- 모션이 성능·치료·효능을 과장하게 되는 경우

GIF를 쓰지 않기로 한 판단도 `planning/GIF.md`에 `motion_required: no`와 이유를
기록한다.

## 4. 제작 순서

### 4.1 주장과 상태 잠금

1. 상세페이지의 `claim_id → component_id → fact_id → section_id` 연결을 확인한다.
2. GIF가 답할 구매 질문을 한 문장으로 쓴다.
3. 시작 상태와 결과 상태를 각각 한 문장으로 쓴다.
4. 모션이 없으면 확인할 수 없는 차이를 적는다.
5. 금지할 확장 주장과 오해를 적는다.
6. 주장과 직접 연결된 주 FX를 하나 이상 이름 붙인다.
7. 외부 카피와 중복되지 않는 내부 상태 라벨을 잠근다.

시작·결과를 이름 붙일 수 없거나 실제 상태가 달라지지 않으면 GIF를 만들지 않는다.

### 4.2 패턴 선택

[`gif-motion-pattern-library.md`](gif-motion-pattern-library.md)의 선택 표에서 주 패턴
하나를 고른다.

- 같은 구도의 두 상태 비교: `MOTION-COMPARE-WIPE`
- 상면·하면 또는 앞·뒤 공개: `MOTION-FACE-FLIP`
- 실제 외곽·곡률 추적: `MOTION-STRUCTURE-TRACE`
- 접점·구멍·발생 지점 강조: `MOTION-LOCAL-EFFECT`
- 입력값에서 옵션 선택: `MOTION-SELECTION`
- 삽입·조립·설치 순서: `MOTION-PROCEDURE`
- 판매 구성 공개: `MOTION-HERO-REVEAL`

두 패턴을 섞기 전에 주 패턴 하나만으로 충분한지 먼저 확인한다.

### 4.3 자산 준비

1. 실제 동일 SKU의 제품 SSOT를 확인한다.
2. 제품이 포함된 승인 이미지와 순수 배경을 분리한다.
3. 제품, 배경, 텍스트, 상태 라벨, 선·화살표, 이펙트를 독립 레이어로 계획한다.
4. 제품의 로고·인쇄·부품·표면·수량이 확인되는 프레임을 기준 이미지로 저장한다.
5. 효과가 시작할 실제 좌표나 추적할 실제 외곽을 표시한 QA 오버레이를 준비한다.

완성 GIF 픽셀을 제품 사실의 원본으로 사용하지 않는다. 승인된 GIF의 구도·휨·타이밍은
후속 교정의 모션 참조로 사용할 수 있지만 제품 디테일은 실제 SSOT로 다시 검증한다.

### 4.4 컴포지션 작성

1. 편집 가능한 HyperFrames HTML 원본을 만든다.
2. seek 가능한 paused timeline 하나를 등록한다.
3. 첫 프레임에 제품·주장·상태가 모두 보이는 포스터 상태를 둔다.
4. 중간 프레임에서 변화의 원인이나 조작을 보여 준다.
5. 마지막 프레임에서 결과 상태와 제품 정체성을 함께 홀드한다.
6. 루프 복귀 때 흰 화면, 제품 점프, 텍스트 깜박임을 없앤다.
7. 장식 FX만 움직이지 않게 하고 `claim_fx`가 제품 상태·비교·절차·좌표를 바꾸거나
   읽게 만드는지 확인한다.

제품 위 오버레이를 쓸 때는 제품과 모든 추적 레이어를 같은 `product-scene` 그룹에
넣는다. scale, x, y, rotation은 이 부모 그룹에 적용해 선·리플·스캔이 제품에서
미끄러지지 않게 한다.

### 4.5 검사와 렌더

1. 프로젝트 지침에 지정된 HyperFrames 명령으로 `check --strict`를 통과한다.
2. 첫·중간·마지막과 핵심 변화 프레임의 접촉판을 만든다.
3. 실제 제품 SSOT와 프레임을 확대 비교한다.
4. 사용자에게 최종 컴포지션 미리보기를 승인받는다.
5. 승인 뒤 QA용 MP4와 게시용 무음 무한 반복 GIF를 렌더한다.
6. GIF를 생성 방식이 포함된 이름으로 `asset/generated/pending/gif`에 저장한다.
7. poster, 프레임 수, 길이, 파일 크기, SHA-256을 manifest에 기록한다.
8. manifest에 `claim_fx`, `outer_copy`, `inner_copy`, 규격 GIF라면
   `measurement_axis`, `start_anchor`, `end_anchor`를 기록한다.

기본 방식은 `hybrid`다.

```text
03-flex-hybrid-v01.gif
03-flex-imagegen-seq-v01.gif
03-flex-heygenframe-v01.gif
```

사용자 승인 뒤에만 `asset/generated/approved/gif`로 이동한다. 반려본은
`asset/generated/rejected/gif`에 보존하고 수정본은 새 버전으로 pending에 만든다.

검사가 통과해도 사용자 승인 전에 게시용 렌더를 확정하지 않는다.

## 5. 패턴 선택

패턴별 레이어 구조, 타임라인과 하드 실패는
[`gif-motion-pattern-library.md`](gif-motion-pattern-library.md)가 소유한다.

제작자는 해당 상품의 실제 제품 근거에 맞는 패턴만 선택하고, 사례 상품의 색·카피·
좌표·부품명·GIF 개수를 복제하지 않는다.

## 6. HyperFrames 구현 계약

다음은 모든 패턴의 공통 불변식이다.

- 800×800 정사각형을 기본으로 사용한다.
- 한 컴포지션에는 결정적 timeline 하나만 둔다.
- 네트워크, 실시간 시계, 무작위 값을 사용하지 않는다.
- 제품 레이어는 승인된 SSOT와 버전에 묶는다.
- 움직이는 요소는 레이어·그룹·시작·종료·위치·scale·opacity를 기록한다.
- 텍스트는 상세페이지 HTML과 같은 한글 폰트·굵기·색 체계를 사용한다.
- 첫 프레임의 제목과 결과 정보가 투명 상태로 시작하지 않는다.
- 제품 인쇄를 DOM·SVG 텍스트로 덮어씌워 교정하지 않는다.
- 정량 시험 근거가 없는 냉감·열감은 그래프·막대·꺾은선·가짜 열화상 범례로
  표현하지 않고 승인 실착 위 쿨 스윕·공기 흐름·제한된 서리 입자로 표현한다.

## 6.1 위치형 규격 GIF 잠금

길이·폭·높이처럼 제품의 어느 구간인지 알아야 하는 규격이 있으면 규격표 바로 위에
치수 위치 GIF를 반드시 만든다.

- 승인된 제품 전체 이미지에서 실제 시작점과 끝점을 각각 고정한다.
- 측정선·끝단 캡·치수 라벨을 같은 축으로 애니메이션한다.
- 제품 외곽과 시작·끝점이 4px 이상 떨어지거나 반대 축을 가리키면 실패다.
- 공급처가 `약`으로 표기한 규격은 GIF에도 `약`을 유지한다.
- 제품을 늘이거나 줄여 숫자에 맞추지 않는다.
- 규격표의 바로 앞 모듈에 배치하며 페이지 끝의 별도 증거 모음으로 보내지 않는다.

구체적인 원본 보존과 렌더 계약은 [`hyperframes.md`](hyperframes.md)를 따른다.

## 7. QA와 상세페이지 삽입

게시 전 다음을 확인한다.

1. 한 GIF가 한 주장과 한 부품만 설명한다.
2. 시작·중간·마지막에서 제품 수량·실루엣·부품·인쇄가 유지된다.
3. 비교선·커서·경로·리플이 실제 대상 좌표와 함께 움직인다.
4. 이펙트가 다른 부품이나 빈 배경에서 시작하지 않는다.
5. 시작과 결과의 상태명이 실제 화면 변화와 일치한다.
6. 390px 상세페이지 카드 안에서도 제목·상태 라벨을 읽을 수 있다.
7. 정적 이미지와 같은 설명을 연속으로 반복하지 않는다.
8. GIF는 바로 옆 주장과 결속되고 별도 장식 섹션처럼 고립되지 않는다.
9. `prefers-reduced-motion`에서는 poster 또는 설명력 높은 정지 상태를 제공한다.
10. 실제 게시 HTML의 `currentSrc`가 승인된 버전 없는 GIF 경로를 가리킨다.
11. 모든 핵심 장점 뒤에 대응 GIF가 있고, 페이지 끝의 중복 증거 갤러리는 없다.
12. 첫 프레임만 보아도 제품과 증명할 차이가 읽히며 이펙트가 제품보다 먼저 보이지 않는다.
13. 주장과 연결된 주 FX가 1개 이상 있고 장식 FX만으로 구성되지 않는다.
14. 상세페이지 외부 카피와 GIF 내부 문구가 같은 문장을 반복하지 않으며 내부 문구가
    상태·단계·수량 중심으로 더 짧다.
15. 정량 근거가 없는 냉감·열감 GIF에 그래프·막대·꺾은선·가짜 열화상 범례가 없다.
16. 위치형 규격이 있으면 규격표 바로 위 치수 위치 GIF가 있고 시작·끝점이 승인
    제품 외곽과 일치한다.

전체 하드 게이트는 [`hyperframes-gif-qa.md`](hyperframes-gif-qa.md)를 따른다.

## 8. 프로젝트 종료 학습

상세페이지 작업을 완료하기 전에 다음 절차를 반드시 수행한다.

1. 프로젝트의 `planning/GIF.md`, GIF manifest, 접촉판, 최종 HTML을 읽는다.
2. 사용한 패턴, 성공한 점, 실패 원인, 실제 수정, 재사용 조건을 정리한다.
3. 아래 프로젝트 학습 원장에 새 항목을 추가한다.
4. 기존 규칙과 같으면 중복 문장을 추가하지 않고 기존 규칙의 근거 프로젝트를 보강한다.
5. 기존 규칙과 충돌하면 바로 덮어쓰지 않고 충돌 조건과 적용 범위를 함께 기록한다.
6. 특정 상품의 색·카피·좌표·제품 사실은 일반 규칙으로 승격하지 않는다.
7. GIF가 없었던 프로젝트도 `GIF 사용 없음`과 정적 이미지가 더 적합했던 이유를 기록한다.

프로젝트 학습 항목은 다음 형식을 사용한다.

```markdown
### YYYY-MM-DD — <project_id> — <상품명>

- 상태: `GIF 사용 | GIF 사용 없음`
- 사용 패턴: `MOTION-*`
- 근거 경로: `<project>/planning/GIF.md`, `<manifest>`, `<qa report>`
```
