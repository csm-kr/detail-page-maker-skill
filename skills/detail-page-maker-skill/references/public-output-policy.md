# 고객용 상세페이지와 제작 메타데이터 분리 정책

상태: 필수 정책 / 모든 기획·미리보기·HTML·GIF·내보내기·QA에 적용

## 세 가지 출력 영역

1. **고객 화면**: 상세페이지 iframe, 공개 미리보기, 이미지·GIF, 검토용 고객 화면, 게시 HTML
2. **Studio 제어 화면**: 로드맵, Inspector, 승인 상태, 누락 자산, QA, 페이지 이동
3. **프로젝트 기록**: `planning/`, manifest, JSON, 프롬프트, 로그, 해시, 출처 원장

고객 화면에는 구매자가 상품을 이해하고 결정하는 데 필요한 내용만 둔다. 제작 과정과 승인 판단에 필요한 정보는 Studio 제어 화면이나 프로젝트 기록에서만 관리한다.

## 고객 화면 금지 정보

다음 문구나 같은 의미의 제작자용 표기를 고객 화면의 보이는 텍스트, 이미지, GIF, `alt`, `title`, `aria-label`에 넣지 않는다.

- `구매 질문`, `확인 근거`, `DESIGN RULE`, `기획 의도`, `비중복 이유`
- `COMMERCIAL REVIEW`, `DESIGN REVIEW`, `DRAFT`, `검토본`, `페이지 검토`
- `에셋`, `asset_id`, 파일명, 경로, 버전 번호, SHA-256
- `SSOT`, `REV-001`, 모델 후보·모델 버전, 승인·보류·QA 점수
- `ImageGen`, `HyperFrames`, 프롬프트, 렌더 승인, 키프레임
- `장면 레퍼런스 제작 예정`, `이미지 준비 중`, 자리표시자
- 적용한 `.md` 문서명, 내부 정책명, 생성 시각, 작업자 메모

안정적인 `data-layer-id`, `data-section-id` 같은 비가시 편집 식별자는 허용한다. 단, 사용자에게 보이는 문자열이나 접근성 이름으로 노출하지 않는다.

## 고객 화면에 허용되는 근거

근거라는 내부 분류명은 숨기되 구매 결정에 필요한 사실은 자연스러운 소비자 언어로 보여 준다.

- `화이트 한 쌍`
- `공급처 표기 47 × 14cm`
- 실제 구성·옵션·재질·원산지·주의사항
- 실제 제품 구조를 설명하는 `손등 커버`, `안쪽 엄지홀`
- 출처 표시가 법적·구매 판단상 필요한 수치·시험·인증

`확인 근거`라는 제목 아래 내부 증거 문장을 그대로 붙이지 않는다. 사실은 관련 제품 사진·도해·규격표 가까이에 고객용 카피로 다시 쓴다.

## 미완성 자산 처리

- 고객 화면 안에 제작 예정 카드나 빈 회색 자리표시자를 넣지 않는다.
- 승인 자산이 없으면 해당 모듈을 숨기거나 승인된 실제 제품 자산으로 상업적으로 완결된 대체 구성을 만든다.
- 누락 자산, 예정 역할과 제작 상태는 Studio 로드맵·Inspector에서만 보여 준다.
- 미승인 GIF 키프레임을 완성 모션처럼 고객 화면에 넣지 않는다.
- 고객용 카피가 `7개 GIF`처럼 아직 완성되지 않은 수량을 단정하지 않게 한다.

## 검토 화면 계약

검토본도 고객이 보게 될 화면과 동일한 콘텐츠 면을 사용한다.

- 페이지 번호, 승인 버튼, 누락 자산, 구매 질문, 주장-근거 ID는 iframe 밖 Studio UI에 둔다.
- iframe 안에는 최종 고객 화면에 남을 카피·제품·시각 요소만 둔다.
- 제작 메타데이터를 숨기기 위해 `display:none`으로 고객 DOM에 남겨 두지 않는다. 프로젝트 JSON과 Studio UI로 이동한다.
- 검토용 장식을 제거해야만 상용 화면이 되는 구조를 금지한다.

## 하드 QA

다음 중 하나라도 발견되면 상용 점수와 무관하게 실패다.

1. 고객 화면에서 제작자용 문구가 보임
2. 이미지·GIF 픽셀 안에 제작 메타데이터가 구워짐
3. `alt`, `title`, `aria-label`에 내부 파일명·버전·상태가 노출됨
4. 누락 자산 자리표시자가 공개 화면에 남음
5. 검토 화면과 게시 화면의 콘텐츠 면이 달라 검토 승인 의미가 사라짐

QA는 고객 화면의 렌더 캡처와 공개 HTML 텍스트를 모두 검사한다. Studio 제어 화면과 프로젝트 기록에 존재하는 같은 문구는 실패로 세지 않는다.
