# 루프·첫 프레임·다양성 QA

## 첫 프레임 계약

첫 프레임만 표시돼도 다음 셋이 **동시에** 이해돼야 한다.

1. 제품 또는 문제
2. 한 줄 메시지
3. 그 메시지를 뒷받침하는 시각 근거

따라서 헤드라인은 t=0에 이미 보이는 정적 요소다. 페이드인 시키지 않는다.
근거가 애니메이션으로만 나타나면(예: 벌레가 나중에 등장) 최소 2~3개를 t=0에 `tl.set`으로 켜 둔다.

애니메이션은 메시지를 **새로 만들지 않고** 첫 프레임의 메시지를 강화한다.

## 루프 계약

루프에는 두 종류가 있고 검사가 다르다. 슬롯의 `loop_mode`로 선언한다.

| loop_mode | 대상 | 검사 |
| --- | --- | --- |
| `return` (기본) | 오버레이가 나타났다 사라지는 모션 | 첫·끝 프레임 차이가 허용치 이하 |
| `cycle` | 회전·컨베이어처럼 계속 도는 모션 | 이음새 차이가 **정상 프레임 간 차이 중앙값의 2배 이하** |

`cycle`을 `return`으로 검사하면 정상적인 360° 턴어라운드가 항상 실패한다.
315°와 0°는 원래 45° 만큼 다르기 때문이다. 이때 봐야 하는 것은 이음새가 다른 스텝보다
유독 튀는지 여부다.

`return` 모션은 마지막 프레임이 첫 프레임 상태로 복귀해야 한다. 픽셀 동일성만으로는 부족하다.

- 첫 장면이 검거나 비어 있지 않은가
- 마지막 → 처음 연결에서 **속도·방향·밝기**가 튀지 않는가
- 제품 위치·크기가 갑자기 변하지 않는가
- 제품 형태·색상·부품이 중간에 바뀌지 않는가
- 숫자·단계가 정확한 최종 값까지 도달하는가

구현: 모든 오버레이에 종료 트윈(`opacity: 0` 또는 초기값 복귀)을 두고,
지속 시간의 마지막 0.3~0.5초를 복귀 구간으로 예약한다.
왕복 성격의 모션(와이프 등)은 시작 비율로 되돌아오게 설계한다.

## 인접 다양성 — 4축 중 2축

| 축 | 값 예시 |
| --- | --- |
| 카메라 | 고정 · 컷 · 느린 이동 |
| 핵심 변화 | 개체 증가 · 하중 버팀 · 경로 접근 · 상태 전환 · 흐름 · 단계 진행 · 와이프 · 카드 순차 |
| 전환 | 홀드 · 컷 · 와이프 · 상태 크로스 |
| 강조 그래픽 | 경고 링 · 점선 원 · 화살표 · 글로우 · X/체크 · 물줄기 · 숫자 배지 · 분할선 · 카드 |

**페이지 순서대로** 인접 쌍을 검사한다. 2축 미만이면 한쪽의 강조 그래픽이나 핵심 변화를 바꾼다.
이 검사는 **경고다.** 렌더를 막지 않는다. 슬롯을 빼는 근거로 쓰지 않는다.

## 장식-only 판정

다음만 움직이면 coverage로 세지 않는다.

- 정보가 늘지 않는 팬·줌·흔들기·광선·입자
- 제품 위를 지나가는 의미 없는 스캔 라인
- 동일 주장을 반복하는 두 번째 강조

반대로 제품이 고정돼 있어도 **검증된 선·라벨·카드가 치수·위치·단계·구성을 새로 설명하면** 유효하다.
판정 기준은 움직임의 화려함이 아니라 `visible_delta`의 유무다.

## 같은 주장 중복 금지

한 장점 아래 정지 이미지와 GIF를 연속으로 쌓지 않는다.
모션이 주매체면 정지 이미지는 첫 프레임 poster fallback으로만 쓰거나 다른 증명 섹션으로 옮긴다.

GIF에 구운 하단 캡션과 HTML 본문 문장이 같으면 GIF 쪽을 뺀다.
GIF에 구운 헤드라인과 HTML 섹션 제목이 같으면 HTML 쪽을 라벨 칩으로 낮춘다.

## 검사 순서

1. 포스터 컨택트 시트를 만들어 **눈으로** 본다. 자동 게이트가 못 잡는 결함이 여기서 나온다.
2. 프레임 수 2 이상, 목표 크기 일치.
3. 첫·중간·끝 프레임을 뽑아 제품 불변 조건을 대조한다.
4. 인접 2축 차이표를 채운다. 경고만 남기고 진행한다.
5. GIF 합계를 기록한다. 상한은 없다.
6. 공개 DOM animation 수 = 파일 수 = 매니페스트 수.
