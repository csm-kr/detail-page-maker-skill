# 엔진 라우팅

## 결정 규칙

```
제품 픽셀이 프레임 사이에 바뀌어야 하는가?
├─ 아니오 → HyperFrames
│    제품은 고정 이미지. 카메라·오버레이·레이어·클리핑만 움직인다.
│    결정론 렌더 → 제품 동일성이 구조적으로 보장된다.
│
└─ 예 → make-consistent-gif
     회전·접힘·개봉·결합·변형·복원처럼 형상 자체가 달라진다.
     프레임별 생성 + 실루엣 드리프트/정체성 QA + 전역 시퀀스 선택.
```

## 두 엔진의 실제 성격

| | HyperFrames | make-consistent-gif |
| --- | --- | --- |
| 산출 정본 | 무음 MP4 | RGBA PNG 시퀀스 + 스프라이트시트 |
| 결정론 | 있음. 같은 시간 → 같은 픽셀 | 없음. 생성 결과를 QA로 선별 |
| 제품 동일성 | 원본 이미지를 그대로 쓰므로 100% | 프레임마다 검증 필요 |
| 780×3.5초 비용 | 렌더 약 6초 | 후보 생성 수십 장 + 선별 |
| 텍스트·치수선 | 안정적 | 프레임마다 흔들림. 쓰지 않는다 |
| 잘하는 것 | 정보 오버레이, 비교 와이프, 단계 컷 | 형상 변화, 회전, 상태 전환 |

## 혼용 패턴

형상 변화 **위에** 정보 오버레이가 필요하면 두 엔진을 직렬로 쓴다.

```
make-consistent-gif → 프레임 시퀀스(회전 등) → PNG 연속 이미지
        ↓
HyperFrames 컴포지션의 배경 트랙에 프레임 시퀀스를 얹고
        ↓
그 위에 결정론 오버레이(라벨·콜아웃·치수선)를 합성
        ↓
MP4 → FFmpeg GIF/WebP
```

이 경로에서만 회전에 라벨을 붙일 수 있다.
make-consistent-gif가 만든 프레임에 직접 텍스트를 생성시키지 않는다.

## make-consistent-gif 호출 규약

- 형제 `god-tibo-gpt-image2-skill`을 재사용한다. 인증 코드를 복사하지 않는다.
- 호스트가 런타임을 고정할 때만 `GOD_TIBO_SKILL_ROOT`, `GOD_TIBO_NODE`를 쓴다.
- 캐노니컬 레퍼런스는 평면 `#ff00ff` 배경으로 먼저 정규화한다. 제품 안에 `#ff00ff`가 없어야 한다.
- 상세페이지 용도에서는 `loop_mode: closed`가 기본이다. 마지막 프레임이 첫 프레임으로 이어져야 한다.
- 턴어라운드는 프레임 수를 360의 약수로 잡는다. 8프레임이면 45°씩, 12프레임이면 30°씩.
- `size_mode: controllable`을 쓸 때는 `size_prompt: "size-only"`를 함께 보낸다.
  기본값(`aspect-guided`)은 프롬프트에 비율·센터크롭 지시를 써넣어 프레임마다 구도가 재구성된다.
- 부분 실패는 실패다. 매니페스트 없는 부분 결과를 선별에 섞지 않는다.
- 배치 규모를 먼저 줄인다. 8프레임 × 2후보 = 16 items가 안전한 시작점이다.
  workers를 낮추는 것은 도움이 되지 않는다. 벽시계 시간만 늘어나 유실이 커진다.

## fallback

| 실패 | 대체 |
| --- | --- |
| 회전 시퀀스의 정체성 드리프트가 QA를 못 넘김 | 정면·사선·측면 정지 3컷 + HyperFrames 컷 전환 |
| 결합·피팅 프레임이 부자연스러움 | 짚기(T3)로 결합 위치만 표시 |
| 단면 자료 없음 | 꿰뚫어보기 포기, 짚기로 대체 |
| 옵션별 실물 이미지 없음 | 갈아입기 포기. 프로그래밍 recolor 금지 |
| 프레임 시퀀스 비용이 과함 | 해당 동사를 HyperFrames 가능 동사로 교체 |

못 만드는 증명을 억지로 만들지 않는다. 근거가 있는 다른 동사로 바꾼다.
